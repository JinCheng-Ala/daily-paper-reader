## 摘要
随着LLM智能体的激增，理解并诊断智能体中的失败对于实现卓越的效果和可信度至关重要。由于智能体失败往往表现为长而复杂的轨迹，手动寻找其中的关键问题点难以实现。然而，传统的软件缺陷诊断技术几乎无法解决LLM智能体失败，而完全依赖LLM作为裁判则会产生不可靠的诊断结果。为克服这些挑战，本文提出了AGENTSCOPE，一种用于智能体失败模式诊断的新型神经符号方法。AGENTSCOPE的核心原则是基于其轨迹将智能体行为抽象为结构化表示。此外，AGENTSCOPE引入了神经不变量的概念来指定智能体行为属性。AGENTSCOPE利用基于LLM引导的推理，在结构化表示之上对照神经不变量，以精确定位轨迹中的失败步骤及其类型。我们展示了AGENTSCOPE在公开可用的智能体失败数据集（Who&When）以及我们创建的更全面数据集（AgentErrata）上的有效性，其中AGENTSCOPE在故障定位和归因准确性方面显著优于当前最先进技术。我们的工作表明，将结构化抽象与LLM引导推理相结合，能够实现对智能体失败有效、可靠且可解释的诊断。

## Abstract
With the proliferation of LLM agents, the ability to understand and diagnose failures in agents is essential to achieving superior effectiveness and trustworthiness. As agent failures often manifest via long and complex trajectories, manually finding the needles in the haystack is untenable. However, traditional diagnosis techniques for software bugs can hardly address LLM agent failures, while completely relying on LLMs as the judge yields unreliable diagnosis results. To overcome these challenges, this paper presents AGENTSCOPE, a new neuro-symbolic approach for agent failure mode diagnosis. The key principle of AGENTSCOPE is to abstract agent behavior, based on its trajectories, into structured representations. Furthermore, AGENTSCOPE introduces the concept of neural invariants to specify agent behavior properties. AGENTSCOPE leverages LLM-guided reasoning atop the structured representation against neural invariants to pinpoint both the failure step and its type in the trajectory. We show the effectiveness of AGENTSCOPE on publicly available agent failure datasets (Who&When) and a more comprehensive dataset created by us (AgentErrata), where AGENTSCOPE significantly outperforms the current state of the art in fault localization and attribution accuracy. Our work shows that integrating structured abstractions with LLM-guided reasoning enables effective, reliable, and interpretable diagnosis for agent failures.

### 1. 核心问题与研究动机

- **背景**：LLM（大语言模型）智能体已被广泛用于多步推理、工具调用与跨系统交互（如 LangChain、AutoGPT、OpenManus 等）。此类智能体在长周期任务中常因推理错误、上下文处理不当、工具使用失误等原因而失败。
- **核心困难**：
  - 失败轨迹通常较长且高度复杂，故障信号被淹没在大量正常步骤中，人工审计“大海捞针”不可行。
  - 传统软件故障诊断方法（如基于程序不变量、符号执行、日志分析）本质上依赖符号逻辑，难以刻画基于神经网络模糊判断的错误（如“误用上下文”或“未遵循指令”）。
  - 完全依赖 LLM 作为“裁判”的单次全局判断（或逐步判断）方法受限于长上下文、位置敏感性和因果混淆，诊断结果不可靠。即使最强模型 GPT-5.1，其故障归因准确率也仅约 18.15%。
- **研究目标**：提出一种将结构化行为抽象与 LLM 引导推理相结合、可本地化失败步骤并归因失败类型的诊断框架，兼顾有效性、可靠性与可解释性。

### 2. 方法论：AGENTSCOPE 框架

AGENTSCOPE 是神经符号（neuro-symbolic）诊断框架，核心思想是“先把轨迹结构化，再做推理分析”：

- **① 行为抽象（Behavioral Abstraction）——构建 ReAG 图**：
  - 将原始轨迹建模为有向无环图 **ReAG（Reasoning-Action Graph）**：`G = {V, E}`，其中 V 为节点（一步），E 为控制或数据依赖边。
  - 每个节点表示为 `v_i = ⟨id_i, r_i, c_i, I_i⟩`，即“步骤 ID、执行角色、操作内容、中间语义表示”；节点通过 API、工具调用和日志插桩构造，并用 LLM 做语义切分与融合，以处理无结构日志。
  - 关键创新点是 **ISR（Intermediate Semantic Representation，中间语义表示）**：每个节点被提炼为三元组 `I_i = (C_i, R_i, S_i)`，分别覆盖意图与上下文、推理与动作、信号与验证。ISR 的作用是压缩冗余、形成长期语义索引，使后续分析无需每次都处理全部原始文本。

- **② 神经不变量（Neural Invariants）**：
  - 扩展传统程序不变量的思想，提出**神经不变量**：用“神经函数”表达智能体的行为正确性属性；神经函数由 LLM（如 GPT-4o）实现，输入为 ReAG/ISR 中相关步骤的结构化上下文，输出为二元判断（违反/不违反）。
  - 每种失败模式对应一个不变量违例，例如：
    - *Action Mismatch*：检查动作节点与其前驱推理节点在意图、工具选择、推进任务上是否一致（判断函数 `aligned()`）；
    - *Wrong Context*：判断是否有幻觉上下文或未澄清模糊用户输入（`failedToClarify()`/`hallucinated()`）；
    - *Instruction Unfollowing*：检查输出是否满足指令要求（`followed()`）；
    - 其余还有 Insufficient Context、Context Miss、Termination Miss、Premature Termination、Step Loop、Invocation Issue、Execution Failure 等（共 10 类）。
  - 该设计显著优于纯 LLM 直接判断：不变量将模糊判断转化为离散的、可追踪的规则检查，给出结构化证据链条。

- **③ 三阶段实施流程**：
  1. **ReAG 构建**：把运行时原始轨迹规整为带注释、语义字段对齐的图（含指令、缺失信息信号、步骤目的等），避免 LLM 因原始文本的脆弱性（错位、遗忘早期上下文、误解隐含推理）而误判。
  2. **失败模式检测**：按各类不变量分别定位相关步骤、检查并暂存**多个候选失败**（带证据），不做过早合并；支持多假设并保留审计性。
  3. **决定性错误判断**：基于全轨迹与候选证据做全局推理，选出一个“最终决定性错误”的步骤及类型——它被定义为“对终态劣化影响最大的失败”，而非“第一个异常”。

总体上看，AGENTSCOPE 通过“结构化解耦 + 局部校验 + 受控聚合”来缓解 LLM 的长上下文能力不足、位置敏感性、前后依赖缺失等本质缺陷。

### 3. 实验设计

- **数据集 / 基准**：
  1. **Who&When**（公开）：含 184 条人工标注轨迹，分为 Algorithm-Generated（126 条）与 Hand-Crafted（58 条）两个子集；只标注失败步骤、无明确失败类型标签。
  2. **AgentErrata**（新构建，303 条高质量轨迹）：通过“故障注入”（fault injection）生成，覆盖全部 10 类失败模式，保证注入错误会导致最终任务失败。其轨迹来源涵盖多个正交框架（OpenManus、OWL、Mini SWE Agent）及任务基准（BrowseComp、SWE-Bench Lite、WebArena），分布相对均衡（Reasoning 36%、Control-flow 31%、Action 36%）。
- **对比方法**：
  - All-at-once：将全轨迹整体交给 LLM，一次性给出失败定位。
  - Step-by-step：逐步结合先前所有上下文判断每一步是否异常。
  - LLM-as-Judge：作为归因任务的对照，即一次性判断失败类型。
- **基座模型**：GPT-4o（2024-11-20）、GPT-5.1、DeepSeek-V3.2，温度 0.01，max_tokens=4096，通过 Azure AI Foundry 部署。
- **评测指标**：
  - **SLA**（Step-level Accuracy）：精确命中真实失败步骤的比例；
  - **SLAT**：允许在 δ = 0/1/3 邻域内的命中率；
  - **CA**（Classification Accuracy）：预测模式集合中是否包含真实失败类型。
  - 论文刻意不用原有 Agent-level Accuracy（ALA），因它未反映失败步骤且容易通过猜高频角色获得虚高分数。

### 6. 主要结论与发现

- **AGENTSCOPE 在定位上显著优于基线**：
  - 在 AgentErrata 上，GPT-4o（w/o Solution）SLA 达 30.03%，远超 All-at-once（2.09%）和 Step-by-step（8.91%）；SLAT±3 下达 49.83%。
  - 在 Who&When（Algo-Generated）上，GPT-4o 达 31.75%（w/ Solution，SLA），GPT-5.1 下 SLAT±3 为 64.29–65.87%。
- **归因能力大幅超越 LLM-as-Judge**：CA 从基线约 18–21% 提升到 41.58–45.87%；SLA 提高达 8–16 倍。且在有无任务真解条件下性能几乎一致，说明增益来自结构性分析而非答案泄露。
- **跨基座模型稳定性强**：GPT-4o、GPT-5.1、DeepSeek-V3.2 上均保持 30–35% 左右的 SLA（AgentErrata），波动小；而基线方法对模型极其敏感（如 Step-by-step 在 GPT-4o 上 8.91%、GPT-5.1 上掉到 1.32%）。
- 失败诊断能力不与模型能力简单正相关；结构化解析和不变量检查是更关键的因素。
- 运行时开销可管理，且各类不变量检查间相互独立，可并行化进一步降耗时。
- 给出原则性结论：**结构化行为抽象 + 神经不变量 + LLM 引导推理**是构建高可信智能体诊断系统的有效路径。

### 7. 优点与亮点

- **框架层面创新突出**：
  - 提出“神经不变量”概念，把传统程序验证思想推广到不可精确规格化的 LLM 错误，兼具形式化优势与自然语言语义灵活性；
  - ReAG+ISR 设计了紧凑可检索的行为中间表示，缓解长上下文和依赖断裂问题。
- **工作流设计合理**：
  - 把“全局判断”分解为“构造图→局部不变量检测→决定性汇聚”三段式，保留多候选假设、支持审计和回溯；
  - “决定性错误”与“误差发生点”的区分比现有 Who&When 的“首个错误”标注更能刻画真实因果。
- **实验设计较扎实**：
  - 引入合成的 303 轨迹 AgentErrata 数据集，保证失败“真正影响任务完成”且覆盖全部 10 类失败模式（分布相对均匀）；
  - 采用 3 个基座模型 × 2 个公开/自建基准 × 2 个基线 × 3 个容忍带，比较体系相对全面；
  - 度量定义严格（SLA/SLAT/CA），并解释了为什么要弃用 ALA。
- **商业级实现**：代码/框架集成到主流 Agent 框架，可做在线/离线的单/多智能体诊断。

### 8. 不足与局限

- **绝对准确率仍偏低**：即使远高于基线，SLA 也只有约 25–35%（精确命中），距离实用级高可靠诊断尚有较大距离；对极长（>100 步）轨迹定位的漏检率或误检率并未细粒度报告。
- **“决定性错误”标定存在主观性**：AgentErrata 由论文自行合成与人工校验，注入错误的人为设计可能低估真实世界失败的自然表现与相互耦合；而 Who&When 标注策略（先验首个错误）又可能导致对 AGENTSCOPE 的评估不利，两种基准口径并不完全一致。
- **缺少细粒度的模块消融**：没有明确量化 ReAG、ISR、神经不变量集合、决定性挑选策略各自的贡献；也没有做非 LLM 或轻量模型实现神经函数的对照。
- **LLM 重复调到哪一步仍有随机性**：只给出温度 0.01 等设定，没有评估多次重复测量的标准方差/置信区间；也未公开可用复现代码与提示词全清单。
- **算力评估不够透明**：数千次 API 调用的经济/能耗成本没有摊开；运行时仅对 20 条轨迹、单模型做了剖析，代表性有限。
- **泛化性限界尚不清晰**：评估集中于 Web 搜索、软件工程与通用任务代理，未涵盖具身/仿真/多代理协同及大规模并行交互等更复杂环境；对“新失败模式如何自动扩展不变量”的问题也没有给出完整方案。
