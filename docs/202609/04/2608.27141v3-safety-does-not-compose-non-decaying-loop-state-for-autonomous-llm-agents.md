## 摘要
大语言模型代理日益被部署为自主循环。从一个人类目标开始，这样的系统反复发现工作、规划、执行工具调用、验证结果，并在许多无人值守的迭代中保持状态。然而，广泛使用的代理安全措施是针对单一轨迹定义的，当下一轨迹开始时，其安全状态被重新初始化。我们表明，这是一个组合失败而非实现细节。我们的核心结果是一个分离：针对一种证据分散在多次迭代中的攻击，每个轨迹范围内的监控器的真阳性率等于其假阳性率，无论其多么富有表现力，因为它所需证据永远不会出现在其可见窗口中，而保留跨迭代状态的监控器则能将两者完美分离。我们进一步表明，携带几何衰减风险分数的明显修复是不充分的，因为耐心对手必须等待的冷却期是一个不随范围N增长的常数。然后，我们提出了LoopHarness，它在循环层面恢复了持久、非衰减的安全状态。在中介提交和仲裁者检测下限δ_M下，它将未经授权的不可逆操作的期望数量限制为B+m-1+m/δ_M，这是N中的常数，其中B+m-1项由无模型规则决定，因此在完全共谋的验证者面前仍然有效。我们给出了一个完整的评估协议，包括原生Agent-SafetyBench任务上的配对的干净和攻击情节，一个仅在跨迭代中存在决定性证据的外部状态攻击套件，逐模块消融，以及自适应的白盒红队。

## Abstract
Large language model agents are increasingly deployed as autonomous loops. Starting from one human goal, such a system repeatedly discovers work, plans, executes tool calls, verifies outcomes and persists state across many unattended iterations. The agent safeguards in wide use, however, are defined over a single trajectory, and their safety state is re-initialized when the next trajectory begins. We show that this is a failure of composition rather than an implementation detail. Our central result is a separation: against an attack whose evidence is fragmented across several iterations, every trajectory-scoped monitor has a true-positive rate equal to its false-positive rate, however expressive it is, because the evidence it would need never appears in the window it sees, whereas a monitor retaining cross-iteration state separates the two perfectly. We further show that the obvious repair of carrying a geometrically decaying risk score is insufficient, because the cooling-off period a patient adversary must wait is a constant that does not grow with the horizon $N$. We then present LoopHarness, which restores a persistent, non-decaying safety state at the loop level. Under mediated commits and an arbiter detection floor $δ_M$, it bounds the expected number of unauthorized irreversible actions by $B+m-1+m/δ_M$, a constant in $N$, of which the $B+m-1$ term is decided by a model-free rule and therefore survives a fully colluding verifier. We give a complete evaluation protocol on native Agent-SafetyBench tasks with paired clean and attacked episodes, an outer-state attack suite whose decisive evidence exists only across iterations, per-module ablations, and an adaptive white-box red team.

**研究动机与背景：**

- 当前工业界广泛部署的代理安全机制（输入清洗、单调用分类、权限上限、能力令牌、轨迹内回滚等）全部以**单条轨迹（trajectory）**为作用域，且安全状态在每条轨迹结束时**重置（re-initialize）**，即论文所称的**逐轨迹重置（Per-trajectory reset）**。
- 攻击方则恰恰利用循环系统所刻意保留的跨迭代通道（持久记忆、任务账本、累积上下文）来积累能力，形成结构性不对称：**防御者的安全状态每轮归零，而攻击者的进度随循环持续累积**。

**核心问题：**

> 论文证明这是一个**组合失败（failure of composition）**，而不是防御实现的细节缺陷：针对证据被碎片化到多个迭代的攻击，任何轨迹级监控器的检测能力在理论上等同于随机猜测（TPR = FPR），而保留跨迭代状态的监控器可以完美分离攻击与良性流量。

**整体含义：**
- 单条轨迹安全做得再好，无法组合出循环级安全（"安全不可组合"）。
- 简单地携带几何衰减风险分数无法修复该问题（衰减只带来常数级的冷却延迟，不随总迭代数 N 增长）。
- 自主代理的长期安全必须依赖**循环级、持久、非衰减安全状态**——这正是论文提出的框架 LoopHarness 的核心立场。

## 2. 方法论：LoopHarness

**核心思想：**
在循环执行层面建立一个持久且不被逐轨迹重置的安全状态层，并保持三类信号的严格分离：
1. **动作影响（action impact）**——只影响当前轮内的审查路由，不进入持久风险状态；
2. **已落地的攻击证据（grounded attack evidence）**——是唯一被允许进入持久风险累积器的信号；
3. **验证器不确定/分歧（verifier indecision）**——只影响当前轮内的审查，不回写持久状态。

**总体框架**（在所有现有内部防御之外运行，可与其任意组合）：
- 每一轮（iteration）执行固定相位顺序：0—重补水（rehydrate）→ 1-2—准入与门控 → 3—执行内部内框架（L1-L4）→ 4—审查仲裁 → 5—持久化 ← 6—风险更新与停止决策。

**五大持久组件：**

1. **IPM（Intake and Provenance Monitor，输入与来源监控）**
   - 所有新工作项的唯一入口，六条拒绝规则（默认拒绝域检查、信任与信道匹配、拒绝去重、授权的原子性、跨任务来源可委托性、无注入模式检查）。
   - 每轮最多接受 k 个工作项；对不信信任工作项输出连续的输入先验分数。

2. **XRC（Cross-iteration Risk Cumulant，跨迭代风险累积器）**
   - 每个迭代更新一次风险：

     \[
     \Xi_i = \max(r_i, \gamma_i \Xi_{i-1}), \quad \gamma_i =
     \begin{cases}
     1 & \text{若截至第 } i \text{ 轮有结构标志触发} \\
     \gamma_\downarrow \in (0,1) & \text{否则}
     \end{cases}
     \]

   - 关键机制：**衰减闩锁（latch）**——只有离散、规则可判定的循环结构性标志（如范围扩张、被拒任务重入、能力升级、记忆篡改、未签名的信任升级等）才能将 γ 永久锁定为 1（停止衰减）；仅凭高连续风险分数本身永远不会触发闩锁。
   - 这种设计保证：耐心对手通过等待来重置风险门控（类"冷却期"攻击）**永久失效**（见 Proposition 3）。

3. **MIG（Memory-Integrity Guard，记忆完整性守卫）**
   - 持久记忆采用 **哈希链（HMAC 链式标签）+ 周期性检查点**存储；检查点同时认证日志前缀摘要、长度和支配器计数器，因此攻击者无法静默截断或篡改计数。
   - 三条策略：单调信任写门（未签名授权禁止信任升级）、重补水时审计、只看受信后缀的召回策略（封堵"自我喂入记忆中毒"通道）。

4. **ASA（Adversarially Robust Stopping Arbiter，抗对抗停止仲裁器）**
   - 三层证据裁决：①**确定性门**（不调用模型：成功不可逆提交 + 结构性标志/授权违约等规则触发）；②**去相关检查器**（每轮至多一个模型调用，高级检查角色必须与写者模型不同）；③**滑动窗口发散统计量**。
   - 任何检测触发即停机；只接受无检测、无待审、合规的迭代结果写入记忆。

5. **CRG（Compounding-risk Governor，复合风险调控器）**
   - 硬性预算：风险计费提交数上限 B、高级验证调用数上限 B_adv；风险-计费提交计数器只增不减。
   - 能力上限按当前 Ξ 分级映射到五个动态权限层级；任务契约强制执行风险清除阈值和完成次数上限。

**理论保证：**

- **Proposition 2（碎片化分离）**：任意表达力的轨迹级监控器，对 s-碎片化攻击的TPR恒等于FPR；跨迭代状态读取者则可获得（TPR=1, FPR=0）。
- **Proposition 3（冷却期对抗几何衰减）**：
  - 几何衰减下门控重开所需等待步数为 \(k^*=\lfloor \log(\theta/\rho)/\log\gamma \rfloor + 1\)，为**不依赖 N 的常数**；
  - 带闩锁的非衰减模式下，被动等待永远无法重开风险门。
- **Theorem 5（主界限）**：在所有攻击者策略和任意 N 下，
  - \(U^{\text{vis}}_{1:N} \le B+m-1\)（必然成立，无模型调用，纯规则）
  - \(\mathbb{E}[U^{\text{inv}}_{1:N}] \le m/\delta_M\)（概率界）
  - 合并为：**E[U₁:ₙ] ≤ B + m − 1 + m/δ_M，与迭代总数 N 无关的常数上界**。
- **Proposition 6**：其中 B + m − 1 项是无模型规则决定的，即使验证器与写者完全共谋也能成立；唯一依赖检查器的 m/δ_M 项对应"声明范围 vs 运营商意图"的残差类，可通过收窄 A/Π 来压缩。

**在理论适用性方面论文保持谨慎**：该界是期望意义上的缩放声明，并非保证零事件的经验交叉点；(A2) 检测下限假设是分析中唯一的实证输入。

## 6. 主要结论与发现

1. **结构性失效定理（Proposition 2）**：对任意的 s-碎片化攻击，任何轨迹级监控器都不可能做到比随机更好的区分（TPR = FPR）。这不是实现缺陷而是定义性盲区；只有读取跨迭代状态的监视器才能以 (TPR=1, FPR=0) 分离两者。

2. **衰减修复方案不成立（Proposition 3）**：几何衰减累积器只对攻击者施加**恒定长度冷却期** \(k^* = O(1)\)（与 N 无关），一次付出即可形成 Ω(N) 次攻击机会；非衰减闩锁机制才能永久封锁被动等待型重开。

3. **主定理（Theorem 5）**：在中介提交、检测下限 δM 和单调计数三个假设下，期望未授权不可逆提交数被常数 B+m−1+m/δM 界定——**不随总体迭代次数 N 增长**；其中确定性部分（B+m−1）**不需要任何模型调用**，甚至验证器与写者共谋时依然可靠成立（Proposition 6）。

4. **实证有效性**：B4 在 Track B 上将总体 ASR 压至 0.1%（对照 B0-B3 的 88.4~97.6%），同时保持 96.9% CleanGC；Track A 中 B1/B1.5 在 N=5→10 时 cASR 从 2.9% 升至 6.2%，B4 在全部 N 水平下恒为 0.0%
