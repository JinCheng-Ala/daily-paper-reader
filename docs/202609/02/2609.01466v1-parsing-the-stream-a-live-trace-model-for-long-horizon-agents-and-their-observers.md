## 摘要
长期运行的智能体的轨迹会超出它的两个消费者：监控运行的人类观察者，以及智能体本身，轨迹必须被折回到其受限上下文中。我们提出了一个实时轨迹模型，它作为一个仅追加的事件账本，增量折叠成类型化的运行状态，并编译成针对每个消费者的视图，并根据确定性的基准真值对两个消费者进行评估。在观察者方面，使用LLM阅读器作为代理，与预算受限的单次读取整个原始轨迹相比，编译后的视图在回答监控问题时需要的输入token大约减少14倍和15倍（取决于阅读器），成本降低5-7倍，同时准确率更高（0.85-0.87对比0.48）。由于问题与视图模式是共同设计的，我们将token和成本降低（在模式覆盖率条件下）视为可迁移的结果。对于智能体本身，在120个链式依赖任务上，在每步状态中维护任务运行统计信息的机制在完整上下文提示失败的情况下取得了成功（在干净协议下为30/30对比8/30，n=30，由于基准系统是共同开发的，因此标记为描述性）；提示级草稿本以更低的成本匹配了折叠的准确性，而双臂分解将折叠的准确性归因于其确定性聚合，成本优势归因于其紧凑性。与更便宜的替代品相比，折叠的剩余价值在于其确定性的可审计性，以及从相同状态为观察者提供服务。我们从观察到的失败中推导出轨迹折叠的十一个候选需求，并用一个对顺序敏感的任务族来界定其边界，在这个任务族上折叠不再起作用。我们发布了代码、基准、一个可重新生成的合成语料库以及所有工作台轨迹。

## Abstract
A long-horizon agent's trace outgrows both of its consumers: the human observer monitoring the run, and the agent itself, whose bounded context the trace must be folded back into. We present a live trace model, an append-only event ledger folded incrementally into typed run state and compiled into per-consumer views, and evaluate it for both consumers against deterministic ground truth. For the observer side, evaluated with an LLM reader as proxy, the compiled view answers monitoring questions using approximately 14x and 15x fewer input tokens (by reader) and at 5-7x lower cost than a budget-capped single-call reading of the raw trace, with higher accuracy (0.85-0.87 versus 0.48). Because the questions were co-designed with the view schema, we treat the token and cost reduction, conditional on schema coverage, as the transferable result. For the agent, on 120-link sequential-dependency tasks, mechanisms that maintain the task's running statistic in per-step state succeed where full-context prompting fails (30/30 versus 8/30 under a clean protocol, n=30, labeled descriptive owing to benchmark-system co-development); a prompt-level scratchpad matches the fold's accuracy at lower cost, and a two-arm decomposition attributes the fold's accuracy to its deterministic aggregate and its cost advantage to its compactness. The fold's remaining value over cheaper alternatives is deterministic auditability and serving the observer from the same state. We derive eleven candidate requirements for trace folding from observed failures and delimit them with an order-sensitive task family on which the fold ceases to help. Code, benchmarks, a regenerable synthetic corpus, and all workbench traces are released.

## 一、核心问题与研究动机

- **研究对象**：长周期（long-horizon）智能体在运行中持续产生单一产物——运行轨迹（trace），包括消息、工具调用、结果、token 用量等。
- **核心矛盾**：轨迹的规模会同时压垮它的两个消费者：
  1. **人类观察者**：需要在运行中途判断"智能体在做什么、哪些已定、哪些待办"。实测 12 个真实会话共 112 MB，前沿模型直接读取原始尾部回答基本监控问题，准确率仅 **0.479**，同时消耗 **779K** 输入 token。
  2. **智能体自身**：必须在有界上下文中消化轨迹。120 链接的链式任务上，全上下文 worker 累计计费输入达 **2.37M token**（每次调用约 33K 且不断增长），成功率降至 **7/30**（干净协议下 8/30）。
- **现有做法的割裂**：如今两个消费者由两套独立系统服务（可观测性工具 vs. 上下文管理），成本与失败是两个独立问题——未缓存的扁平全上下文每轮 7.49 美元且失败；缓存的会话式变体便宜（约 1.06 美元）却完全失败（0/10）。
- **论文主张**：将轨迹只建模一次，从**单一基底（substrate）**编译出面向各消费者的视图，同时服务观察者与智能体，并提供确定性、可审计的溯源。

## 二、方法论

### 1. 实时轨迹模型（Live Trace Model，实现于 tracelab）——四层栈
- **第一层：仅追加账本（Ledger）**
  - 将框架的 JSONL 记录逐条解析为类型化事件，保留因果链、工具调用/结果关联与缓存感知的用量字段。
  - 内容载荷携带 SHA-256 指纹，防篡改；畸形行隔离计数；未知类型保留。
  - 以**字节偏移**作为断点续传标记；属性测试证明分块摄入等价于整文件解析。
  - 关键性质：按 API 消息 id 对每块重复的用量去重，否则 token 记账最多虚增 **3.49×**。
  - 摄入开销极低：104 MB、16,737 事件仅 0.4 秒（Apple 单核，指示性计时）。
- **第二层：单遍折叠（Fold）→ RunState**
  - 将事件流增量归约为类型化运行状态：执行位置、计数器、接触文件、事实（facts）。
  - 事实按 `file:key` 来源作用域标识，采用**出现同一性**（重复观测各计一次，而非最新覆盖）；有界存储，**保聚合淘汰**（被淘汰的数值折叠进逐键运行计数与总和，精确保留统计量），且跨淘汰可重读（幂等）。
  - 属性测试保证折叠与分块方式无关；独立从原始 JSONL 重算与五个 120 链接轨迹逐键完全一致（零失配）。
- **第三层：版本化派生节点（Derived Nodes）**
  - 每回合片段摘要带有有效性生命周期（current / suspected-stale / invalidated-superseded）与终止态保护。
  - **事后重解析（hindsight re-parsing）**：被中断的回合只有等下一用户回合带着悬挂调用出现才能识别，迟到结果要挂回发起它的回合——因此解析器通过"取代旧版本"而非改写来修正过去。
- **第四层：按消费者编译的视图（Views）+ 策展循环（Curator）**
  - 观察者视图（HTML）：目标、实时前沿、异常徽章、统计卡、逐回合钻取与溯源链接，含诚实水印。
  - worker 视图（紧凑文本块）：GOAL / NOW / ANOMALY / COUNTERS / FILES / KEY FACTS（按 key 分组带运行聚合），并附**覆盖戳**（"已包含以上全部……至某来源"）。
  - 策展循环每 K 步（默认 5）从 worker 自身记录轨迹重新物化 worker 视图，使系统通过自身基底观察自己的执行。
- **确定性边界**：可选语义提取器为 LLM，其输出按事件记忆化，运行内可复现但跨缓存丢失/模型退役不保证；论文中"确定性"指非提取路径。

### 2. 十一条折叠需求（由失败总结而来，每条均被回归测试固定）
1. 携带事实而非引用；2. 出现同一性而非最新胜出；3. 绝不静默截断；4. 来源作用域身份；5. 确定性运行聚合；6. 保聚合淘汰；7. 跨淘汰重读幂等；8. 跨提取批次的规范键模式；9. 容忍拒答的批处理；10. 提取事实的逐字校验；11. 聚合需声明自身覆盖范围。

### 3. 两个基准仪器
- **COMPREHEND（观察者腿）**：由账本真值机械生成六类监控问题；LLM reader 作为被测消费者，答案按确定性规则评分（精确/子串/set-F1）。
- **CONTINUE（智能体腿）**：确定性工作台，任务族包括 scatter、fix、chain、prose-chain、altchain；成功以最终环境状态判定；各臂共享模型、任务、种子与**预承诺的按调用索引错误调度**；区分重试与重复，协议失败被记录并计费。
