## 摘要
长时程工具使用代理不仅需要搜索与规划，还需要决定何时最终确定。我们研究了后期压力状态，在这种状态下，代理倾向于提交看似完整且精致的关键约束仍未解决的最终答案。我们首先训练一个线性探针，证明这种压力状态可以从代理的隐藏状态中识别出来。然后，我们使用沿该压力方向的激活干预，发现移动隐藏状态会改变压力得分以及代理是继续使用工具还是提前提交。通过受控上下文操纵，我们进一步观察到，约束清晰度和动作映射可以缓解压力。基于这些发现，我们提出了探针感知压力缓解（PSPR），一种在中等压力下应用轻量级压力缓解方向，并在高压风险下转向结构化组织的插件。在多个长时程基准测试上的实验表明，我们的方法持续增强了现有代理方法的性能。

## Abstract
Long-horizon tool-use agents need not only to search and plan, but also to decide when to finalize. We study late-stage pressure states, in which an agent is biased toward submitting a final answer that appears complete and polished while key constraints remain unresolved. We first train a linear probe to show that this pressure state is identifiable from the agent's hidden states. Then, we use activation interventions along this pressure direction and find that shifting the hidden states changes both the pressure score and whether the agent continues tool use or submits early. Through controlled context manipulations, we further see that the pressure is mitigated by constraint clarity and action mapping. Based on these findings, we propose Probe-Sensed Pressure Relief (PSPR), a plugin that applies lightweight pressure relief direction under moderate pressure and moves to structured organization under high pressure risk. Experiments on multiple long-horizon benchmarks show that our method consistently strengthens existing agent methods.

## 二、方法论：核心思想、关键技术与流程

### 2.1 整体技术路线（三阶段）

1. **表征探测阶段**：训练线性探针，验证后期压力状态在隐藏空间中线性可分。
2. **因果干预阶段**：构造压力方向向量做激活加减，检验沿/逆方向移动能否改变继续工具使用还是提前提交的行为。
3. **上下文缓解分析**：通过受控文本注入（约束澄清 + 动作映射）考察压力缓解因素。
4. **应用插件（PSPR）**：将探测与干预整合为在线控制插件。

### 2.2 状态定义与探测

- **样本构建**：在每个"动作边界"（prefill 上下文结束、生成动作前）取第一个 token 的隐藏状态。
- **三类标签**：
  - **PresC（压力驱动提交）**：最终提交边界，约束满足得分 Ssat ≤ 0.3 但交付精美度 DPS ≥ 4（正样本）；
  - **HealC（健康提交）**：Ssat ≥ 0.85 且 DPS ≥ 4（控制"提交形式"混淆）；
  - **ProdC（生产性继续）**：虽未完成但后续继续解决未决约束（控制"难度/未完成"混淆）。
- **探针形式**：线性探针，公式上即对首 token 隐藏状态做线性打分；负样本由 HealC ∪ ProdC 构成。结果：AUROC = 0.916，PR-AUC = 0.921；对 HealC（0.890/0.918）和 ProdC（0.929/0.914）的定向区分均有效，说明信号并非"提交形式"或"任务难度"的伪影。Qwen3-14B 取第 26 层，并在 Qwen3-32B（46 层）与 TravelPlanner 上复现可分性。

### 2.3 激活干预（CAA 风格）

- 每个边界动作用该次生成前 K 个 token 的隐藏状态均值表示；类中心 μ(C) = 平均表征。
- 构造方向：v(C₊−C₋) = μ(C₊) − μ(C₋)，具体为 vPresC-HealC、vPresC-ProdC；另将 vPresC-ProdC 对"通用承诺方向" vcommit = μ(HealC) − μ(ProdC) 做残差化（线性概念擦除）得到 v⊥，以排除"提交 vs 继续"的通用效应。
- **结果**（60 个 PresC-risk 节点 + 60 个 ProdC 节点）：减去压力方向稳定提升 CS（如 0.21→0.25）、降低下一边界压力分（0.67→0.53）、提高继续率；加上则反之；残差化方向保持同趋势。说明该状态是**行为相关**的。

### 2.4 缓解因素分析

- 在边界上下文末尾追加两类诊断性文本块：
  - **约束清晰度（Constraint Clarity）**：显式重述硬约束、已有证据、未解决项；
  - **动作映射（Action Mapping）**：把未解决约束映射为具体下一步工具/动作。
- 结果：单独加澄清使 PresC-risk 压力 0.62→0.34，继续率 0.28→0.70；加动作映射压力→0.26、继续率→0.78；两者叠加压力仅 0.13、修复率 0.85（表 3）。注意力分析显示，追加块仅占 prefill token 的 11.9%，却获得 19.1% 的注意力质量（约为 token 占比的 1.6 倍），支持模型确实在利用这些信息。

### 2.5 PSPR：探针感知压力缓解（核心方法）

- **在线压力感知**：在每个动作边界，用首个生成 token 的隐藏状态计算 s_t = Probe(h^(ℓ)_{t,1})。
- **三级控制策略**（阈值 a=0.4、b=0.65）：
  1. 低压（s_t < a）：不干预；
  2. 中压（a ≤ s_t < b）：加**压力缓解方向** v_relief = μ_LP − μ_HP，作用于本次动作前 K=10 个生成 token（幅值 α=1）。HP 集为 PresC 回放激活；LP 集为对 ProdC 种子追加约束澄清 + 动作映射后、在"下一个有效生产性动作边界"采集的激活（而非追加边界本身，以避免捕捉表层文本效应）；
  3. 高压（s_t ≥ b）：进入**显式状态组织**分支——让模型自己总结约束状态（verified/uncertain/unsupported）并规划下一步验证动作，再插入上下文继续生成（每个轨迹最多触发两次，防止过度干预）。
- 该设计使 PSPR 无需改动基座模型参数，仅作为轻量插件。

### 3.3 消融与对照（续）

- **消融设置**：将完整 PSPR 逐模块剥离——仅保留压力缓解方向干预（无显式组织）、仅保留显式组织分支（探针只做触发而后由模型自省总结）、以及完整 PSPR 三者进行对比。
- **结论分解**：
  - 仅缓解方向干预：能降低边界压力、提高继续率，但对 CS/PS 的最终提升有限，说明缓解方向善于“推迟提交”但不保证接下来行动正确；
  - 仅显式组织：在关键节点让模型重新梳理约束，可提升 PS，但若触发过频或时机不当，会破坏流畅轨迹并降低 CS；
  - 完整 PSPR：利用轻量缓解方向在多数中压节点争取更多探索，在高压节点启动结构化自查，二者互补，带来最佳综合指标。
- **触发机制对照**：
  - **Random Trigger**：在随机边界触发一次显式组织，性能反而下降。原因在于干预时机与任务状态脱节——若在“刚刚开始验证、尚无紧迫压力”时打断，反而引入额外切换成本；
  - **Periodic-3 Trigger**：每三个边界固定触发一次，性能优于 CoT，但显著低于完整 PSPR。说明固定频率干预部分有效，但既可能在低压阶段浪费计算，也可能在真正高压的提交边界错过干预窗口；
  - 对比可见，探针的**时机**是 PSPR 的核心：不是“是否干预”而是“何时干预”决定最终的约束满足率。

### 3.4 附加分析与鲁棒性验证

- **跨骨干模型一致性**：线性探针在 Qwen3-14B、Qwen3-32B 与 OLMo-3.1-32B-Instruct 上都能取得高 AUROC，且 PSPR 带来的收益方向一致。不同层探针的最佳层位不同（如 Qwen3-14B 在第 26 层，Qwen3-32B 在第 46 层），但整体性质稳定。
- **跨任务/语言泛化**：中文版的 DeepPlanning-Travel 上 PSPR 的改进幅度与英文版基本相当；DeepPlanning-Shop 与 TravelPlanner 的平行实验确认了该方法并非旅行规划任务的独有现象。
- **干预副作用分析**：在健康提交（HealC）节点上施加“加压力”方向，会使原本正确的提交转为继续工具调用，但不会导致明显的低劣行为；在达到最大干预次数或重试限制后，代理仍能回到正常轨迹。说明该状态维度可被安全地双向控制，至少在当前任务范围内没有观察到破坏性副作用。

## 四、主要发现与结论

1. **后期压力状态是真实、可表征化的存在。** 探针在多个模型、多个任务上均能以超过 0.9 的 AUROC 区分“压力驱动提交”与“健康提交/生产性继续”，说明这一状态并非任务难度或输出风格的混淆，而是隐藏空间中一个相对稳定的方向。
2. **该状态具有行为因果性。** 沿压力方向做激活加减，就能系统地改变代理是否继续工具使用；逆方向操作能提高成功率，正方向操作则诱使过早提交。即便擦除“承诺/继续”的通用方向后，效果依然存在，表明后期压力并非“简单的不想干活”，而更接近于一种针对约束满足的紧迫感偏差。
3. **缓解方式并不神秘：澄清约束 + 映射动作即可显著降压。** 让模型重新看到“哪些约束未满足”，以及“下一步可以做什么”，几乎可以消除压力状态（压力分从 0.62 降至 0.13），且修复率达 0.85。注意力证据说明这种效果来自模型在 prompt 中对新增文字的实质性利用。
4. **PSPR 是这一机理的最小在线实现。** 仅通过在动作边界轻量读取一层隐藏状态，并在中压/高压阶段采取不同强度的干预，即可在多个长时程规划基准上稳定提升硬约束满意度和综合分数，且无需微调任何模型参数、不改变模型部署方式。

## 五、局限与未来方向

- **任务域限制**：论文实验集中于工具使用/规划类任务，其中工具调用边界清晰、提交是一个离散事件。“后期压力”在其他场景（如长文档写作、多轮代码调试或开放式问答）是否同样存在、是否同样可被线性探针捕获，仍需验证。
- **训练数据依赖**：线性探针与压力方向向量均需一批“成功/失败/继续”的三类标注轨迹来构建。虽然论文采用两折留出协议避免过拟合，但在没有标注数据的新型代理环境中，如何自动发现这组方向仍是一个工程与科学上的开放问题。
- **阈值与超参数敏感性**：PSPR 依赖 prefill 边界探测的压力阈值 a、b，以及干预幅值 α、回溯 token 数 K。论文给出了一套可行参数，但未深入探讨参数空间的边界；若应用到不同架构或不同对齐风格的模型上，可能需要进行少量校准。
- **干预深度的上限**：对高压节点，PSPR 迫使模型显式组织约束状态，但若模型自身的底层能力无法完成后续验证（例如工具本身缺失或推理链本身错误），该方法仍不能产生正确行动。它更像“恢复方向盘”的工具，而非“动力系统”。
- **社会讨论面**：线性可读的内部状态意味着未来可能存在更直接的可控性，也可能被用于不当操控（如强制提前提交或隐瞒不确定）。作者强调本论文的干预均以提升用户可验证结果为目标的防御性意图，但任何内部状态方向一旦被确认，都值得社区审慎看待。
