## 摘要
视觉-语言-动作（VLA）模型将视觉观察和语言指令直接映射到机器人动作，但长时程任务不仅仅需要动作预测。代理必须在物理状态演变过程中协调感知、规划、执行、进度验证和恢复。一个动作预测或模型生成的技能决策本身并不能保证所提议的操作在当前状态下有效，也不能保证其结果会被验证。我们提出EmbodiedSkills，一个统一的框架，将每个技能决策视为一个执行提议：运行时在执行前检查其前置条件，并在执行后验证结果。一个共享的可执行技能接口在单一代理循环中连接了高层技能选择、受限的低层VLA执行以及动作后验证。由于该接口保持固定，低层VLA策略可以在不改变代理循环的情况下被替换或调整。该接口还将规划、执行、验证和恢复事件记录为结构化轨迹，这些轨迹为各个组件提供监督，并在交互反馈可用时支持可选的在线适应。我们在RoboTwin 2.0和LIBERO上使用Qwen3-VL和OpenPI/pi0.5实例化了EmbodiedSkills。任务适应的低层VLA策略在50个RoboTwin 2.0任务中平均成功率达到86.20%，在四个LIBERO套件中达到97.40%。这些结果确立了EmbodiedSkills中使用的任务适应低层VLA策略的执行性能。在四个依赖记忆的RMBench任务上，相同的任务适应执行方法实现了12.5%的平均成功率。该框架提供了一个可训练、可检查的代理层，将这些策略转化为闭环具身系统。

## Abstract
Vision-language-action (VLA) models map visual observations and language instructions directly to robot actions, but long-horizon tasks require more than action prediction. An agent must coordinate perception, planning, execution, progress verification, and recovery as the physical state evolves. An action prediction or a model-generated skill decision does not, by itself, guarantee that the proposed operation is valid in the current state or that its outcome will be verified. We propose EmbodiedSkills, a unified framework that treats each skill decision as an execution proposal: the runtime checks its prerequisites before execution and verifies the outcome afterward. A shared executable-skill interface connects high-level skill selection, bounded low-level VLA execution, and post-action verification within a single agent loop. Because this interface remains fixed, low-level VLA policies can be replaced or adapted without changing the agent loop. The interface also records planning, execution, verification, and recovery events as structured trajectories, which provide supervision for individual components and can support optional online adaptation when interactive feedback is available. We instantiate EmbodiedSkills with Qwen3-VL and OpenPI/pi0.5 on RoboTwin 2.0 and LIBERO. Task-adapted low-level VLA policies achieve an average success rate of 86.20% across 50 RoboTwin 2.0 tasks and 97.40% across the four LIBERO suites. These results establish the execution performance of the task-adapted low-level VLA policies used in EmbodiedSkills. On four memory-dependent RMBench tasks, the same task-adapted execution approach achieves 12.5% average success. The framework provides a trainable and inspectable agent layer for turning these policies into closed-loop embodied systems.

## 1. 核心问题与研究动机

### 长期任务中的根本矛盾
- **VLA模型的直接映射局限**：视觉-语言-动作（VLA）模型擅长将视觉观察和语言指令映射为短期的动作生成，但现实中的机器人长时程任务（如"把容器放到盘子上"）涉及一系列相互衔接的物理操作，远非"预测下一步动作"所能覆盖。
- **动作预测≠物理有效性**：一个由模型预测的"动作"或"技能决策"，即便在语义上合理，也无法自行保证：
  - 在当前物理状态下**可执行**；
  - 具备**配套的前提条件**；
  - 执行后会产生**预期的实际效果**。
- **传统方法的割裂**：
  - 端到端 VLA 策略将中间决策（感知、规划、验证、恢复）隐式化，任务失败时难以定位是"目标识别、子目标选择、低级执行还是验证"环节出错；
  - LLM 机器人类代理虽然显式生成工具调用与推理步骤，但显式决策并不等于可执行决策，提示引导无法强制执行约束或验证物理效果。
- **核心研究挑战**：如何架起"模型级决策制定"与"物理世界执行"之间的桥梁，使模型提出的操作在执行前被校验、执行后结果可被验证，并将验证证据回流到后续的决策和学习中。

## 2. 方法论

### 2.1 核心思想：技能即执行提议
EmbodiedSkills 将每个技能决策（skill decision）视为一次**执行提议（execution proposal）**——高层的 VLM 代理先提出结构化操作，运行时不直接执行，而是依次对**前置条件**进行验证，完成后对**结果**进行核验。由此构建了一个`策略提议 (propose) → 运行时校验 (validate) → 执行 (execute) → 验证 (verify) → 结构化记录 (trace)`的闭环运作机制。

### 2.2 系统结构与关键流程（六阶段状态机）
系统由高层 VLM 代理、带守卫的运行层（Guarded Runtime）和低层 VLA 策略组成，采用固定的阶段序列（并非死板的串行流水线，可根据状态灵活回跳）：

| 阶段 | 作用 |
|----|----|
| **Observe（观察）** | 采集当前视觉证据，更新场景表示 |
| **Plan（规划）** | 将任务分解为有序的可验证语义子目标 |
| **Preflight（预检）** | 在执行前校验子目标是否具备执行条件，刷新过期证据 |
| **Execute（执行）** | 调用低层 VLA 策略生成有界动作块，在环境中执行 |
| **Verify（验证）** | 基于执行后的新观测判断子目标进度 |
| **Recover（恢复）** | 面对失败采用修订后的执行上下文安全重入 |

### 2.3 核心公式与机制（文字说明）
- **状态表示**：设当前子阶段为 z、可用的任务产物为 M、有序循环轨迹为 H，构成状态 s=(z, M, H)。策略看到的上下文 C 是对任务的指令、当前状态和循环轨迹的**压缩摘要**。
- **策略决策空间**：智能体每步只发出三类控制信号之一——**RunSkill（执行某技能）**、**AdvanceStage（前进到下一阶段）** 或 **FinishRun（结束任务）**。*这一机制与人类团队协作中的"提议—审核—执行"思路一致*。
- **技能合约（公式5）**：k=(X, Y, pre, exec, post, fail)，每个技能有类型化的输入输出模式、显式前置条件、执行操作、状态更新规则和失败映射；任何"模型输出的结果"在通过校验之前都只是**提议**。
- **守卫函数（公式7-10）**：
  - 技能守卫：检查当前阶段匹配、技能可用性、前提条件是否通过；
  - 前移守卫：检查当前子阶段产生的证据是否满足下一阶段需要；
  - 终止守卫：允许显式结束。
  - 守卫失败禁止状态更新，并记录阻塞证据。换言之，**模型没有能力跳过运行时校验而直接产生物理动作**。
- **动作块合法性（公式12-13）**：低层 VLA 策略输出的有限动作块 a=(动作类型, 维度上限, 动作序列, 上下文标识) 必须具备：动作类型有效、维度匹配、序列值数值合法、并且与当前子目标和观测具有"保鲜性（fresh）"对应——防止陈旧上下文驱动的无效动作被执行。
- **验证路径（公式14）**：执行后验证器输出语义路由：Advance / Continue / Reobserve / Replan / Recover / Finish，以此决定"推进计划、继续当前子目标、重观察、重新规划或进入恢复"。

### 2.4 训练方式：组件级适应
- **高层策略**：以 Qwen3-VL 为调度器，接受任务指令、当前观测、少量近期循环历史、可执行技能集合，输出一次"技能调用"决策。训练数据与**部署时输入完全一致**，避免训练—部署不一致。
- **低层策略**：以 OpenPI/π0.5 为基础，用"子任务级演示"做有监督的微调。每个样例是（图像+机器人状态+当前子目标文本→对应动作序列），一次子目标可由多个有界动作块完成。
- **解耦可替换**：各组件可通过独立接口训练或替换，低层 VLA 更换时**无需修改 AI Agent 循环逻辑**——例如升级低层控制策略、更换视觉编码器或调整验证器，都不影响周围的规划与运行时状态机。

## 6. 主要结论与发现

- **任务适应的低层 VLA 策略在执行接口上表现良好**
  - RoboTwin 2.0 的 50 个双手机器人操作任务平均成功率达到 86.20%，较 LingBot-VA 报告的 π0.5 参考值 82.74% 提高 3.46 个百分点；其中在悬掛杯子、大小积木排序、开微波炉、罐子移动、按压器等距离/接触敏感的难任务上取得了显著进步（分别 +20、+15、+15、+10、+10）；而在 39/50 的任务上超过参考值，仅 10 个任务出现 1-2 点的下降。
  - LIBERO 四个套件总计 97.40%，相比 OpenPI 参考值 96.85% 提升 0.55 个百分点；发挥最好的情景出现在 Long 长序列任务上（+1.2 点），证明接口本身不绑定单一基准的任务分类体系。
  - RMBench 记忆依赖的四种任务上 12.5% 的平均成功率超过 DP、ACT、π0.5 和 X-VLA 的参考结果，推测与它采用子任务条件和语义分解有关。
- **闭环消融证明了 AgentLoop 三机制的阶梯式贡献**
  1. 去掉语义子目标条件化（仅用任务指令生成动作块）→ 平均成功率从 86.20% 骤降为 34.4%，说明 VLA 策略无法从长指令中可靠推断当前阶段和具体任务；
  2. 在保留子目标序列但没有中间验证时 → 只有 48.2%，表明"固定序列开环执行不能适应初始状态和实际动作的差异"；
  3. 只给每个子任务 1 个 32 步的块而不能继续执行 → 19.5%，表明"子目标分解不足以支撑成功，还需要后验验证驱动的自适应续块"。
  这些结果共同保证了"子任务分解 + 动作后中期验证 + 有界动作块自适应续航"是闭环 VLA 代理设计中必需的组件配合。
- **分离策略与运行的框架价值**：将"决策提议层"与"可执行语义的运行时"分开之后，无效的决策不能直接变成物理操作；失败被公开地记录并在循环轨迹中稳定追踪——提高了调试验证性并允许组件单独训练或替换。

## 7. 优点

- **将决策与运行时执行安全解耦**：这是最具理论价值的贡献点。用固定接口取代提示注入或基准特定控制脚本，让模型引导的决策具有明确的物理安全基线。
- **可训练、可检查的智能体轨迹机制**：循环事件以结构化格式完整覆盖"规划、执行、验证、恢复"全过程，能够描述本体和端到端执行过程，追溯失败来源以做出精细的恢复。
- **组件的模块化**：子模块如规划器/验证器/调度器/低层 VLA 策略可以采用共享基础平台、独立 Adapter 和各自的训练范式，整体优化路径不必是"端到端黑盒的，不用在增加问题的抽象度时牺牲替换的灵活度"。
- **足够系统化的消融实验设计**：w/o V.、w/o S.、1-chunk 三个干扰点能从实证上剥离"验证模块、语义子任务模块、自适应执行步骤"各自的贡献，使得结论具备较强的可信度。
- **大范围的双基准验证**：从多任务双手机器人（RoboTwin 2.0）到泛化测试套件（LIBERO），再到独特的历史记忆依赖测试（RMBench），形成了一个三维的跨基准评估，有效说明实现的 VLA 执行接口在不同任务架构下都能保持稳定。

## 8. 不足与局限

- **底层能力**：闭环性能仍受底层策略和视觉/语言组件校准质量的局限，一个"在当前状态下没有物理意义但语义上合理"的子目标可能通过了语法验证却把执行引向错误状态，且对于遮挡、外观歧义或无法从视觉推断的特性（属性）不能完整验证。
- **部署成本与一致性风险**：50 个任务各维护一个专用 π0.5 策略的代价远高于单一通用策略（存储和训练成本激增），在分布式部署时引入对通用、子目标条件化的 VLA 基线的急切需求；模块级联合训练还可能产生接口边缘处的行为不兼容问题。
- **在线优化的归因粗糙**：单个回合向多个决策附着了同一回报，不能区分不同决策对成功贡献，因而其闭环在线训练被"可选性"所限定，只能作为组件级监督之后的增强。
- **报告的基准限制**：由于无法直接用同一环境重跑所有参考基线，实验对比多引用第三方报告，可能引入跨论文的细小差异；而 LIBERO 的对比基准已处于饱和水准，能产生的差额不大。
- **通用技术栈集成可迁移性问题**：任务相关的规划细节被刻画为固定的系统边界，若跨到真实物理机器人，接触丰富的触觉反馈、感知延迟等对实体环境适配器提出额外挑战（论文只观察到了模拟器背景下的验证，对真实世界环境的泛化能力未直接评估）。
