## 摘要
工具使用智能体越来越依赖外部工具来完成多步骤任务，但工具返回可能以不同方式失败，并需要不同的恢复操作。现有的鲁棒性研究通常使用基于不确定性的度量来检测智能体何时变得不可靠。这些度量可以揭示出了问题，但不能直接识别工具失败的类型或适当的响应。我们通过分析工具失败进入智能体上下文的那一刻来解决这一限制。我们的方法结合了两个互补的信号。第一个将返回内容在工具模式下的似然性与完整轨迹前缀下的似然性进行比较。第二个测量智能体对其合法下一动作的概率分布。我们通过向零售客户服务基准中注入不完整和不一致的返回来评估该方法。结果表明，基于似然的信号清楚地捕捉到不完整的返回和一些直接的不一致，而基于动作的信号揭示了失败如何强烈地改变下一个决策。某些在似然信号下较弱的失败仍然可以将智能体引向改变状态的行动。这些发现表明，工具失败可以在返回边界处被识别，但可靠的诊断需要结合多个信号。

## Abstract
Tool-using agents increasingly rely on external tools to complete multi-step tasks, but tool returns can fail in different ways and require different recovery actions. Existing robustness studies often use uncertainty-based measures to detect when an agent becomes unreliable. These measures can reveal that something has gone wrong, but they do not directly identify the type of tool failure or the appropriate response. We address this limitation by analyzing tool failures at the moment a return enters the agent context. Our approach combines two complementary signals. The first compares the likelihood of the returned content under the tool schema and under the full trajectory prefix. The second measures the agent's probability distribution over its legal next actions. We evaluate the approach by injecting incomplete and inconsistent returns into a retail customer-service benchmark. The results show that likelihood-based signals clearly capture incomplete returns and some direct inconsistencies, while action-based signals reveal how strongly a failure changes the next decision. Some failures that are weak under likelihood signals can still redirect the agent toward state-changing actions. These findings show that tool failures can be recognized at the return boundary, but reliable diagnosis requires combining multiple signals.

## 1. 核心问题与整体含义

- **背景**：工具使用型语言智能体（tool-using agents）依赖外部工具完成多步骤任务，但工具返回内容可能以不同方式失败，主要分为**不完整（incomplete）**和**不一致（inconsistent）**两类。前者表现为调用失败或字段缺失；后者则是在形式上合法、内部连贯，但与用户意图或先前工具返回冲突。
- **既有方法的不足**：现有鲁棒性研究主要使用不确定性度量（如预测熵、语义熵）或整条轨迹的熵曲线，只能判断“出了问题”，**无法识别失败类型**，也就难以决定相应的恢复动作（如重试 vs. 查证）。而错误的恢复策略可能与完全不处理同样有害。
- **论文目标**：在工具返回进入智能体上下文的那一刻（“返回边界”），利用**互补的信号组合**，识别失败类型，从而为后续恢复决策提供依据。

## 2. 方法论

- **核心思想**：不同类型的失败相对于不同的“参照系”是异常的。
  - 不完整返回：在**工具 schema** 下就很不寻常；
  - 不一致返回：可能完全符合 schema，但与**先前轨迹前缀**（包括用户意图、早期工具返回）不符。
- **两类信号**：
  1. **似然信号（likelihood channel）**：
     - 对返回字符串 x 计算两种条件下的每 token 平均负对数似然（surprisal）：
       - \(S_0(x)\)：仅以工具 schema 为条件；
       - \(S_1(x)\)：以 schema + 轨迹前缀 + 用户意图为条件。
     - 定义 gap：\(G(x) = S_1(x) - S_0(x)\)。额外上下文使正常返回更易预测，因此正常返回的 G 应明显为负；若与上下文冲突，G 会变大（趋近于零或正）。
  2. **动作信号（action channel）**：
     - 在注入返回后的下一个决策点，获得智能体在合法动作集合上的概率分布 π（共 17 个动作：16 个工具调用 + 1 个回复）。
     - 计算熵 \(H(\pi) = -\sum \pi_j \log \pi_j\)；
     - 记录最大概率动作 \(a^*\) 是否等于参考动作（用 A 表示）；
     - 记录概率质量在动作组上的分布：\(\pi(V)\)（重读状态/验证类工具）、\(\pi(W)\)（写操作工具）、\(\pi_r\)（回复）。
- **配对对比（paired contrast）**：由于熵会随对话长度漂移且似然是模型主观的，所有指标都相对“同一任务、同一决策点”的干净返回行做差分：\(\Delta X = X(\tilde{o}) - X(o)\)。这样可消除轨迹长度等混淆因素。
- **注入设计**：在 τ²-bench 零售域的第一个 `get_order_details` 调用（位置 ≥2）处注入，构造四个实验臂：
  - **C**：干净返回（基线）；
  - **F**：失败返回（不完整族，环境自产错误字符串）；
  - **Ns**：伪造订单状态字段（schema 合法但违反领域策略，需通过语义推理才能识别的矛盾）；
  - **Nm**：伪造支付方式标识（schema 合法，且正确值已在轨迹前缀中逐字出现，属于直接 token 级矛盾）。

## 3. 实验设计

- **数据集/场景**：τ²-bench 的零售客户服务域，共 114 个任务。筛选后 **53 个任务** 满足可重放、含有效注入点等条件。
- **基准与对比**：
  - 没有与外部方法做端到端对比，而是重点对比本方法内部的**两个信号通道（似然 vs 动作）**在不同失败类型下的表现；
  - 对照组为每个任务的干净行（C），所有指标均在配对差分意义上报告。
- **轨迹衰减测量**：注入后沿轨迹继续测量（k=0 为注入调用，k≥1 的返回在各臂间字节一致），检验信号是否持续可见。
- **统计检验**：对 F 臂在 k=1 处作符号检验，得到 p < 10⁻¹⁵。

## 5. 实验数量与充分性

- **规模**：53 个任务，189 个评分决策点（各臂数量不等：F 有 53 行，Ns 有 46 行，Nm 有 37 行）；每个臂都在注入点和 k=0~3 的后续轨迹上测量多种指标。
- **测量维度**：覆盖 \(\Delta S_0\)、\(\Delta G\)、\(\Delta H\)、领先动作变化、验证工具概率质量变化等，内容较丰富。
- **充分性评价**：
  - **优点**：配对差分设计控制了任务和轨迹前缀，统计检验（符号检验）支持了主要结论；对 F/Ns/Nm 三种条件做了仔细的区分（schema 合法性、矛盾可识别性）。
  - **不足**：仅一个领域、一个模型、一个注入点、模板化噪声；没有与其他诊断方法直接对比；动作分布测量在 teacher forcing 下进行，而非完整 rollout；任务数量偏少，且不同臂样本量不同，跨臂比较只能“指示性”而非严格定量。

## 6. 主要结论与发现

- **F（失败/不完整返回）**：在两类信号中都清晰可见。schema 似然显著偏移、G 增大；动作分布上推高对“重读状态”工具的概率，并且这种影响在注入后几步仍持续。
- **Nm（直接不一致）**：主要被似然信号捕获——当正确值在轨迹前缀中出现时，G 明显上升；但动作分布几乎不受影响，不改变领先动作。
- **Ns（策略级不一致）**：似然信号难以检测（G 无明显方向），但动作信号显示它能增加行动不确定性、改变领先动作，甚至将智能体引向**写操作**而非验证工具。
- **核心结论**：没有单一指标能覆盖所有失败类型；似然信号反映“返回内容本身是否异常”，动作信号反映“返回如何影响下一步决策”，两者互补，可靠诊断需要联合使用。

## 7. 优点

- **问题定位精准**：首次把工具失败诊断放在“返回进入上下文”的边界上，而不是靠整条轨迹的熵曲线事后推测。
- **信号设计有层次**：同时利用“schema 下的似然”和“全轨迹前缀下的似然”，区分了“格式异常”和“上下文冲突”，并能捕捉“直接矛盾”与“策略推理矛盾”的差异。
- **动作级分析**：不仅看熵，还看领先动作和动作组概率质量，能识别“似然信号弱但实际影响严重”的失败。
- **实验控制严格**：配对差分、固定注入调用点、保持数据库状态不变、只修改返回 payload，排除了多数混淆变量。
- **展示轨迹衰减**：沿 k 步追踪信号残留情况，说明似然影响和动作影响的时效性。

## 8. 不足与局限

- **覆盖范围窄**：仅一个领域（零售客服）、一个模型（Qwen3-8B）、一个注入点、一种注入方式（模板化而非对抗性噪声），泛化性未知。
- **Teacher forcing**：实验固定了参考动作序列，测量的是“给定改变后的上下文下模型的即时反应”，而非真实 rollout 中智能体主动选择动作后的累计影响，因此不能直接解释任务完成率的退化。
- **跨臂可比性受限**：不同任务目标字段可用性不同，导致 Ns/Nm 样本数少于 F，跨臂比较是“指示性”而非严格对称的。
- **模型主观性**：似然是模型依赖的，不同模型可能在不同失败类型上表现出不同敏感性。
- **未与其他诊断方法对比**：没有在相同注入数据下与预测熵、语义熵等基线方法直接比较，无法量化本方法的相对提升。
- **未探讨所有失败类型**：论文在讨论部分提到“无关返回”“歧义返回”等带内/带外失败，但没有实验验证，属于未来工作。
