## 摘要
LLM代理在长时间跨度的任务上仍然不可靠，局部的微小失败可能会在扩展交互中累积，并导致整体任务失败。尽管外部工具链可以显著提升鲁棒性，但工具链设计仍是一个手动且昂贵的过程，需要在大量提示、工具配置和控制逻辑的空间中进行搜索。我们提出AutoSaddler，一种自动工具链优化框架，将工具链改进形式化为离线学习问题，并利用小批量的失败信号迭代更新工具链。AutoSaddler结合了失败轨迹诊断、将工具链视为代码的结构化补丁生成以及基于验证的更新选择。在GAIA2、SWE-Bench Pro和Terminal-Bench 2.0上的实验表明，AutoSaddler相对于对应的基础工具链显著提升了代理性能，分别取得了9.0、9.6和10.0个百分点的增益。消融研究进一步表明，有效的工具链优化受益于三个要素：深度调试而非浅层反思、针对性修改而非无约束编辑，以及泛化感知的选择而非特定轨迹的修复。综合来看，这些结果表明自动工具链优化是通向更高性能和更可靠代理系统的有前景的路径。

## Abstract
LLM agents remain unreliable on long-horizon tasks, where small local failures can compound over extended interactions and lead to overall task failure. Although external harnesses can substantially improve robustness, harness design remains a manual and expensive process that requires searching over a large space of prompts, tool configurations, and control logic. We propose AutoSaddler, an automatic harness optimization framework that formulates harness improvement as an offline learning problem and iteratively updates the harness using failure signals from mini-batches. AutoSaddler combines failure-trace diagnosis, structured patch generation that treats the harness as code, and validation-based update selection. Experiments on GAIA2, SWE-Bench Pro, and Terminal-Bench 2.0 show that AutoSaddler substantially improves agent performance over the corresponding base harnesses, achieving gains of 9.0, 9.6, and 10.0 percentage points, respectively. Ablation studies further suggest that effective harness optimization benefits from three ingredients: deep debugging rather than shallow reflection, targeted modifications rather than unconstrained editing, and generalization-aware selection rather than trajectory-specific repair. Together, these results suggest that automatic harness optimization is a promising path toward more performant and reliable agent systems.

### 1. 核心问题与整体含义

- **研究背景**：大语言模型（LLM）尽管能力提升迅速，但在长周期任务中仍表现出不稳定的可靠性。局部小错误在扩展交互中逐步累积，最终导致整体任务失败（即“锯齿状智能”现象）。
- **现有解决方案的不足**：外部 harness（工具链，涵盖提示词、工具配置、控制逻辑等）能显著提升代理鲁棒性，但 harness 设计严重依赖手工，成本高昂且难以规模化——设计空间大、评估代价高、轨迹分析困难。
- **核心研究问题**：能否**自动化 harness 优化过程**，使其在有限执行预算下高效找到泛化性能更好的工具链配置？AutoSaddler 对这一问题的回答是：将 harness 优化形式化为**离线学习问题**，通过迭代式的失败诊断、结构化补丁和泛化感知筛选来实现。

### 2. 方法论

#### 核心思想
AutoSaddler 将 harness（由提示词、工具、中间件三类参数构成）视为可“学习”的对象，用**小批量训练**的方式替代人工调参：在每一轮迭代中评估当前 harness，诊断失败轨迹，生成结构化补丁，验证补丁效果，并通过有向无环图（EvoDAG）积累经验以指导后续演化。

#### 关键技术细节

- **优化目标**：在有限 rollout 预算 K 内，最大化任务分布上的期望性能：
  - \( J(θ) = \mathbb{E}_{(x,y^*) \sim T} \mathbb{E}_{(\tau,\hat{y}) \sim P_θ(\cdot|x)}[\mu(\hat{y}, y^*)] \)
  - 其中 θ =（θ_prompt，θ_tool，θ_middleware），即提示词、工具和中间件三类 harness 参数。

- **三个核心组件**：
  1. **诊断-补丁会话（Diagnosis-Patch Session）**： 诊断与补丁生成耦合进行。代理被赋予失败轨迹和 harness 代码库，通过逐步检索相关轨迹细节（缓解长上下文问题）来识别根因，并生成**结构化补丁**。补丁空间被划分为三类（Prompt、Tool、Middleware）九种亚型，并进一步分为**能力补丁（Capability）** 和**引导补丁（Steering）** 两组。
  2. **反思会话（Reflection Session）**： 对比补丁前后的轨迹，将结果分类为 fixed / regressed / still-failing / still-passing 四类，并有针对性地提取经验教训。若补丁通过小批量验证，还会额外评估开发集上的泛化表现。
  3. **演化会话（Evolution Session）**： EvoDAG 存储所有历史 harness 节点（含补丁描述、指标、经验教训）和边（补丁差异）。演化代理可跨谱系重组成功组件，而非只在当前候选上继续，从而跳出局部最优。

- **分阶段补丁调度（Phased Patch Scheduling）**： 类似学习率调度——先用**能力补丁**（探索阶段）解决工具/基础设施/控制流的根本缺陷，再切换到**引导补丁**（精炼阶段）微调行为。

- **与 mini-batch 训练的类比**： 诊断-补丁-验证 对应“反向传播”，反思+EvoDAG+演化对应“优化器更新”，开发集验证对应“checkpoint 泛化门控”。

- AutoSaddler 在三个基准上均显著优于基础 harness：GAIA2 提升 9.0 pp（53.0%→62.0%）、SWE-Bench Pro 提升 8.4 pp（37.3%→46.9%）、Terminal-Bench 2.0 提升 10.0 pp（40.0%→50.0%）；相比最强自动基线分别提升 7.4、6.2、4.4 pp（摘要中称 7.4/4.4/6.7，正文中据表格为 7.4/4.4/6.2）。
