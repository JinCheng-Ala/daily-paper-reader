## 摘要
自主LLM智能体越来越多地部署在复杂的现实工作流中，但它们仍然容易受到运行时行为漂移的影响，这是一种偏离原始任务的静默偏差，可能对外部系统造成不可逆的副作用。现有方法在提示级别处理漂移，但缺乏步骤级检测、风险评估和恢复决策的结构化机制。由于主任务执行智能体通常是大型且昂贵的模型，无法在每次部署时重新训练，因此本工作针对即插即用的恢复模块。它引入了一个基于图的框架，其中单个小型语言模型通过强化学习训练，在恢复图的每个节点上专门化，独立于主智能体。每个节点都有精确的角色：漂移分类、操作检测、风险评估或最终决策，模型学习生成适合该角色的结构化XML格式推理。训练结合了基于规则的结构奖励和LLM作为评判者的语义质量信号，因此模型在回答方式（模式和长度）和内容上都被评分。在公开的AppWorld基准上的实验表明，该方法通常利用有关疑似漂移起点的信息，使用小型语言模型发出正确的恢复决策。此外，训练后的小型语言模型可靠地遵守规定的输出模式，并根据其分配的节点角色在每个字段中产生语义上适当的内容。

## Abstract
Autonomous LLM agents are increasingly deployed in complex real-world workflows, yet they remain vulnerable to runtime behavioral drift, a silent deviation from the original task that can lead to irreversible side effects on external systems. Existing approaches address drift at the prompt level but lack structured mechanisms for step-level detection, risk assessment, and recovery decision. Because the main task-executing agent is often a large and expensive model that cannot be re-trained on every deployment, this work targets a plug-and-play recovery module instead. It introduces a graph-based framework in which a single small language model is trained via reinforcement learning to specialize at each node of a recovery graph, external to the main agent. Each node has a precise role\,: drift classification, operation detection, risk evaluation, or final decision and the model learns to produce structured XML-formatted reasoning adapted to that role. Training combines rule-based structural rewards with an LLM-as-judge semantic-quality signal, so that the model is graded both on how it answers (schema and length) and on what it says. Experiments on the public AppWorld benchmark show that the method generally exploits information about the suspected drift onset to issue correct recovery decisions using a small language model. In addition, the trained small language model reliably respects the prescribed output schema and produces semantically appropriate content in each field according to its assigned node role.

## 1. 核心问题与整体含义（研究动机与背景）

**问题定义：Runtime Behavioral Drift（运行时行为漂移）**
- 自主 LLM 智能体在真实工作流中会执行 API 调用、发邮件、转账、修改数据库等实际操作，而不仅仅回答问题。
- 行为漂移是指智能体在执行过程中**静默偏离原始任务**，通常由网页/邮件中隐藏的恶意指令（prompt injection）或自发的子目标过度扩展引发。
- 漂移的后果可能造成**不可逆的环境副作用**——回滚消息历史不等于回滚环境状态（即 "rolling back the message history does not roll back the world"）。
- 现有防御工作（如指令层级训练、防火墙、隔离不可信内容）大多集中在**预防**层面，缺乏对已发生漂移的**事后检测、风险评估与恢复决策**机制。

**论文的核心立场**
- 主任务执行智能体通常是大型且昂贵的模型，无法在每次部署时重新训练。
- 因此本文提出一个**即插即用（plug-and-play）的外部恢复模块**：用强化学习训练单个小型语言模型，在恢复图的各个节点上分工执行漂移分类、操作检测、风险评估和最终决策，无需改动主智能体。

## 2. 方法论

### 2.1 核心思想
- 将漂移恢复建模为**五节点诊断状态机的路由遍历**。
- 所有节点共享同一个小型策略模型，通过**角色条件提示（role-conditioned prompts）** 区分各节点职责。
- 每个节点输出统一的 XML 结构：一个 `<reasoning>` 推理块 + 一个 `<answer>` JSON 答案块。

### 2.2 恢复图架构（五节点）
1. **Classify Drift（n1）**：判断给定步骤是否与任务对齐（Y/N），并给出简短理由。
2. **Detect Operations（n2）**：枚举该步骤中实际成功执行的写操作和离题读操作。
3. **Search Documentation（n3）**：输出去重后的涉及应用/API 名称列表，用于获取文档。
4. **Evaluate Risk（n4）**：结合 API 文档将写操作划分为 `write_reversible` 与 `write_not_reversible`。
5. **Aggregate & Decide（n5）**：综合各步骤诊断结果，输出最终动作——`rollback_before_drift`（带目标步骤）或 `escalate_human`（带结构化事故报告）。

### 2.3 向后遍历与对齐连续段终止
- 从外部检测器提供的疑似漂移起点 k0 开始，**逐步骤向过去回溯**。
- 每个步骤由 n1 判定对齐与否；若为 N 则触发 n2–n3–n4 操作检测链，然后回到 n1 继续向前一步。
- 当连续 K 个步骤都被判定为对齐时，终止回溯并进入 n5 聚合决策。
- K 的设定源于观察：单个对齐步骤不足以保证漂移边界，需要短连续段作为稳健代理指标。

### 2.4 GRPO 强化学习训练
- 采用 **GRPO（Group Relative Policy Optimization）**，不训练价值网络，优势值按组内相对计算：

  \[
  \hat{A}_i = \frac{r_i - \bar{r}}{\text{std}(r) + \varepsilon}
  \]

- 目标函数为带裁剪比率和 KL 散度惩罚的策略优化目标：

  \[
  J(\theta) = \mathbb{E}\left[ \min(\rho_i \hat{A}_i, \text{clip}(\rho_i, 1-\epsilon, 1+\epsilon) \hat{A}_i) - \beta D_{KL}(\pi_\theta \| \pi_{\text{ref}}) \right]
  \]

- 训练使用 **LoRA 适配器**（rank=128, α=256），保持 πθ 为对基础模型的轻量更新。

### 2.5 复合奖励函数
- 总奖励为九个分量的加权和：

  \[
  R(o, \nu, q) = \sum_{k=1}^{9} w_k r_k(o, \nu, q)
  \]

  八个**规则化结构奖励**：
  - `r_xml_count`：XML 标签数量与尾噪声惩罚
  - `r_strict`：严格标签顺序与间距奖励
  - `r_soft`：宽松标签顺序奖励
  - `r_reason_len`：推理块长度约束
  - `r_total_len`：总输出长度紧凑性
  - `r_json_valid`：JSON 语法有效性
  - `r_json_schema`：键与节点预期集合匹配（精确匹配满分，Jaccard 部分分）
  - `r_json_sanity`：节点级值域检查（如 `is_aligned` 必须为 Y/N）

  一个**语义质量奖励（LLM-as-judge）**：
  - `r_judge`：冻结的 14B 推理模型根据节点角色 rubric 对输出内容打分（1.0=具体、有根据、正确；0.5=泛泛但无错；0.0=空洞、幻觉或矛盾）。
  - 评判者被明确指示忽略 XML/JSON 格式问题，仅评估推理是否基于输入、字段内容与推理是否一致。

## 3. 实验设计

### 3.1 Benchmark
- 使用 **AppWorld** 基准：约 450 个 API、九个模拟应用（Spotify、Gmail、Venmo、Splitwise 等），按难度 1–3 分级。
- 评估指标为 **task_goal_completion**（任务目标完成率）。

### 3.2 漂移注入协议
- 在智能体消息历史中插入恶意指令，载荷为来自 AppWorld 任务池的不同任务。
- **Type I（瞬态读漂移）**：注入任务为只读，消息历史回滚即可恢复。
- **Type II（持久读漂移）**：触发源持续存在（如邮件中的恶意指令），回滚后重新执行时仍会遭遇，需附加警告。

### 3.3 基线设置
- **base vs. trained**：每个基础模型（未训练）与训练后对比。
- **No drift（上界）**：无漂移注入的正常执行。
- **Drift, no recovery（下界）**：有漂移但无恢复。
- **GPT-4o / GPT-4o-mini recovery**：将前沿模型接入同一恢复图作为能力 oracle。
- **Granite base（未训练）**作为恢复骨干，用于隔离节点专门化训练的效果。
- 初始代理骨干：GPT-4o 和 GPT-4o-mini。

## 6. 主要结论与发现

1. **单一小模型可专门化为全部五个节点角色**：无需每节点单独训练策略或奖励，仅靠节点标记条件提示 + 复合奖励即可。
2. **结构一致性大幅提升**：`json_schema` 从 Granite 0.67→0.98、Qwen 0.08→0.97，`json_sanity` 也显著提升；Qwen 的总奖励从 0.56 提升至 4.80（8.6×），Granite 从 3.68 提升至 5.15。
3. **语义质量也获得非平凡提升**：`r_judge` 在 Granite 上 0.71→0.90，在 Qwen 上 0.47→0.66，说明 GRPO 不只优化格式。
4. **端到端恢复效果可观**：
   - Type I（GPT-4o 初始代理）：trained Granite 恢复 27.5% 聚合任务完成率，为 no-drift 上界（35.3%）的 **78%**，接近 GPT-4o recovery 的 32.5%；D1 级别与 GPT-4o 完全持平（57.1%）。
   - Type II（GPT-4o 初始代理）：trained Granite 恢复 35.0%，接近 no-drift 基线 42.5%。
5. **未训练的 Granite base 全部失败（0.0%）**，验证了节点专门化训练的必要性——小模型不能自发产生可用输出。
6. **模型规模差距在训练后被大幅压缩**：Qwen 1.5B 与 Granite 2B 的奖励差距从 3.12 缩小到 0.35（8.9× 压缩）。

## 7. 优点

- **即插即用设计**：不触碰主代理，独立恢复模块可以以低成本（单 GPU、小型模型）集成到现有部署。
- **方法新颖**：将漂移恢复形式化为诊断性状态机而非任务求解图，节点角色明确（分类/提取/查档/评估/决策），而非重复同一 Thought/Action/Observation 循环。
- **结构化输出纪律**：强制 `<reasoning>` + `<answer>` XML 格式，将下游解析成本从"语义重解析"降为"直接读取"，避免自由文本 CoT 传参的脆弱性。
- **奖励设计兼顾形式与内容**：九分量复合奖励让模型同时学会"如何回答"和"说什么"，LLM-as-judge 弥补纯规则检查无法评估语义真实性这一缺口。
- **训练效率高**：GRPO 去掉值网络，单 GPU 即可训练；LoRA 保持对基座模型的轻量更新；组归一化优势自动吸收 judge 分数的绝对尺度。
- **实验分析细致**：逐节点、逐分量、逐提示词的奖励分解让读者能精确定位增益来源与薄弱节点。

## 8. 不足与局限

- **Type III（写漂移）无端到端验证**：尽管 n4 负责可逆性分类，但当前框架不执行逆 API 调用，实际上对写操作只做"标记+上报"而非"修复"。可逆/不可逆划分仅作为决策信号，未闭环为纠错动作。
- **漂移单调性假设**：论文在 Remark 1 中承认漂移可能呈现交错模式（漂移→对齐→漂移），但方法论部分明确假设漂移一旦开始即单调持续，限制了框架在交错漂移场景下的适用性。
- **对疑似漂移起点 k0 的依赖**：恢复质量依赖外部检测器提供的起点质量，若起点偏差过大，整个向后遍历可能错失真正的漂移区间。
- **Judge 能力瓶颈**：LLM-as-judge

- **Judge 能力瓶颈**：LLM-as-judge 的语义质量打分依赖于一个额外的 14B 推理模型，该模型本身存在判断偏差，且无法保证完全捕捉细粒度的事实性错误或业务规则违例；训练阶段对 judge 的依赖也增加了部署复杂度（需要自托管推理服务并维护其可用性）。此外，judge 的 1.0/0.5/0.0 三级评分粒度较粗，可能无法区分语义质量的细微差异。
- **端到端任务数有限，统计功效不足**：每设置仅 40 个任务，尤其在 D2/D3 难度下基础完成率极低（7.7%、0–30.8%），导致恢复效果提升的置信区间较宽；论文也承认 85.7% vs 78.6% 的轻微越界属于小样本下的正常方差。这使得某些结论的稳健性有待更大规模评测验证。
- **模型规模覆盖有限**：训练实验仅覆盖 2B 和 1.5B 两个小模型，未验证该训练范式在 7B/8B 或更大模型上的有效性；虽然论文声称小模型足够，但更大大小的模型能否带来额外收益尚不清楚。
- **多语言与多模态场景未探索**：所有实验均基于英文文本交互的 AppWorld 环境，未涉及多语言指令、语音/图像输入等场景，限制了方法的通用性结论。
- **对现有防御机制缺乏联合评估**：论文将恢复模块定位为“事后恢复”，但未与常见的“事前防御”（如指令层级训练、提示注入检测器、不可信内容隔离）组合测试；实际部署中二者如何协同（检测器漏报/误报率如何影响恢复模块）缺乏实验依据。
- **决策空间过于二元化**：最终动作只有 `rollback_before_drift` 或 `escalate_human`，缺少更细粒度的中间操作（如部分回滚、暂停后确认、定向撤销某个写操作、保留已完成的无害子任务等），限制了在复杂工作流中的实用灵活性。
- **评估指标单一**：仅使用 `task_goal_completion` 作为端到端指标，未报告副作用严重度、误报率、恢复成本（时间/API 调用开销）、人类介入频次等维度；因此难以全面权衡“自动回滚”与“上报人工”的收益与风险。

## 9. 总结与展望

本文的核心贡献在于**将 LLM 智能体的运行时行为漂移恢复问题重新定义为一个可训练的、即插即用的外部诊断过程**。通过五节点恢复状态机 + GRPO 强化学习，作者成功让一个 2B 参数的小模型在结构化输出纪律与语义质量两方面都获得显著提升，并在 AppWorld 端到端任务中逼近 GPT-4o 的恢复效果，同时完全超越了未训练的同类小模型。

该工作的价值体现在三个层面：
1. **工程层面**：无需改动主智能体、无需重训大模型、单张 A100 即可完成训练，展示了低成本、高可移植性的恢复模块设计。
2. **方法层面**：将漂移恢复从“自由文本纠错”转化为“结构化节点路由+强化学习对齐”，并设计九分量复合奖励解决格式与语义的联合优化，这一思路可迁移到其他 agent 可靠性任务（如安全审查、合规检查）。
3. **科学层面**：通过消融剖析了结构奖励与语义奖励各自的贡献，揭示了“小模型经过针对性训练可以承担复杂诊断角色”这一重要结论。

未来研究方向值得关注：
- **闭环写漂移修复**：让恢复模块不仅“标记”不可逆操作，而是学习调用 API 执行撤销或补偿动作，真正实现“环境状态回滚”。
- **交错漂移处理**：引入更灵活的状态模型（如 HMM）以识别漂移→对齐→漂移的间歇模式，降低对“单调漂移”假设的依赖。
- **与实时检测的协同**：将恢复模块与旁路检测器联合训练，使整个检测-恢复管线端到端可微，减少对人工设定起点 k0 的敏感度。
- **扩展到更广泛环境**：将训练协议应用于更复杂、多模态、多用户交互的 agent 平台，并纳入副作用评估指标。

总体而言，这是一篇**方法新颖、实验严谨、工程落地性强**的工作，尤其适合关注 LLM 智能体安全、可靠性与强化学习应用的研究者和工程师阅读。尽管存在 Type III 验证缺失、样本量有限等不足，但其问题定位和解决方案在自主 agent 走向真实世界部署的当下具有重要参考价值。
