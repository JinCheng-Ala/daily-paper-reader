## 摘要
基于大型语言模型的智能体框架主要优化能力：智能体能否推理、检索信息、调用工具、委派工作并完成目标。企业级执行则需要一个更强的属性。如果成功结果是通过未经授权的数据访问、扩大的委派权限、未经批准的副作用、不可恢复的预算消耗或不完整的证据产生的，那么它并不可靠。本文将可靠能力定义为路径属性：只有当智能体通过行动事件完成任务，且这些事件在身份、配置文件、工具、数据、记忆、预算、工件、审批和审计约束下仍然可接受时，该智能体才被认为是可靠有能力的。我们提出了一种政策代数，定义了智能体能力可被行使的可靠性边界。安全配置文件和运行时义务通过连接、交集、预算收窄、审批继承和证据积累进行组合；由此产生的组合既保留信任，又是满足所有管控输入的最不限制状态。该代数还在多智能体调用中传播限制，并引入了成本感知的工件物化，随着预算暴露的增长，将开放式执行导向可恢复的结果。评估被解释为可靠性-能力权衡而非能力基准：政策代数运行时干预了94.8%的违反政策事件，同时保留了86.9%的任务完成率，消除了观察到的配置文件单调性和零工件耗尽违规，并将审计完整性提高到98.6%。该方法为研究人员和实践者提供了形式化正确性条件、可执行决策语义和痕迹证据，以构建不仅有能力而且可靠有能力的智能体。

## Abstract
Large language model-based agentic frameworks primarily optimize capability: whether an agent can reason, retrieve information, call tools, delegate work, and complete a goal. Enterprise execution requires a stronger property. A successful result is not reliable if it was produced through unauthorized data access, widened delegated authority, unapproved side effects, unrecoverable budget consumption, or incomplete evidence. This paper defines reliable capability as a path property: an agent is reliably capable only when it completes a task through action events that remain admissible under identity, profile, tool, data, memory, budget, artifact, approval, and audit constraints. We propose a policy algebra that defines the reliability envelope within which agent capability may be exercised. Security profiles and runtime obligations compose through joins, intersections, budget narrowing, approval inheritance, and evidence accumulation; the resulting composition is both trust-preserving and the least restrictive state satisfying all governing inputs. The algebra also propagates restrictions across multi-agent calls and introduces cost-aware artifact materialization, which redirects open-ended execution toward a recoverable outcome as budget exposure grows. The evaluation is interpreted as a reliability-capability trade-off rather than a capability benchmark: the policy-algebra runtime intervenes on 94.8% of policy-violating events while retaining an 86.9% task-completion rate, eliminates the observed profile-monotonicity and zero-artifact-exhaustion violations, and increases audit completeness to 98.6%. The method provides researchers and practitioners with formal correctness conditions, executable decision semantics, and trace evidence for building agents that are not only capable, but reliably capable.

## 1. 核心问题与整体含义

- **研究动机**：当前的大语言模型（LLM）智能体框架主要优化“能力”（capability），即智能体能否推理、检索、调用工具、委派任务并达成目标。然而，在企业执行环境中，仅仅有能力还不够：如果结果是通过未经授权的数据访问、扩大的委派权限、未批准的副作用、不可恢复的预算消耗或不完整的证据产生的，那么该结果不能被信任。“可靠的能力”（reliable capability）必须是一种**路径属性**——智能体只有在通过一条完整可接受的动作路径达成目标时，才称得上有能力并且可信。
- **核心问题**：如何在不显著牺牲任务完成率的前提下，确保每一项被执行的智能体动作都满足身份、角色、配置、数据、记忆、工具、预算、工件、审批和审计的全部约束？即如何最大化“在可靠性包络内的有用自主性”。
- **整体含义**：智能体安全不应只关注最终输出或提示词层面的防御，而应聚焦于“推理到动作的转换”（reasoning-to-action transition）这一环节。现有标准（如OWASP AISVS、NIST AI RMF、MAESTRO）提供了威胁识别和控制类别的知识基础，但缺少可执行的运行时语义；本文用策略代数填补了这一空白，使评估类工件能够编译为可执行的运行时约束。

## 2. 方法论

- **核心思想**：将可靠能力定义为“至少存在一条可达目标的执行轨迹，且该轨迹上每个动作事件都满足所有安全谓词的合取”。可靠性是所选择轨迹上的全称性质，能力则是对轨迹集合的存在性性质。
- **策略代数基础**：
  - 策略状态表示为 $\varpi = (p, T, \Theta, B, Q, h, E)$，分别对应安全配置文件、工具/服务权限集合、记忆/数据范围、剩余预算、工件物化策略、人工审批标志、证据义务集合。
  - 定义代数顺序 $\preceq_{alg}$，表达“至少同样严格且至少同样可审计”的偏序关系。
  - 策略组合运算 $\varpi_1 \otimes \varpi_2$ 通过**配置文件连接**（取更严格）、**工具集交集**、**记忆范围交集**、**预算最小值**、**物化策略连接**、**审批义务析取**、**证据义务并集**实现多方策略的合成。
- **关键定理**：
  - **定理1（信任保持）**：组合后的策略状态不会弱于任何一个输入状态，即不能降低配置保证、增加工具权限、扩大记忆范围、增加预算、软化物化要求、移除审批或审计义务。
  - **定理2（最不严格健全组合）**：组合结果是满足所有输入策略的最小上界（least upper bound），不会施加超出各输入所要求的额外限制。
- **策略级联**：有效配置文件 $p_{eff}$ 为平台、团队、用户、智能体和发布五级配置文件的连接 $\sqcup$，任何一层可以收紧但不可放宽下层继承的约束。
- **策略交叉工具授权**：工具调用必须通过 RBAC 权限、智能体白名单、服务暴露策略、威胁层策略、数据策略、预算、物化策略和审批谓词的合取（Permit 公式）。
- **RAG 与记忆访问**：读取和写入分别用 Read_p 与 Write_p 谓词约束，涉及数据分类、ACL、范围、目的、TTL 和脱敏映射。
- **信任保持委派**：父子委派时配置文件取连接、工具集取交集、预算取最小值、审批取析取、记忆范围取交集，防止“配置文件清洗”（profile laundering）。
- **成本感知工件物化（算法5）**：当累计成本超过阈值 α 时重定向到物化；超过 β 时仅允许产生工件的动作，确保预算耗尽前存在可恢复输出。
- **受控动作选择（优化问题式31）**：在可行集内对效用、风险、成本加权优化，硬策略约束优先于风险评分。
- **威胁到控制映射**：将威胁发现编译为最小配置文件门槛、运行时谓词和审计证据字段，使评估产物转化为执行约束。

## 3. 实验设计

- **工作负载构成**：共 **612 条多步轨迹、1,936 个动作事件**（其中 842 个不安全事件、1,094 个安全事件），分为五个工作负载族：

  - RAG 与记忆治理任务（137 轨迹）
  - 多智能体委派任务（121 轨迹）
  - 发布与服务调用任务（88 轨迹）
  - 预算、工件物化、HITL 与沙箱任务（112 轨迹）
- **对比方法**：RBAC + 工具白名单（RBAC-and-allowlist comparator），即只做单层授权的基线系统。
- **评估指标体系**（七项）：
  - 不安全事件干预率（Unsafe Intervention Rate）
  - 错误干预率（False Intervention Rate）
  - 配置文件单调性违规次数
  - 零工件预算耗尽次数
  - 审计完备性（Audit Completeness）
  - 任务完成率（Task Completion Rate）
  - 授权延迟（中位数和 P95）
- **场景级子实验**：覆盖提示注入触发禁用工具、未授权工具执行、RAG 越权访问、记忆投毒写入、子智能体配置文件清洗、无 HITL 的外部副作用、发布/配置文件漂移、预算或速率耗尽、沙箱/网络逃逸九个具体场景。

## 6. 主要结论与发现

- **可靠性-能力权衡**：策略代数运行时相比 RBAC+白名单基线，将不安全干预率从 67.1% 提升至 **94.8%**（干预了 842 个不安全事件中的 798 个）；任务完成率由 90.7% 下降至 86.9%，保留了基线 95.8% 的完成率——这是“以少量能力换取更强可靠性”的直接量度。
- **消除关键违约**：配置文件单调性违规从 31 起降至 **0**；零工件预算耗尽从 18 起降至 **0**，验证了委派代数与成本感知物化机制在测试工作负载上的有效性。
- **审计完备性**：从 71.9% 提升到 **98.6%**，使失败案例可复现、可修复。
- **副作用**：错误干预率从 2.1% 上升到 4.2%，中位授权延迟从 38ms 升至 71ms（P95 从 91ms 升至 184ms），是增强约束所付出的直接代价。
- **整体判断**：该工作提供了让“标准/威胁模型 → 可执行谓词 → 运行时约束 → 证据记录 → 策略修复”闭环可落地的形式化基础；主要目的是把“能行动的智能体”转化为“能可靠行动的智能体”，而不是无限制地宣称任务完成率优势。

## 7. 优点

- **理论严谨**：给出策略代数的封闭性、交换律、结合律、幂等性、信任保持定理和最不严格性定理，使策略组合具有可预期的代数结构。
- **关注根本安全转变**：将安全目标从“输出安全”重新定义为“动作路径可靠”，准确抓住了智能体“推理 → 动作”这一关键转换点。
- **可扩展的治理架构**：配置文件级联、策略交叉授权、委派单调传播机制天然适用于多智能体场景和 MCP/REST 发布控制。
- **成本与安全结合**：成本感知工件物化将“预算耗尽无工件”视为策略违约，从平台层面强制“止损”，这是突破单纯访问控制思维的重要亮点。
- **可执行、可闭环**：给出从标准/威胁工件到运行时谓词、审计字段、回归测试的具体编译器、算法（五套）、Python 风格测试代码和修复策略，具备实践可操作性。
- **客观披露条件**：用条件正确性分解（上下文感知误差 vs. 决策逻辑误差）明确划清了代数能保证什么、不能保证什么。

## 8. 不足与局限

- **缺乏大规模通用基准验证**：实验结果来自自建符合性工作负载（612 条轨迹），不是公共基准；没有与最新运行时防御系统（如 ClawGuard、DRIFT）做对照，也没有给出置信区间或跨数据集泛化证据。
- **依赖上下文与元数据正确性**：代数定理的前提是上下文构造正确；若文档分类有误、工具意图不明、服务元数据过期，则可能出现漏拦。这一点被论文归为外部边界问题（式7），但也是实际部署中的主要可靠性风险。
