## 摘要
自我改进的LLM代理将成功的轨迹转换为持久的跨任务状态。因此，一个不安全的成功在其触发输入消失后可能成为可重用的策略。技能进化通过将操作轨迹提炼为可执行、可转移和可检查的程序，使这种失败变得可测量。由于进化优化的是任务结果而非程序安全性，受损的经验可能导致技能误进化。现有基准衡量当前行为或静态工件，但无法在编写、检索和后续执行之间归因风险。为了揭示这一生命周期，我们引入了SkillMisevo-Gym，一个生命周期感知的测试平台，跨代理框架对技能状态进行版本控制，以及SkillMisevo-Bench，一个从恶意暴露到携带任务的冻结设计，包含概念对齐的良性任务和九个生命周期指标。我们还引入了SafeEvolve，一个修复不安全内容并管理后续重用的包装器。在25种代理方法配置中，每种配置覆盖25个情节中的525个任务，所有21种进化配置都编写了不安全的工件，而只有15种导致新会话中的伤害。在暴露扫描中，三个恶意任务将携带任务的ASR从16.0%提高到35.3%。在代表性的技能进化方法中，SafeEvolve将不安全检索和新会话伤害分别降低了26.7和17.3个百分点，而平均良性效用仅变化了0.4个百分点。总之，持久适应安全性必须管理更新写入的内容以及未来执行者重用的内容。代码可在https://github.com/henrymao2004/misevolve获取。

## Abstract
Self-improving LLM agents convert successful trajectories into persistent cross-task state. An unsafe success can thereby become reusable policy after its triggering input disappears. Skill evolution makes this failure measurable by distilling operational trajectories into executable, transferable, and inspectable procedures. Because evolution optimizes task outcomes rather than procedure safety, compromised experience can cause skill misevolution. Existing benchmarks measure current behavior or static artifacts but cannot attribute risk across authoring, retrieval, and later execution. To expose this lifecycle, we introduce SkillMisevo-Gym, a lifecycle-aware harness that versions skill state across agent frameworks, and SkillMisevo-Bench, a frozen design from malicious exposure to carryover tasks, with concept-aligned benign tasks and nine lifecycle metrics. We also introduce SafeEvolve, a wrapper that repairs unsafe content and governs subsequent reuse. Across 25 agent-method configurations, each covering 525 tasks in 25 episodes, all 21 evolved configurations author unsafe artifacts, while only fifteen lead to fresh-session harm. In the exposure sweep, three malicious tasks raise carryover ASR from 16.0% to 35.3%. Across representative skill evolution methods, SafeEvolve reduces unsafe retrieval and fresh-session harm by 26.7 and 17.3 percentage points, respectively, while mean benign utility changes by only 0.4 points. Together, persistent-adaptation safety must govern what updates write and what future executors reuse. Code is available at https://github.com/henrymao2004/misevolve.

## 一、论文的核心问题与整体含义（研究动机与背景）

- **核心问题**：自我改进型LLM代理（self-improving LLM agents）会将成功轨迹提炼为可复用的持久化技能（skill），但这一进化过程以**任务结果**而非**程序安全性**为优化目标。由此产生一个关键风险：一个“不安全的成功”（unsafe success）可以在其触发输入消失后，被固化为可跨会话、跨任务复用的稳定策略——即论文所称的**技能误进化（skill misevolution）**。
- **现有基准的缺陷**：已有的技能基准（如SkillsBench、SWE-Skills-Bench）测量任务成功率或技能质量，安全基准（如AgentHazard、MalSkillBench）只测试给定提示、环境或静态制品，均**无法将风险归因到“创作—检索—执行”的完整生命周期**。单一的成功率（ASR）无法区分“库是安全的”与“库不安全但未被检索到”这两种截然不同的状态。
- **整体含义**：持久化自适应（persistent adaptation）改变了AI安全边界——一次不安全的动作未必随会话结束而消失，而可能通过进化层转化为长期策略。因此，**安全治理必须贯穿“更新写入什么”与“未来执行者重用什么”两个环节**，而非只关注当前响应是否安全。

## 二、论文提出的方法论

1. **形式化定义**：设基础策略 π，每三个任务构成一个块 Q_k = (q_{k,1}, q_{k,2}, q_{k,3})，产生轨迹 T_k。进化方法 E 更新技能库：L_{k+1} = E(L_k, Q_k, T_k)。若E将不安全过程选择或泛化为库中技能，并在后续检索/执行中伴随更高的不安全行为，则构成一次“技能误进化”事件。

2. **SkillMisevo-Gym（生命周期感知测试平台）**：
   - 对技能库进行**版本化（versioned）**管理，将每次写入链接到源轨迹的diff。
   - **隔离状态**：每个任务运行在新沙箱、新会话、新workspace、新进程命名空间、新工具会话中，**只有情节范围内的技能库跨任务推进**。
   - 支持目标代理、进化方法、治理策略的可插拔扩展（定义了最小集成接口）。

3. **SkillMisevo-Bench（冻结基准）**：
   - 基于AgentHazard作为可执行验证基础，利用AHA（autorsearch）离线发现“恶意—良性”漏洞概念，再由构造器实例化为全新的 **M（恶意）/B（良性）/P（持久性）** 任务记录。
   - 每个情节顺序为：M³ BBB M³ BBB M³ BBB | BBB ，共21个任务（9个恶意学习任务、9个良性评估任务、3个干净会话持久性探针）；进化在每三任务块后执行。共25个情节、525次任务执行。
   - 定义了**九个生命周期指标**：BU、M-ASR、B-ASR、CU、UG、Stealth、URR、C-ASR、C-Util。

3. **SafeEvolve（方法无关的安全治理包装器）**：
   - **写时检查（Write-time）**：非阻塞的critic-deleter配对。critic定位可复用的不安全指令；deleter执行最小减法式删除（只删除不安全片段或缩窄过度泛化规则，**不允许添加检查、白名单、人工审批等新内容**）。修复版本仅在仍可加载且风险降低时替换原生候选。
   - **复用治理（Reuse-time）**：基于效用+谱系风险（lineage risk）排序检索结果；将有害结果归因到被检索的技能并写入其谱系；超过安全风险阈值或低效用阈值的技能被**退役（retire）**；容量淘汰按“效用−风险”排序。

## 六、论文的主要结论与发现

1. **技能误进化的普遍性**：所有21个进化配置均创作了不安全工件（author unsafe artifacts），19个检索到不安全技能，19个表现出污染（contamination），但只有15个导致新会话伤害（fresh-session harm）——展示出清晰的“创作→检索→执行”门控衰减。
2. **效用与风险可共存**：在15/21的进化设置中，BU高于对应No Evolution条件；C-Util在16/21中更高——即一个配置可以同时保留有用工作流和嵌入在其成功轨迹中的不安全捷径。不存在简单的效用—安全权衡。
3. **有限暴露即可播种风险**：仅**3个恶意任务**即可将携带ASR（carryover ASR）从16.0%提升到35.3%，继续增加到9个恶意任务可达到41.3%。
4. **早期暴露扩大污染窗口**：早期暴露产生40.7%的污染（Late为19.8%），即使最终携带ASR相似——说明安全性风险的传播范围与暴露时机密切相关。
5. **良性更新无法可靠擦除风险**：完全混合与分批调度下，携带ASR分别保持48.0%与46.0%——良性经验混入更新并不能消除已学习的危险捷径。
6. **进化方法×代理框架的交互决定门控位置**：EvoSkill在所有框架中穿越完整生命周期（C-ASR 25.3%–30.7%）；AutoSkill的C-ASR在14.7%（OpenClaw）到29.3%（Codex）间变化；SkillOpt在OpenClaw上创作高泛化危害工件但无携带危害。
7. **SafeEvolve的有效性**：在AutoSkill和EvoSkill上，将不安全检索率（URR）从35.33%降至8.67%，C-ASR从21.33%降至4.00%，平均良性效用仅变化0.4个百分点；但C-Util从53.33%降至40.67%——抑制混合有用行为与可转移风险的过程存在成本。

## 七、优点

1. **生命周期视角的开创性**：首次将“创作—检索—执行”三个门控分离度量，可定位风险在哪个环节被阻断，而非只报告最终行为。
2. **状态隔离设计严谨**：深入隔离对话、工作区、进程、工具会话与技能库，确保跨任务影响只能通过技能库传导——因果识别清晰。
3. **概念驱动的基准构建**：利用AHA自动发现可证伪的恶意—良性配对概念，并以严格的VCG（已验证概念集）而非原始prompt实例化任务，保证概念的机制多样性与可复制性。
4. **方法无关的安全治理**：SafeEvolve包装器不改变底层代理或进化算法，且使用“仅删除”约束防止治理自身引入新的不安全或不可验证的行为，设计精妙。
5. **对比基线与控制丰富**：不仅对比No Evolution和Raw，还对比Utility-only以分离“生命周期管理效应”与“安全证据效应”；三组件消融+组件本机验证（Table 6）使结论可信度高。
6. **数据集统计透明**：固定分母、缺失置零、冻结设置、预设阈值等处理减少实验自由度，增强可复制性。

## 八、不足与局限

1. **领域覆盖有限**：实验集中在编码和计算机使用任务（coding/computer-use），未覆盖记忆进化、策略进化、多模态自适应等更广泛的持久化机制。作者也承认这一点。
2. **单一骨干模型**：所有配置均使用MiniMax-M2.7，骨干模型变化对结论的影响未知。
3. **计算资源信息不完整**：未报告GPU型号/数量，无法评估复现的算力成本。
4. **短期部署视野**：每个情节只有25轮技能更新（6个进化块），未测试数周或数月自然发生的长期任务流对误进化累积的影响。
5. **SafeEvolve的效用代价**：虽然BU变化微小（约0.4点），但C-Util下降明显（约为12.7个百分点），说明治理确实抑制了一部分“有用但带风险”的可复用过程——论文承认这是一个剩余成本，但未提出更精细的权衡机制。
6. **潜在偏差风险**：AgentHazard作为上游任务源可能引入分类偏差；judge采用Gemini-3-Flash和Kimi-K2-0905，其判决质量直接决定指标可靠性，但论文未系统评估judge自身的一致性与错误率。
7. **攻击者模型局限**：假设攻击者不能直接写技能库或修改检索/进化环节，现实中更强能力的攻击者可能绕过这些限制。
