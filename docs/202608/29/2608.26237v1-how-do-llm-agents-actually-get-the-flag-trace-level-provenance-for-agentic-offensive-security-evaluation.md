## 摘要
夺旗（CTF）基准测试被广泛用于评估自主语言模型代理的进攻性安全能力。现有评估依赖于浅层的二元判断或聚合分数，忽视了代理通往旗帜的轨迹。因此，实际利用与直接暴露旗帜、记忆性回忆、外部查找、猜测及无根据的声明混为一谈，可能高估代理的网络安全能力。我们提出CTF-ABACUS，一种基于轨迹的代理审计框架，将每次运行重构为基于证据的解决档案。通过将代理行为分解为渗透测试阶段和分类技术，该框架识别利用发生在何处、旗帜首次出现在何处，以及恢复的旗帜是否得到所展示行为的支持。跨代理聚合解决档案可生成挑战签名，揭示成功是通过预期利用途径还是捷径路径实现的。我们将CTF-ABACUS应用于六个前沿及开源模型在240个挑战上的1,435次CTF尝试，在两种评判视角下产生2,870份解决档案。追踪验证的利用仅占各基准恢复旗帜的62%-87%，而捷径恢复遵循明显更浅的轨迹。这些发现将CTF评估从统计恢复的旗帜转变为验证所展示的利用，并为设计更好隔离进攻能力的基准提供了基础。

## 速览
**TLDR**：现有的夺旗基准在评估语言模型代理时多依赖最终结果，容易把直接暴露、背诵或猜测当作实际利用，从而夸大其攻防能力。我们提出痕迹审计框架，把代理行动分解为渗透阶段与不同技术，重建有证据支撑的解题过程，明确标记利用发生位置和旗帜的首次来源。在两百四十个挑战上对六个模型的千余次尝试进行审计，发现经痕迹验证的利用只占回收旗帜的六成到九成，其余多为捷径。这项研究推动评估从统计旗标数量转向验证真实利用，为设计更能分离真实攻防能力的测试基准奠定基础。 \

## Abstract
Capture-the-Flag (CTF) benchmarks are widely used to assess the offensive security capabilities of autonomous language-model agents. Evaluations rely on shallow binary judgments or aggregate scores, overlooking the agent's trajectory to the flag. Consequently actual exploitation is conflated with direct flag exposure, memorized recall, external lookup, guessing, and unsupported claims, potentially overstating the agent's cybersecurity capability. We introduce CTF-ABACUS, a trace-based agent auditing framework that reconstructs each run as an evidence-grounded solve profile. By decomposing agent actions into penetration-testing phases and categorical techniques, it identifies where exploitation occurs, where the flag first appears, and whether the recovered flag is supported by demonstrated behavior. Aggregating solve profiles across agents yields challenge signatures that reveal whether success was achieved via the intended exploit or via shortcut pathways. We apply CTF-ABACUS to 1,435 CTF attempts by six frontier and open-source models on 240 challenges, yielding 2,870 solve profiles under two judge lenses. Trace-verified exploits account for only 62-87% of recovered flags across benchmarks, while shortcut recoveries follow substantially shallower trajectories. These findings shift CTF evaluation from counting recovered flags to verifying demonstrated exploitation and provide a basis for designing benchmarks that better isolate the offensive capabilities.

- 随着自主语言模型代理在复杂进攻性安全任务中表现出色，CTF（夺旗赛）基准已成为评估这些代理安全能力的主流平台。

- 同一个正确的旗标可能来自完全不同的路径：真实利用漏洞、直接阅读暴露的旗标、回忆已见过的公开解决方案、检索外部write-up、猜测，甚至是在推理中无证据地断言。传统二元成功判定无法区分这些本质不同的行为，导致对代理实际网络能力的系统性高估。
- 此外，基准内容污染和记忆效应进一步放大了这一问题——代理可能凭借训练时见过的内容而非实际推理拿分。
- 该论文的深刻洞察在于：**评估不应只是问"代理是否拿到了旗标"，而应问"代理是如何拿到旗标的"**，答案从执行轨迹（execution trace）中才可获得。作者据此提出CTF-ABACUS框架，将审计焦点从最终输出转向完整行为证据链。

## 2. 论文提出的方法论（核心思想与技术细节）

**核心思路**：CTF-ABACUS将每次代理运行重构为"基于证据的解题档案"（evidence-grounded solve profile），通过追溯旗标首次出现的位置和前置行为，将真实利用与各类捷径分离。该框架的主要处理流程如下：

- **轨迹采集与线性化**：将D-CIPHER多代理架构中规划器与执行器子代理交错运行的轨迹，展平为按时间排序的步骤序列 $T=(e_1, ..., e_n)$，每个步骤 $e_i=(a_i, o_i)$ 由工具调用 $a_i$ 和观察窗口 $o_i$ 组成。仅做路由控制、不对目标产生操作的操作会被丢弃。
- **步骤标注**：每个步骤携带标签 $z_i=(\phi_i, \tau_i)$，其中 $\phi_i$ 是PTES渗透测试阶段（预参与、情报收集、威胁建模、漏洞分析、利用、后期利用、报告），$\tau_i$ 是来自分类学标准的具体技术类别（如Web用OWASP WSTG、二进制利用用CWE/CAPEC/MITRE ATT&CK、密码学与取证用NIST）。标签注册表是开放式的，新的操作可生成候选技术词条并经人工验证后补充。
- **旗标溯源**：确定性读取旗标首次出现位置 $f$（来源 $\sigma$）和正确提交 $s$；唯一需要推断的是"利用行为" $\xi$——第一个真正利用目标的步骤。在没有参考解决方案的情况下，$\xi$ 以"展示的深度"为锚定标准。
- **归属判定（旗标来源 π）**：依据旗标来源和前置行为划分：
  - **genuine-solve**：目标观察到的旗标出现在 $\xi$ 之后（真实利用）；
  - **undemonstrated exploit**：目标旗标出现但无前置利用行为；
  - **looked-up**：旗标来自外部来源；
  - **agent-reasoning**：旗标仅出现在推理中（需人工审查进一步分为derived/recalled/leaked/guessed/unclear）；
  - **unsolved**：未出现旗标。
- **双重独立审计**：两个不同家族的judge（Claude Opus 4.8和GPT 5.6 Sol）分别从动作和观察独立标注，避免单一模型偏见的引入。对重建档案进行盲审评分（保真度平均98.3/100），安全研究人员复评10%样本达成93.5%一致率。
- **挑战签名生成**：将多个代理在同一个挑战上的解题档案聚合为"挑战签名"，揭示该挑战的成功究竟依赖预期能力还是捷径。

## 6. 论文的主要结论与发现

- **真实的利用占比远低于表面成功率**：在1,056个被恢复的旗标中，仅约72.9%得到环境中执行行为的验证，10.9%为人工验证但在无执行观察下的推理推导，16.2%则完全缺乏支持证据。跨基准的轨迹验证利用占比仅62%—87%。
- **捷径恢复普遍存在**：直接旗标暴露（151例）远超记忆回忆或外部查找（17例），比率为8.9:1——大多数无支持恢复并非来自数据污染而是测试环境的构造问题。
- **分数换算与排名不稳定**：若采用"需执行验证"的标准，所有模型得分下降17.4%—22.6%；不同基准上的调整幅度差异显著（从CTFTiny的11.4%到InterCode的29.8%），基准层面的排名相关性范围从HTB的-0.06到Cybench的0.88——基准身份解释了运行级变异中 $\eta^2=0.0369$（约为随机预期的17倍），而模型身份的解释力可以忽略不计。
- **轨迹几何差异明显**：真实利用型恢复展现出PTES阶段的稳步上升（单调性或适度zigzag），而捷径恢复轨迹扁平、单薄，缺乏深层次的漏洞分析阶段。利用执行率在两类恢复中分别为88.7%与41.6%，报告阶段出现率则相反（1.8% vs 24.8%）。
- **挑战有效性是"挑战×求解者"的交互属性**：196个有恢复的挑战中，严格标准下仅46.4%被完全支持、40.3%混合、13.3%不支持；即使计入人工验证的推导，混合类仍占33.2%。同一挑战在不同模型下可能展现完全不同的证据质量。
- **无法用廉价替代物区分真实与捷径**：简单的关键词检测器、命令级摘要仅达到0.28的F1，最強单特征AUC也只有0.617，无法产生有效区分——需要完整的序列重建和上下文关系。

## 7. 优点

- **问题定义精准且重要**：首次从"旗标来源"这一明确的证据维度定义并量化了CTF评估中长期存在的混淆问题，直击基准有效性这一根本性议题。
- **方法论追求严谨的证据链构建**：不依赖单一判官，"动作+真实输出"的证据珠设计、双重独立judge审计、盲审评分、人工抽检——多层验证机制使归属判定的可信度显著提高。
- **构建了从单个轨迹到基准级分析的完整分析谱系**：从solve profile（单次运行）到challenge signature（跨模型聚合），再到基准质量四维度评估（技术广度、轨迹深度、单调性、真实利用比例），形成了层次化的评估工具。
- **实验规模大且覆盖面广**：240个挑战、6个模型、4个基准、1,435次运行，在同类研究中最具广度；跨基准的验证还揭示了评测环境对行为模式的系统影响。
- **论述中兼具"解决性问题"和"否证性洞察"**：不仅展示了一套可行的审计框架，还严谨地否证了"可以用简单特征替代完整轨迹重建"的可能性，为方法的必要性提供了实证依据。
- **伦理与安全考量**：通过将评估焦点从"能否黑入"转向"如何黑入"的记录和审计层面，在推动安全能力研究的同时也为模型能力的可信度量提供了基础。

## 8. 不足与局限

- **推理来源旗标判定仍需人工介入**：127个"仅推理出现"的旗标无法完全自动化判定，需要人工审查——这意味着框架在推理型路径上还未能做到全自动，扩展到大规模评估时成本较高。
- **"利用行为ξ"的推断缺乏参考解决方案**：在不依赖参考答案的前提下，ξ依赖于"展示的深度"的判定标准，对于简单或环境构造异常的挑战（如旗标暴露在明显位置），真实利用与捷径之间的边界可能模糊，作者也承认这一歧义无法完全消除。
- **模型版本与实际环境的时效性约束**：论文所述模型与实际环境版本相关内容均为2026年的前沿配置，与当前公开模型版本存在差异，且可能存在评测模型与judge模型重叠的问题（如Claude同时是求解者和审计者）。
- **未分析求解架构选择的影响**：所有评估均基于D-CIPHER多代理框架，未验证不同代理架构（如单代理、ReAct模式）在溯源结果上是否存在差异——框架的普适性尚未被直接证实。
- **缺乏消融实验**：未评估标签体系的粒度、judge数量减少一个、或只使用单一审计路径时判定结果的稳健性变化。
- **成本与可复现性未充分讨论**：虽然提到每尝试$3上限，但完整的审计流程（包括双judge标注和人工审查）的总成本未被评估，这可能影响他人复现该框架的意愿；亦未提供开源代码与数据集的详细信息。
- **无算力汇报**：缺少训练和推理所需的GPU型号、数量、耗时等信息，降低了结果的可复现性和可比性。
