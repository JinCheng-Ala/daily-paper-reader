## 摘要
长时程智能体运行会产生既能改进当前运行又能促进未来工作的经验。大多数自我改进方法仅在执行结束后才处理这些经验，因此它们无法调整正在进行的运行，也无法立即应用并验证从中获得的经验教训。我们认为，自我改进应改为实时的，既利用涌现的经验来调整当前运行，又更新持久的执行框架。现有的智能体架构并不能完全支持这一目标。单智能体自我纠错将任务执行与轨迹评估结合在同一上下文中，而子智能体委派虽分离了执行，但通常无法调整正在运行的子智能体。我们提出了PILOT，一个监督者-工作者的执行框架，通过两种耦合机制实现实时自我改进：（1）实时引导，允许独立的监督者在执行期间调整或中止正在运行的工作者；（2）实时自我进化，将在执行过程中揭示的程序和失败模式提炼为可复用的技能和记忆。在两个冻结骨干模型和三个基准测试中，PILOT在六个配置中的五个中排名第一。在Terminal-Bench 2.0上，PILOT比对应的执行框架最高高出9.8个百分点。在自我改进场景中，PILOT在GLM-5.1上提升14.6个百分点，在Kimi-K2.6上提升12.4个百分点。平均输出令牌数分别下降42.9%和47.4%，而每百万输出令牌的成功评估次数分别提升110.3%和134.0%。

## Abstract
Long-horizon agent runs generate experience that can improve both the current run and future work. Most self-improvement methods process this experience only after execution ends, so they cannot redirect the active run or immediately apply and validate lessons learned from it. We argue that self-improvement should instead be live, using emerging experience both to redirect the active run and to update the persistent harness. Existing agent architectures do not fully support this goal. Single-agent self-correction combines task execution and trajectory assessment within one context, while subagent delegation separates execution but typically cannot redirect an active subagent. We present PILOT, a supervisor-worker harness for live self-improvement through two coupled mechanisms: (1) live steering lets a separate supervisor redirect or abort the active worker during execution; and (2) live self-evolution distils procedures and failure modes revealed during execution into reusable skills and memory. Across two frozen backbones and three benchmarks, PILOT ranks first in five of six configurations. On Terminal-Bench 2.0, PILOT outperforms counterpart harnesses by up to 9.8 percentage points. In the self-improvement setting, PILOT gains 14.6 points with GLM-5.1 and 12.4 points with Kimi-K2.6. Mean output tokens fall by 42.9% and 47.4%, while successful evaluations per million output tokens rise by 110.3% and 134.0%, respectively.

## 1. 核心问题与整体含义

- **研究背景**：长时程（long-horizon）智能体在环境中执行复杂任务时会产生大量经验。成功的轨迹蕴含可复用的程序性知识，失败的轨迹则暴露了失败模式。这类经验理论上既能改进当前正在执行的运行，也能改进未来的运行。
- **现状痛点**：现有自我改进方法（如反思、评判式评估、自我进化框架）大多属于**事后处理（post-hoc）**——它们只在一次完整执行结束后才处理经验教训。其数学本质是：学习到的知识无法影响产出该知识的运行，也无法通过该运行立即验证其有效性，只能在后续独立运行中测试。
- **核心论点**：自我改进应当是**实时的（live）**——既利用涌现中的经验重定向当前正在进行的运行，又同时更新持久化的 harness（执行框架）以惠及后续运行。
- **架构鸿沟**：现有架构无法同时支持“实时纠偏”和“独立的自我改进角色”——单智能体自纠错在同一上下文中既要执行又要自我诊断，注意力被切割；子智能体委派虽然分离了执行与主控，但主控通常只能在子智能体结束后收到结果摘要，无法在运行中对子智能体进行实时重定向。
- **论文含义**：提出 PILOT，一个监督者-工作者（supervisor-worker）架构，首次实现**实时自我改进闭环**：在执行过程中同时完成纠偏、知识沉淀与后续复用。

## 2. 方法论

### 2.1 核心思想

PILOT 将自我改进视为一个**闭环**而非事后更新。通过将“任务执行”与“自我改进”两个角色分离，形成两个耦合机制：

1. **实时引导（Live Steering）**：独立的监督者（supervisor）在执行过程中实时观察工作者的轨迹事件，并在必要时重定向或中止工作者。
2. **实时自我进化（Live Self-Evolution）**：监督者将执行过程中发现的成功流程、项目惯例和失败模式实时蒸馏为可复用的技能（skills）与记忆（memory），持续更新持久化 harness。

### 2.2 角色与状态设计

- **模型参数 θ 冻结**：所有自我改进仅发生在 harness 层（技能库 K 与记忆 M），不更新模型权重。
- **工作者（Worker）**：负责任务执行，拥有隔离上下文（isolated context），承载执行细节、死胡同、冗长工具输出。
- **监督者（Supervisor）**：拥有独立上下文，专注于目标、近期事件、偏离迹象和失败模式；仅在需要诊断时读取工作者轨迹的相关部分，避免上下文污染。

### 2.3 双向实时通道（Two-way Live Channel）

每个工作者会话与监督者之间建立双向实时通道，支持三类工作者→监督者事件和两类监督者→工作者动作：

| 方向 | 名称 | 机制 |
|------|------|------|
| 工作者→监督者 | **Notification** | 工作者主动报告进展/中间结果/风险，发完后继续执行 |
| 工作者→监督者 | **Question** | 工作者需要监督者输入时暂停等待回复 |
| 工作者→监督者 | **Result** | 运行时自动在工作者结束时将最终结果和工作者索引传给监督者 |
| 监督者→工作者 | **Steer** | 监督者发现偏离时，检查相关轨迹并为工作者下一回合排队指导（当前回合先完成） |
| 监督者→工作者 | **Abort** | 继续当前工作者会话已无用时，监督者中断该工作者 |

### 2.4 实时自我进化流程

- 监督者在实时轨迹中发现可复用的成功流程或需避免的失败模式时，立即写入技能库 K 或记忆 M，将 harness 从 H 更新为 H'。
- **更新后新生成的任何 worker 会话都会加载 H'**，无论该会话属于当前 episode 还是后续 episode，从而形成“经验→沉淀→复用”的闭环。

### 2.5 实现细节

- PILOT 作为 Pi 编码智能体运行时的扩展实现；监督者与工作者均为独立 agent 会话，在进程内生成。
- 实验采用现实场景：**同一冻结模型同时充当监督者和工作者**，从而隔离架构效果与模型能力差异。

- **GLM-5.1**
- **Kimi-K2.6**

同一骨干同时充当监督者和工作者，控制模型能力变量，从而隔离 harness 架构的影响。

### 3.3 对比基线

- **Terminal-Bench 2.0**：Pi、OpenCode、Terminus-2、Hermes

### 3.4 两种评估设置

1. **一次性（One-shot）设置**：每任务从全新 harness 状态出发，评估实时引导能否在运行中保持任务不偏离。
2. **自我改进（Self-improvement）设置**：将 Terminal-Bench 2.0 组织为 20 轮迭代（iteration），每轮完整跑一遍全部任务。迭代 i 的所有任务共享同一 harness 状态 H_i；执行过程中可用经验更新技能和记忆，但**不使用任何评测信号**；迭代结束后，仅保留来自成功运行的更新进入 H_{i+1}，失败运行的更新被丢弃。

- 每配置运行两次，报告平均通过率（pass rate）。

## 6. 主要结论与发现

### 6.1 性能结论

- PILOT 在 6 个配置中 5 个排名第一；Terminal-Bench 2.0 上，GLM-5.1 达 71.9%（高出最强 baseline 5.0 点），Kimi-K2.6 达 71.3%（高出 4.4 点），两个骨干平均 71.6% 高于 Pi 的 66.3%，**最高超出 9.8 个百分点**。
- SWE-bench Pro 上 PILOT 平均 59.9%，高出最强 baseline Pi（55.5%）4.4 点。
- 硬任务（Hard）上增益最大，两个骨干均达 55.0%，明显优于 baseline。

### 6.2 自改进结论

- GLM-5.1 从迭代 0 的 66.3% 提升至最优 80.9%（**+14.6 点**）；Kimi-K2.6 从 68.5% 提升至 80.9%（**+12.4 点**）。
- 技能库从 62→83（GLM）和 50→81（Kimi），持续增长。
- 平均输出 token 从 28.5K→16.3K（-42.9%，GLM）和 41.9K→22.1K（-47.4%，Kimi）。
- **每百万输出 token 的成功评估数分别提升 110.3% 和 134.0%**——既更省 token 又更成功。
- 对比实验表明：PILOT 自改进增益（+14.6 点）远超 Pi（+2.3 点）和 OpenCode（+7.9 点），证明其不仅积累了更多经验，而且能更有效地复用经验。

### 6.3 实时引导定位结论

- 人工轨迹分析表明：实时引导对 Easy 任务无帮助（0%），主要贡献集中在 Hard 任务（GLM 6.1%、Kimi 19.7% 的成功运行被判定为受实时引导帮助），说明越长的任务链条越需要实时纠偏。

## 7. 优点

- **范式创新性强**：首次明确提出“实时自我改进”概念并将其实现为闭环系统，突破了事后学习的局限。
- **架构设计合理**：监督者-工作者分离，执行细节留在工作者上下文，监督者上下文保持聚焦。解决了单智能体自纠错的注意力分裂和子智能体委派无法中途干预的两个结构性缺陷。
- **双机制耦合**：实时引导（纠正当前运行）与实时自我进化（沉淀持久知识）在同一闭环内配合，前者保证当前轨迹被回收，后者保证经验通过当前运行获得即时验证并惠及未来。
- **实验设计严谨**：冻结骨干控制模型变量；同一模型任监督者/工作者隔离能力差；自改进设置中禁止使用评测信号构造更新；协议对 baseline 一视同仁。
- **效率提升显著**：不仅是性能提升，还大幅减少 token 消耗（约一半），每百万 token 成功率翻倍以上，实用价值明显。
- **分析深入**：按难度分解增益、技能增长、token 效率、人工轨迹标注等多维度分析，验证了机制的有效性，并提供了两个代表性案例作为直观证据。

## 8. 不足与局限

- **计算资源代价高昂**：迭代式自改进需反复多次跑全量任务，论文明确承认成本限制了评估范围，且未报告具体 GPU/算力开销，不利于复现与成本估算。
- **评估覆盖有限**：仅 3 个基准、2 个开源骨干模型，未覆盖闭源模型（如 GPT/Claude 系列）和更多任务领域，结论外部效度有限。
- **监督者与工作者同骨干**：论文自身指出异构配对（不同模型或不同规格）未被探索，例如使用更强大的监督者是否带来更大收益是开放问题。
- **统计可靠性不足**：每配置仅运行两次且未报告方差或置信区间，难以评估结果稳定性与显著性。
