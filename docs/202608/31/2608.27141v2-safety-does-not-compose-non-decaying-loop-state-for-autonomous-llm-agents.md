## 摘要
大型语言模型代理日益被部署为自主循环系统。从一个人类目标出发，这样的系统反复发现工作、规划、执行工具调用、验证结果，并在多次无人值守的迭代中持久化状态。然而，广泛使用的代理安全防护是针对单一轨迹定义的，其安全状态在下一个轨迹开始时被重新初始化。我们表明，这是一个组合失败而非实现细节问题。我们的核心结果是分离性：针对一种证据碎片化分布于多次迭代的攻击，任何轨迹范围监控器的真阳性率等于其假阳性率，无论其表达能力如何，因为它需要的证据永远不会出现在其可见窗口中；而保留跨迭代状态的监控器则能完美区分两者。我们进一步表明，携带几何衰减风险评分的明显修复方案是不足够的，因为耐心的对手必须等待的冷却期是一个不随范围N增长的常数。随后，我们提出LoopHarness，它在循环级别恢复持久、非衰减的安全状态。在中介提交和仲裁器检测下限δ_M下，它将未经授权的不可逆操作的预期数量限制为B+m-1+m/δ_M，这是N中的常数，其中B+m-1项由无模型规则决定，因此即便验证器完全串通也能存活。我们给出了在原生Agent-SafetyBench任务上的完整评估协议，包括配对的干净与攻击情节、一个仅跨迭代存在决定性证据的外层状态攻击套件、逐模块消融实验，以及自适应白盒红队测试。

## Abstract
Large language model agents are increasingly deployed as autonomous loops. Starting from one human goal, such a system repeatedly discovers work, plans, executes tool calls, verifies outcomes and persists state across many unattended iterations. The agent safeguards in wide use, however, are defined over a single trajectory, and their safety state is re-initialized when the next trajectory begins. We show that this is a failure of composition rather than an implementation detail. Our central result is a separation: against an attack whose evidence is fragmented across several iterations, every trajectory-scoped monitor has a true-positive rate equal to its false-positive rate, however expressive it is, because the evidence it would need never appears in the window it sees, whereas a monitor retaining cross-iteration state separates the two perfectly. We further show that the obvious repair of carrying a geometrically decaying risk score is insufficient, because the cooling-off period a patient adversary must wait is a constant that does not grow with the horizon $N$. We then present LoopHarness, which restores a persistent, non-decaying safety state at the loop level. Under mediated commits and an arbiter detection floor $δ_M$, it bounds the expected number of unauthorized irreversible actions by $B+m-1+m/δ_M$, a constant in $N$, of which the $B+m-1$ term is decided by a model-free rule and therefore survives a fully colluding verifier. We give a complete evaluation protocol on native Agent-SafetyBench tasks with paired clean and attacked episodes, an outer-state attack suite whose decisive evidence exists only across iterations, per-module ablations, and an adaptive white-box red team.

## 一、论文的核心问题与整体含义（研究动机和背景）

- **背景**：大语言模型（LLM）代理正在从单轮工具调用走向无人值守的自主循环（autonomous loop）。在一个人类目标的驱动下，系统反复经历“发现问题→规划→执行工具调用→验证结果→持久化状态→自行决定是否继续”的迭代过程。在软件维护、运维、研究辅助、后台财务等场景中，代理携带的持久状态和不可逆操作（如转账、删除记录）构成了新的攻击面。
- **核心问题**：现有代理安全机制（输入消毒、逐调用分类、权限上限、能力令牌、轨迹内回滚等）都是**按单条轨迹（trajectory）定义**的，其安全状态在每个轨迹开始时被重新初始化。这一“逐轨迹重置”（Per-trajectory reset）特性导致安全状态无法跨迭代累积，从而构成了**安全性不可组合（Safety Does Not Compose）**的失败——防御者的安全状态按构造每个轨迹重置，而攻击者的进展却能通过循环所保留的持久渠道（如记忆库）不断累积。
- **关键洞察**：攻击者可以将攻击证据碎片化（fragmented）到多个迭代中，使每次迭代都低于任何单轨迹阈值，从而对任意强大的轨迹级监控器完全隐形。作者证明这是一个结构性缺陷，而非实现细节。

## 二、论文提出的方法论：核心思想、关键技术细节

### 2.1 核心思想

- **形式化刻画**：将自主循环建模为带显式安全状态的受控过程。定义轨迹级监控器（trajectory-scoped monitor）为决策仅取决于当前迭代内部视图的监控器。定义 s-碎片化攻击为：攻击者在 s 次迭代中的每次贡献与良性贡献分布相同，而未经授权能力仅在全部 s 个片段共同出现在持久状态中后才触发。
- **主要理论结果**：
  - **Proposition 2（碎片化分离）**：对任意 s≥2 的碎片化攻击和任意轨迹级监控器 M，M 在攻击迭代上的告警概率等于其良性迭代上的告警概率，即 TPR = FPR，与监控器表达能力无关；而读取跨迭代状态并在累积片段联合实例化能力时告警的监控器可达到 TPR=1、FPR=0。
  - **Proposition 3（冷却期击败几何衰减）**：若风险累积采用固定折扣 γ∈(0,1) 且无闩锁（latch），门禁重新开启所需的冷却步数 k⋆ = ⌊log(ρ/θ)/log(1/γ)⌋ + 1 是一个不随 N 增长的常数；耐心攻击者只需支付一次常数等待时间。只有非衰减、带结构标志闩锁的累积才能让被动等待永远无法重新开启门禁。
  - **Theorem 5（水平无关界限）**：在调解提交（A1：最多 m 次提交）、仲裁器检测下限 δ_M（A2）和单调提交计数器（A3）假设下，未经授权不可逆操作的期望数满足 E[U_1:N] ≤ B+m−1+m/δ_M，这是与 N 无关的常数。
  - **Proposition 6（模型无关部分及残差类）**：授权代理（authorization proxy）由记录轨迹字段上的规则决定，不依赖模型输出，因此 B+m−1 项在验证器完全串通时仍然成立；只有 m/δ_M 项依赖检查器。

### 2.2 LoopHarness 五个持久组件

- **IPM（准入与来源监控）**：唯一新工作进入循环的入口，执行默认拒绝的范围检查、来源信任核对、重入检查、原子授权核验、跨事件谱系可委托性检查，以及针对不可信通道的注入模式检查。每个条目给出连续“准入先验”，仅不可信条目的值作为攻击风险进入 XRC。
- **XRC（跨迭代风险累积器）**：每次迭代恰好一次，将本轮最大真实攻击风险 r_i 与迭代全部标志并入：
  - Ξ_i = max(r_i, γ_i Ξ_{i−1})，γ_i 设为 1（若循环结构标志已触发）否则 γ↓∈(0,1)。
  - 仅规则可判定的循环结构标志（如作用域扩张、被拒绝工作重入、能力升级、记忆篡改等）会使折扣闩锁；单纯高连续风险分数不会。该设计确保普通高影响工作或验证器不确定性不会拉低后续干净迭代的安全水平。
- **MIG（记忆完整性守卫）**：采用追加日志 + 链式 HMAC 标签（类似哈希链），配合检查点认证日志摘要、长度和管理者计数器。实施单调信任写入门、重新水合校验、召回策略（只回读可信后缀并排除逐迭代摘要），以阻断自哺式记忆投毒。
- **ASA（对抗鲁棒停止仲裁器）**：结合无模型确定性门、去相关检查器（每迭代至多一次模型调用，高级角色必须不同于写入模型）、窗口化分歧统计量；任何检测都会在阶段 6 停止循环。仅被接受的迭代写入记忆。
- **CRG（复合风险主管）**：将 Ξ 映射为两类强制执行和一个停止规则——硬预算 B 管风险记账提交、B_adv 管高级验证、能力上限为 Ξ 的分段阶梯函数（仅当 Ξ 下降才放松）、任务合同（风险清除阈值 θ_w、完成上限）以及 K 连续未完成提交时强制停止/升级。记忆回滚只恢复日志内容，不重新加载主管计数器。

## 六、论文的主要结论与发现

- **分离性成立**：轨迹级监控器面对碎片化攻击时 TPR 等于 FPR，无法以任何容量区分攻击与良性流量；保留跨迭代状态的监控器可完美分离。
- **几何衰减不足**：冷却期是常数，不随范围 N 增长；被动等待即可重开风险门禁。非衰减闩锁（Equation 1）使被动等待永远无法重开。
- **LoopHarness 有效**：完整配置 B4 将 Track B 平均 ASR 从 B0–B3 的 88.4%–97.6% 降至 0.1%，CleanGC 保持 96.9%；Track A 在 N=5/10/20 下始终为 0% ASR，而 B1/B1.5 在 N=10 后增至 6.2%。
- **消融验证依赖**：去除对应组件后 ASR 上升 96.0–97.5 个百分点；A-noGov 也增加了 A14 ASR（揭示 XRC 与 CRG 的依赖）。
- **模型无关界限**：B+m−1 项在验证器完全串通下依然成立（A-collude 下总体 ASR 仍 0.1%）。
- **可用性代价**：完整配置存在 15.7% 欠停率；仅闩锁的拒绝服务攻击可使 FullGC 降为 0%，提示需要显式、经认证的清除转换。

## 七、优点

- **理论贡献扎实**：通过 Proposition 2 和 3 给出不依赖具体模型能力的通用分离结果，明确了“安全性不组合”的结构本质；Bound 有清晰的机制分工（预算 vs. 机会）。
- **机制设计分层清晰**：将攻击证据、动作影响、验证器犹豫等信号严格分离，只让真实攻击证据进入持久风险值，避免误伤正常高影响工作或模型不确定性。
- **工程完整性**：提出五个可组合的持久组件，覆盖准入、记忆、仲裁、风险累积、预算治理；明确给出 Phase 顺序、结构标志集合、工具层级规则等实现细节。
- **评估协议规范**：采用配对孪生、冻结清单、dev/ood 分离、bootstrap 检验、防指标作弊的前沿指标，并披露评估器标签不出现在任何运行时提示中。
- **可复现性强**：附录提供完整证明、算法伪代码、配置表、攻击契约、回归测试说明，承诺释放源码和指标实现。

## 八、不足与局限

- **评估覆盖有限**：A1–A5 未重跑，仅作为编号继承；N 最大只有 20，不足以完全验证长期自主运行中复合风险随更大的 N 的行为。Agent-SafetyBench 单任务模拟器的真实性也受限，发现馈送是可调度队列而非竞争性队列，低估了 IPM 的实际准入压力。
- **单一横向设置**：只用一套模型角色、一个执行种子和温度 0；未做多模型/多种子复制。虽然这样保证确定性，但可能忽略模型族差异对去相关验证器效果的影响；A-collude 的 CleanGC 从 96.9% 降至 92.9% 也提示相关性成本。
- **假设依赖**：理论部分依赖 Assumption (A2) 的均匀检测下限 δ_M，这是唯一的经验输入；红队测试无法为任意历史建立 δ_M，只能探测。A3（单调计数器）依赖实现不变性，可能被缓存重放或状态恢复打破。
- **可用性与安全性张力**：完整配置的 15.7% 欠停率、仅闩锁攻击导致的 0% FullGC，说明没有明确、经认证的清除转换（clearance）策略，使用闭环可能导致持续拒绝服务；论文也承认这一点。
- **多智能体与部署边界**：结论基于单智能体循环；多智能体场景（被委托子代理构成重置实体）被列为未来工作。论文未给出部署级 N⋆ 估计，也未处理升级通道无人值守导致的“安全机制变成可用性故障”的风险。
