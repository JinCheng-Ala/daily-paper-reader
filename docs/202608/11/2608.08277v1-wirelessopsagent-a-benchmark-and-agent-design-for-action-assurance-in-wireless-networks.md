## 摘要
大型语言模型（LLM）智能体正逐渐成为自主无线网络操作的规划者。然而，如果在执行时支持遥测数据过时或不一致，即使在提案阶段答案正确的任务也可能在执行时变得不安全。现有基准主要从固定观测中评估任务解决能力，而未测试执行时的支持检查。我们引入了WirelessOptBench，一个用于无线操作中动作保障的基准。它将无线任务转化为带有受控遥测故障和动作约束的执行状态决策片段。我们进一步开发了WirelessOpsAgent，它在执行前基于当前证据对候选动作进行验证，并修复可恢复的支持失败。在三个骨干评估中，每个包含600个片段，WirelessOpsAgent实现了高达0.983的精确动作准确率。在Claude Sonnet 4.6上，与最安全的基线相比，不安全应用率从82.2%降至10.3%。我们在https://anonymous.4open.science/r/wirelessopsbench-artifact-D969/ 公开了WirelessOptBench。

## Abstract
Large language model (LLM) agents are emerging as planners for autonomous wireless network operations. Yet a task answer that is correct at proposal time can still be unsafe at execution time if supporting telemetry is stale or inconsistent. Existing benchmarks mainly evaluate task solving from fixed observations and leave support checking at execution time untested. We introduce WirelessOptBench, a benchmark for action assurance in wireless operations. It turns wireless tasks into execution state decision episodes with controlled telemetry faults and action constraints. We further develop WirelessOpsAgent, which grounds candidate actions in current evidence and repairs recoverable support failures before execution. Across three backbone evaluations with 600 episodes each, WirelessOpsAgent achieves up to 0.983 Exact Action Accuracy. On Claude Sonnet 4.6, the Unsafe APPLY Rate decreases from 82.2% to 10.3% relative to the safest baseline. We make WirelessOptBench available at https://anonymous.4open.science/r/wirelessopsbench-artifact-D969/.

## 1. 论文的核心问题与整体含义（研究动机和背景）

- **核心问题**：现有LLM智能体在无线网络自主操作中缺乏“执行时动作保障”。一个在提案阶段正确的任务答案，如果在执行时支撑其决策的遥测数据已过期、不一致或不可用，就可能导致不安全操作。
- **研究空白**：当前无线网络LLM基准（如WirelessBench、NetConfEval、TeleLogs等）主要评估“任务求解”——即从固定观测中推导正确的答案或计划，而**未测试“执行边界”**——即任务与候选决策保持固定、但支撑观测发生变化时，智能体能否正确判断动作是否仍可执行。
- **核心洞察**：动作正确性（Action Correctness）≠ 动作充分支持性（Action Assurance）。前者只问“决策是否正确”，后者还须回答“当前证据是否支持执行”。
- **核心概念界定**：论文明确提出“动作保障（Action Assurance）”概念，即在执行前检查提议动作是否仍由可接受的网络状态观测所支撑。新鲜度、一致性、覆盖率和可用性共同决定一个先前合理的决策在执行时是否仍然可采纳。
- **整体意义**：填补了无线网络LLM智能体从“任务求解”到“执行授权”之间的安全鸿沟，为可审计、可信赖的自主无线网络操作奠定基础。

## 2. 论文提出的方法论：核心思想、关键技术细节、公式或算法流程

### 2.1 WirelessOptBench：动作保障基准

将无线任务转化为“执行状态决策片段（execution state decision episodes）”，每个片段包含：

- **固定任务与参考答案**（继承自WirelessBench，保证名义答案不变）
- **证据图（Evidence Graph）**：观测台账，暴露值、模式、单位、来源、事件时间、摄入时间、新鲜度限制、父依赖
- **执行契约（Execution Contract）**：指定执行前必须满足的字段与网络约束（如容量、QoS、预算）
- **压力实现（Stress Realization）**：注入五类受控故障：schema/unit（模式/单位）、freshness/order（新鲜度/顺序）、availability/brownout（可用性/调暗）、conflict/provenance（冲突/溯源）、mixed（混合）
- **规则参考动作**：四种动作——APPLY、HOLD、RETRY、ESCALATE（另设ABSTAIN作为预测选项但非参考动作）

### 2.2 无线执行模型（关键公式）

- SINR计算：$\gamma_u(t) = \frac{P_b h_{u,b}(t)}{N_0 + \sum_{j \neq b} P_j h_{u,j}(t)}$
- 可达速率：$r_u(t) = W_u(t) \log_2(1 + \gamma_u(t))$
- 切片约束：$\sum_u W_u(t) \leq W$ 且 $r_u(t) \geq r_u^{\min}$
- 切换条件：$\text{RSRP}_{u,j}(\tau) - \text{RSRP}_{u,b}(\tau) \geq H, \tau \in [t-T, t]$
- 新鲜度检查：$\Delta_k(t) = t - t_k \leq \delta_k$（派生值继承其输入中最大年龄）

### 2.3 WirelessOpsAgent：动作保障智能体

**四阶段闭环架构**：

1. **决策链接证据接地（Decision-Linked Evidence Grounding）**：将观测绑定到不可变账本，维护原始状态→规范化状态→决策状态三层视图，从原始观测到候选动作构建证据图，避免规范化隐藏来源，防止派生值误判为新鲜。

2. **类型化完整性诊断（Typed Integrity Diagnosis）**：对每个关键字段k执行五项显式检查（公式6）：
   - `Valid(k,t) = SchemaOK(k) ∧ UnitOK(k) ∧ SourceOK(k,t) ∧ Fresh(k,t) ∧ ConflictFree(k,t)`
   - 产生类型化违规（而非单一异常评分），区分可修复与不可修复。

3. **依赖范围的有界恢复（Dependency-Scoped Bounded Recovery）**：
   - 令 $D_t = B_t \cup \text{Desc}_{G_t}(B_t)$（仅修复失败字段及其证据图后代）
   - 接受条件（公式8）：$\text{Accept}(x') = \text{Supported}_t \land \bigwedge_{k \in D_t} \text{Valid}(k, t+1) \land [V(d') \geq V(d_t)]$
   - 支持别名归一化、兼容单位转换、派生值重算、有界重试；拒绝用陈旧/冲突/记忆状态覆盖新证据；记忆被视为不可信来源，需通过同样的完整检查。

4. **风险感知授权与可重放记录（Risk-Aware Authorization and Replayable Records）**：
   - 条件：`Ready_t = FieldsValid_t ∧ ConstraintsPass_t ∧ RecordComplete_t`
   - 有序动作策略（公式9）：Ready→APPLY；歧义/冲突→ESCALATE；可重试→RETRY；证据未新→HOLD；否则→ABSTAIN
   - 生成授权记录：含来源、接受修复、未解析风险、状态版本等，供事后回放审计。

### 2.4 基准的公平性设计

- 隐藏真实参考动作和压力标识，不向模型暴露oracle
- 200个APPLY硬负例 + 400个阻塞案例，避免“总是应用”或“总是阻塞”被奖励

- 确定性筛选：从7,680个候选中保留600个，无开发/最终锚重叠，标签分布为200 APPLY、100 HOLD、100 RETRY、200 ESCALATE

## 6. 论文的主要结论与发现

1. **精确动作准确率**：WirelessOpsAgent在三个骨架上达到0.972-0.983，而最强基线的上限仅为0.707，提升幅度显著。
2. **不安全APPLY率大幅下降**：GPT-5.4-mini降至7.8%、Qwen3-8B降至17.2%、Claude Sonnet 4.6降至10.3%；在Claude上相对于最安全基线降低了71.9个百分点（从82.2%降至10.3%）。
3. **安全进展未被牺牲**：Safe APPLY Recall在三个骨架上分别提升至72.5%、48.0%和66.0%，远超最佳基线的25.5%、22.0%和17.0%；避免了“通过泛阻塞提高安全性”的陷阱。
4. **恢复前后对比**：修复后所有骨干的假阳性APPLY决策在400个阻塞片段上降为零（FPR从85.5%-92.2%→0%），APPLY召回率仍保持96.0%-99.5%。
5. **条件特异性路由**：新鲜度/顺序故障→57%→HOLD；可用性/调暗→44-63%→RETRY；冲突/溯源→66-67%→ESCALATE。显示出治理器能将不同故障映射到不同操作响应。
6. **消融归因**：完整性监视器和动作治理器是安全的主路径（移除后Macro F1从0.972降至0.22，不安全率从0.078升至0.69）；实用程序修复对保留安全进展至关重要（无修复时Safe APPLY Recall从0.725降至0.245）；schema/unit归一化移除使不安全执行翻倍（0.078→0.157）。
7. **单元级普适性**：在45个骨干-任务-条件单元格中，40个超过最强基线、5个持平、无一为负，说明效果不是由单任务族或单骨干驱动。
8. **零不安全覆盖**：所有变体在所有场景保持1.000的干净字段保持率，零不安全覆盖，证明恢复是范围限定的而非泛化重写。

## 7. 优点：方法与实验设计的亮点

- **概念创新**：清晰界定了“任务求解正确性”与“执行保障”的边界，并将动作保障作为独立评估维度引入无线网络LLM智能体评估，填补重要研究空白。
- **基准设计严格**：通过参照标签固定、证据变化、隐藏oracle的方式，精确隔离变量；600个片段的标签分布在200/100/100/200之间，既包含APPLY硬负例也包含阻塞支撑案例，防止了“总是应用”或“总是阻塞”的平凡策略获奖。
- **可审计性**：可重放的授权记录允许事后重建决策原因，双重检查器（oracle与公开视图证书检查器）确保评分器与基准规范的一致性。
- **工程化恢复机制**：依赖范围限定的修复操作避免了对整个响应的宽泛重写，消除了Self-Refine、CRITIC等通用方法的固有缺陷。
- **风险评估细节**：有序策略将故障类型与操作响应（HOLD/RETRY/ESCALATE）匹配，而非单一阻塞；类型化完整性诊断设计精细（区分schema、单位、来源、新鲜度、冲突五类）。
