## 摘要
随着大型语言模型（LLMs）的快速发展，工具链（harnesses）已成为在广泛领域中部署智能体的关键基础设施。快速演进的工具链生态系统也使得严格的能力评估变得日益重要。然而，高效构建一个端到端、系统化且全面的评估流程仍然是一项重大挑战。为解决这一挑战，我们引入了$A^2E$（智能体审计引擎），这是一个专为智能体工具链设计的端到端评估引擎。$A^2E$利用我们新提出的智能体任务协议（ATP），能够将评估任务与不同的工具链快速集成。通过自动插桩的监控器（Monitor），它在实验过程中捕获并生成标准化的执行轨迹。在评估阶段，$A^2E$使用一套多维指标系统地评估工具链能力。与仅关注正确性相比，这些指标在执行效率、工具使用、任务规划和错误恢复方面提供了对工具链间差异更细粒度的刻画。使用$A^2E$进行的实验进一步揭示，模型与工具链的组合在不同类型的任务上表现出显著的性能差异，且没有任何一种组合能在所有任务上始终优于其他组合。这些发现不仅证明了系统化评估的必要性，也为模型与工具链的协同进化提供了有益的指导。我们的代码可在https://github.com/datamllab/A2E获取。

## Abstract
With the rapid advancement of large language models (LLMs), harnesses have become essential infrastructure for deploying agents across a wide range of domains. The fast-evolving harness ecosystem has also made rigorous capability evaluation increasingly important. However, efficiently building an end-to-end, systematic, and comprehensive evaluation pipeline remains a significant challenge. To address this challenge, we introduce $A^2E$ (Agent Auditing Engine), an end-to-end evaluation engine designed for agent harnesses. $A^2E$ leverages our newly proposed Agent Task Protocol (ATP) to enable the rapid integration of evaluation tasks with different harnesses. Through an automatically instrumented Monitor, it captures and generates standardized execution traces during experiments. In the Evaluation stage, $A^2E$ systematically assesses harness capabilities using a suite of multidimensional metrics. Compared with correctness alone, these metrics provide a more fine-grained characterization of differences among harnesses in execution efficiency, tool use, task planning, and error recovery. Experiments conducted with $A^2E$ further reveal that model-harness combinations exhibit substantial performance variation across different types of tasks, and that no single combination consistently outperforms all others across every task. These findings not only demonstrate the necessity of systematic evaluation but also provide useful guidance for the co-evolving of models and harnesses. Our code is available at https://github.com/datamllab/A2E.

## 1. 核心问题与研究动机

- **背景**：随着大语言模型（LLM）能力的快速提升，系统整体性能越来越依赖于**智能体工具链/框架（Agent Harness）**——它决定了系统提示词、工具接口、上下文管理和执行策略。仅评估底层模型无法完整反映部署后智能体系统的真实能力。
- **现有方案不足**：
  - **Inspect AI**：擅长基准测试编排、沙箱执行和评分，但集成外部工具链需要逐对编写适配器，且可能改变原生生成参数，损害轨迹保真度，维护成本高。
  - **Phoenix（OpenInference）**：提供标准化可观测性，但缺乏端到端的基准运行和结果验证能力，需用户自行拼装基准、工具链与追踪基础设施。
  - 两者扩展新基准、新工具链或新轨迹语义时，都需要大量框架特定的工程改造。
- **核心问题**：如何构建一个**轻量、低侵入、工具链无关**的端到端评估引擎，统一基准执行与高保真轨迹采集，并支持细粒度、可扩展、可复现的工具链能力评估。

## 2. 方法论

### 2.1 总体架构：三层堆叠
- **Task Layer（任务层）**：基于新提出的 **Agent Task Protocol（ATP）**，将基准与工具链解耦。
  - ATP 是内部软件协议（非网络协议），定义任务表示、智能体接口和执行记录。
  - 四个核心对象：`TaskInput`（指令、状态、期望动作/输出、元数据、沙箱规格）、`AgentBinding`（工具 schema、工具执行、提示词构建）、`AgentRunner`（运行控制循环）、`TaskTrace`（运行状态、最终答案、有序工具调用）。
  - 基准按**时间、类别、难度**三个维度建立层级索引树；每个基准打包为"执行支持包"（沙箱定义 + 任务数据集 + 实验配置 + 运行环境）。
- **Monitor Layer（监控层）**：基于 OpenInference 构建，采用 OpenTelemetry 兼容的 **Span 追踪模型**。
  - **语义层**：定义 agent、chain、model call、tool、skill 等行为原语。
  - **Span 层**：记录操作起止时间、上下文、成败状态及父子关系，形成"既按时间又按因果"的轨迹。
  - **SDK 层**：将不同框架的机制（模型调用、工具执行、异步流程）映射到统一语义表示，新增框架只需写专用解释器。
- **Evaluation Layer（评估层）**：提出 **Lifecycle-Aligned Evaluation（生命周期对齐评估）**。
  - 四个评估阶段：
    - **Reasoning**（推理）：Task（目标理解）、Flow（规划完整性）、Logical（推理连贯性）；
    - **Action**（行动）：Tool（工具使用）、Skill（能力应用）、Memory（上下文忠实使用）；
    - **Final Answer**（最终答案）：Answer Correctness（语义质量）、Task Completion（任务是否到达有效终态）；
    - **Runtime Quality**（运行时质量）：Efficiency（效率）、Safety（安全）。
  - **可扩展性设计**：将"在何处评估"与"如何测量"分离；指标可用 LLM-as-judge、规则判定、环境验证器或统计聚合实现，新增指标无需改动基准或工具链。
  - **数据库存储**：轨迹、指标定义、评估结果统一存库，支持增量评估、跨运行纵向比较、事务恢复，替代独立日志文件。

### 2.2 运行流程
- 流水线分为 **Task、Server、Evaluation、UI** 四个松耦合组件；UI 设计为只读，展示数据但不启动实验，避免破坏状态一致性。

### 2.3 关键公式（跨基准工具链比较）
- 综合得分：
  \[
  Q_h = 1 - \frac{\sqrt{\hat{T}_h^2 + (1 - \hat{S}_h)^2}}{\sqrt{2}}
  \]
  其中 \(\hat{T}_h\) 为归一化补全 token 用量，\(\hat{S}_h\) 为归一化任务成功率；\(Q_h\) 越高表示效果与效率的平衡越好。

## 6. 主要结论与发现

- **不存在普遍最优的工具链-模型组合**：同一模型在不同任务上，最优工具链随基准而变化——OpenAI Agents 在 traject-bench 上达 1.00、在 τ-bench 和 GDPVal 上仅 0.20 和 0.00；成功率差距在 GDPVal 上达 0.20、MMLU-Pro 上达 0.30、τ3-bench 上高达 0.66。
- **最终答案正确率区分度有限**：9 个工具链的 correctness 均值仅集中在 0.57–0.68 的窄区间；而规划、工具调用、效率等过程指标张开的"花瓣"远大于正确率，说明结果相似的工具链在过程行为上差异巨大。
- **工具链不是模型的轻量包装器**：同为 DeepSeek-V4-Pro，token 消耗跨工具链相差 3.5×（Claude-Agent-SDK 2,063 vs smolagents 7,319）；提示词构建、工具表示、上下文管理、执行循环、终止策略等设计选择会实质性地改变智能体行为。
- **案例证据**：LangGraph 用 10,122 token、4 次 LLM 调用正确诊断 τ3-bench 任务；CrewAI 用 96,704 token（9.6 倍）、9 次 LLM 调用仍失败——差距源于上下文累积失控、工具选择低效、未执行目标相关动作和错误的终止行为。
- **单轮问答任务中工具链差异"隐形"**：arc-challenge、gsm8k、openbookqa、humaneval 上 9 个工具链得分完全相同；差异只在多轮/工具交互任务中显现——这正说明多维过程评估的必要性。

## 7. 优点

- **端到端一体化**：任务编排、轨迹监控、生命周期评估、数据库存储、只读 UI 在单一栈内闭环，省去大量胶水代码。
- **ATP 协议设计巧妙**：将基准与工具链解耦，避免了 23×9=207 对组合的逐对编程，m×n 配对只需 23+9 个适配器。
- **监控层低侵入且标准化**：基于 OpenTelemetry/OpenInference，自动插桩，无需为每个基准/工具链手写日志；Span 树结构同时保留时间顺序与因果层级。
- **评估维度体系化**：生命周期对齐 + "位置/测量"分离的可扩展接口，使指标目录可随能力、安全需求演进；过程级

过程级指标能揭示工具链在规划、工具调用、上下文管理上的深层差异——这是仅凭最终答案正确率无法捕捉的信息；这使得缺陷定位从“端到端黑盒”走向“轨迹可寻径”，对调试和优化智能体系统有直接价值。

## 8. 缺点与局限性

- **采样规模过小，统计功效不足**：主实验每格仅 5 个任务，成功率分辨率低至 0.20，置信区间极宽；论文也承认表格不适合作为排名依据。这使“哪条工具链更强”的结论难以从统计上严格落地。
- **模型覆盖度有限**：主矩阵只使用 DeepSeek-V4-Pro（FP4），跨基准对比实验只用 GLM-5.2，未覆盖不同模型家族、不同量级或不同推理策略；工具链与模型的交互效应未能系统刻画。
- **基准构成敏感**：综合排名在 19 个非沙箱基准与 23 个全基准之间不一致（前者 LlamaIndex 领先，后者 Agno 领先），说明结论受沙箱类基准的比例影响较大，通用性存疑。
- **数据缺口**：CrewAI 的 LLM span 未记录 token 计数，无法进入 token 效率对比；这意味着图 7 和综合得分 \(Q_h\) 中部分工具链缺失，跨链比较并不完整。
- **评估器本身的可信度问题**：过程指标高度依赖 LLM-as-judge 或规则判定，论文未对评估器一致性、偏见或错误率做校准实验，也没有消融评估器选择对结论的影响。
- **工具链适配的隐性成本**：ATP 虽将适配器数量从 \(m \times n\) 降低到 \(m + n\)，但每个基准的“执行支持包”（沙箱、数据集、实验配置、环境）仍由人工构建，23 个基准的维护成本并未被量化。
- **缺乏可复现性细节**：论文未披露代码仓库地址、环境镜像、GPU 资源或轨迹数据下载方式，外部研究者难以完全复现其结果。

## 9. 对未来工作的启示

- **扩大采样与统计设计**：未来可采用分层抽样或自适应采样，在保持轨迹完整性的前提下提高每个基准的样本量，并对工具链差异做显著性检验，使“排名”结论具备统计置信度。
- **多模型 × 多工具链叉乘**：将评估矩阵扩展为“模型 × 工具链 × 基准”的三维空间，才有望刻画二者交互对鲁棒性的影响。
- **标准化轨迹协议**：ATP 的提出提示行业可以追求统一的智能体执行记录格式——若被多家框架采纳，将极大简化评测生态的搭建。
- **指标即插即用**：生命周期对齐的“评估位置/测量方法”分离模式，为安全、隐私、合规等新维度预留了扩展位；后续可在此基础上构建类似“模型卡”的“工具链卡”。
- **动态评估与增量追踪**：数据库驱动的增量评估支持对工具链版本升级、提示词修改做 A/B 回归验证，适合作为 CICD 流水线中的持续评估组件。

本文提出了一个设计清晰、工程上自洽且具有前瞻性的智能体审计引擎。其价值不在一份“排行榜”，而在评估范式本身：将工具链从“隐环境变量”变为“可测系统组件”，以生命周期对齐的过程指标补足最终答案的盲区，并以协议化、数据库化的方式支撑大规模、可复现、可演进的评测。尽管受制于采样规模和模型覆盖，结论的统计强度有限，但它为“智能体系统级评测”建立了一个可扩展的参考框架，对学术研究和工程实践都有较强的启发性。
