## 摘要
当故障限制了后续修复时，自我修正特别有用。编程智能体受益于这一特性，因为编译器、测试和执行轨迹将许多故障转化为类型化的恢复信号，但广泛的语言智能体任务通常只暴露粗略的任务失败。这给通用恢复剧本带来了张力：它们恰恰在系统需要更狭窄的修复界面时扩展了智能体的上下文，混合了针对无效动作、缺失程序和严格格式错误的不兼容信号。我们的见解是，通过在测试时修正之前决定哪些恢复干预是允许的，开发集故障可以恢复部分缺失的诊断基础。我们提出了DARC，一种诊断引导的恢复框架，它对任务族故障模式进行剖析，从共享恢复库中剪除不匹配的干预措施，并冻结验证器选择的成功成本策略以供部署。这种因果顺序使修正具有选择性：框架首先确定哪种故障可以修复，然后决定花费多少恢复证据。在ALFWorld、AppWorld和XBRL Finance中，同一协议产生了动作有效性框架、程序性恢复回退和格式精确检索策略；在每个评估设置中，它相对于基础智能体和广泛剧本提高了平均任务性能，同时减少了环境步骤或检索预算。我们的实验表明，故障不需要统一地触发更多上下文：DARC将自我修正从提示扩展转变为恢复接口设计。DARC提供了一条实用路径，在缺乏类似编译器反馈的领域中实现更可靠的智能体：在扩大上下文之前使故障可操作。

## Abstract
Self-correction is particularly useful when a failure constrains the next repair. Coding agents benefit from this property because compilers, tests, and execution traces turn many failures into typed recovery signals, but broad language-agent tasks often expose only a coarse task failure. This creates a tension for generic recovery playbooks: they broaden the agent's context precisely when the system needs a narrower repair interface, mixing incompatible signals for invalid actions, missing procedures, and strict-format errors. Our insight is that development-set failures can recover part of the missing diagnostic substrate by deciding which recovery interventions are admissible before test-time correction. We propose DARC, a diagnosis-guided recovery harness that profiles task-family failure modes, prunes mismatched interventions from a shared recovery library, and freezes a verifier-selected success-cost policy for deployment. This causal order makes correction selective: the harness first determines what kind of failure can be repaired, then decides how much recovery evidence to spend. In ALFWorld, AppWorld, and XBRL Finance, the same protocol yields an action-validity harness, a procedural-recovery fallback, and a format-precision retrieval policy; in each evaluated setting it improves average task performance over base agents and broad playbooks while reducing environment steps or retrieval budget. Our experiments show that failures need not trigger uniformly more context: DARC turns self-correction from prompt expansion into recovery-interface design. DARC provides a practical route toward more reliable agents in domains where compiler-like feedback is absent: making failures actionable before making contexts larger.

# 论文总结

## 1. 核心问题与整体含义（研究动机与背景）

- **背景**：编程智能体（coding agents）之所以能成功自我修正，是因为软件环境提供了类似编译器的反馈（语法/类型错误、测试失败、执行轨迹），这些反馈是**类型化**且**可操作**的，能够区分不同失败类型并提供针对性修复信号。
- **问题**：大多数通用语言智能体任务缺乏这类诊断基础。例如，具身智能体发出无效动作、多应用助手缺少 API 流程、金融抽取智能体违反格式约束，这些失败在基准中往往只表现为“任务未完成”的粗粒度信号。
- **现有做法的缺陷**：通用恢复剧本（generic recovery playbooks）试图通过“追加更多上下文”来应对所有失败，导致三个问题：
  1. **干预不匹配**：未诊断的恢复信号无法回应实际失败，如用完整 API 手册解决无效动作或格式错误。
  2. **恢复干扰**：无关流程和上下文可能把智能体拉离状态兼容动作，甚至相互冲突。
  3. **恢复成本失控**：每次失败都触发所有信号，导致环境步数、检索预算、推理 token 无效膨胀。
- **核心洞察**：关键不是“要不要更多上下文”，而是“哪种失败可以触发哪种恢复信号”。作者提出应在测试时修正之前，利用**开发集失败**来构建“诊断基础”，使失败可操作化，而非简单扩大上下文。
- **整体含义**：自我修正应被重新定义为**恢复接口设计**，而非提示扩展。

## 2. 方法论：DARC

### 2.1 核心思想

DARC（Diagnosis-guided Agent Recovery and Correction）通过两个阶段构建恢复框架（recovery harness）：

1. **诊断阶段**：利用开发集失败剖析任务族的失败模式，并据此**限制可干预集合**，排除无法适配的干预。
2. **策略蒸馏阶段**：基于训练集验证器反馈，在受限干预集内选择并**冻结**一个成本感知的短策略，用于部署。

### 2.2 形式化定义

- 恢复框架：$H_m = (m, R_m, \pi_m)$，其中 $m$ 为失败模式，$R_m \subseteq R$ 为该模式允许的干预集合，$\pi_m = (r_1,\ldots,r_L)$ 为有序部署策略。
- 恢复目标（式 2）：

$$\max_{\pi \in \Sigma(R_m)} \mathbb{E}_{x\sim X}[s(x,\pi)] - \lambda \max\left(0, \mathbb{E}_{x\sim X}[c(x,\pi)] - \tau_{\text{free}}\right)$$

其中 $s$ 为成功指示，$c$ 为执行成本，$\lambda$ 控制成本-成功权衡，$\tau_{\text{free}}$ 为标准尝试的成本配额。

### 2.3 算法流程（Algorithm 1）

1. 在开发集 $D_{\text{dev}}$ 上运行基础智能体，测量失败信号。
2. 诊断主导失败模式 $m$，确定允许干预集 $R_m$。
3. 在训练集上对每个干预评估成功与成本，形成证据矩阵 $E_{i,j}$。
4. 枚举有界候选策略，用目标函数打分。
5. 冻结最优策略 $\pi^*$ 用于测试。

### 2.4 关键技术细节

- **短路径策略**：智能体按顺序尝试干预，若一个成功则停止——对应式 (4) 的停止索引。
- **覆盖子模性**：成功项 $f(A)=\frac{1}{n}\sum_i \max_{r\in A} s(x_i,r)$ 是单调子模覆盖函数，因此短策略即可覆盖大部分可恢复任务。
- **有限样本保证**：对固定策略类 $\Sigma_K$，经验最大化者与总体最优策略的偏差为 $O(\sqrt{\log |\Sigma_K|/n})$，因此诊断缩小候选空间可降低搜索风险。
- **诊断的冻结性**：任务族级别诊断在测试前冻结，避免测试标签泄漏，保证可审计性。
- **三个场景的具体实现**：
  - ALFWorld：动作有效性框架，通过规则打分 $S(a) = S_{\text{goal}} + S_{\text{phase}} + S_{\text{search}} + S_{\text{train-prior}} - S_{\text{conflict}} - S_{\text{loop}}$ 对可执行命令排序，保留 top-12。
  - AppWorld：程序性知识回退链（Auto-Knowledge → local induction → retrieval fallback）。
  - XBRL Finance：格式精度检索策略，蒸馏检索预算 $k$（如 Formula 用 $k=2$，Tags 用 $k=1$）。

## 6. 主要结论与发现

1. **失败不需要统一触发更多上下文**：通过诊断限制恢复干预，可以在提升成功率的同时降低环境步骤或检索预算。
2. **诊断导向的恢复优于通用剧本**：正确诊断的恢复策略在三个基准上均优于 Base、ICL、MIPROv2、GEPA 和 ACE。
3. **恢复干预不是可互换的**：动作守卫不能解决程序缺失，检索演示不能解决无效动作；不匹配干预有时比通用剧本更有害（如 Finance 错配宏准确率仅 37.75%）。
4. **ALFWorld 提升主要来自“恢复接口”的交互效应**：单独提示或单独动作限制几乎无效，二者结合产生 +49.26 pp 的成功率提升，交互项 +46.27 pp。
5. **检索能力存在边际递减甚至负效应**：Finance 中 $k=8/16$ 的准确率低于 $k=1/2$，说明“证据并非越多越好”。
6. **冻结策略可迁移**：同一失败模式下，任务间策略迁移能保留大部分目标调优性能。

## 7. 优点

- **问题切入精准**：指出通用自我修正“提供无关上下文”的核心矛盾，将恢复视为“接口设计”而非“上下文扩展”。
- **方法简洁可操作性**：先诊断、后限制、再蒸馏，两阶段流程清晰；冻结策略保证部署稳定与可审计。
- **成本考量显式化**：目标函数包含成本惩罚，并在实验中量化环境步数、检索预算和推理成本。
- **公平性验证扎实**：专门设计匹配信息测试、随机行动剪枝对照、2×2 因子分解，排除“特权信息”和“简单剪枝”的替代解释。
- **理论支撑**：覆盖子模性、均匀收敛界等分析为“缩小策略空间”提供了有限样本依据。
- **多场景覆盖**：动作有效性、程序广度、格式精度三类失败模式均有所体现，验证了框架的通用性。

## 8. 不足与局限

- **静态任务族级诊断**：每个基准只指定一个主导失败模式，未处理混合失败模式或实例级动态路由；作者也将其列为未来工作。
- **实验范围有限**：
  - 权重空间训练扩展为单种子、在 Qwen3-8B 上绝对增益较小，未形成成熟训练配方。
  - 全库级联对照只在 ALFWorld 上实施，未扩展到 AppWorld 和 Finance。
  - 部分对比（如 AppWorld Challenge 上某些指标）ACE 可匹敌甚至超过 DARC，说明在更难的分布上优势不统一。
- **成本指标不一**：ALFWorld 用环境步数/无效动作，AppWorld 用环境步数，Finance 用检索预算，跨域成本不可直接比较。
- **信息使用口径差异**：DARC 不使用答案标签，只使用训练集验证器反馈，而多数基线使用答案标签；作者虽明示区分，但实际基线差异可能不是纯粹“诊断”带来的。
- **潜在偏差风险**：诊断依赖 LLM 自动标注，虽有 97.22% 一致率验证，但样本量仅 72 条，且诊断失败模式词汇固定，可能遗漏非主导失败。
- **推广性未验证**：所提出的“编译器式反馈替代”是否适用于更广泛、更开放的智能体任务（如网页交互、具身长程任务）仍是开放问题。
