## 摘要
许多自动化多智能体系统设计方法在初始设计阶段优化提示和拓扑，然后将所得系统不变地部署到后续样本上。这些样本中的经验很少被整合为可重用的系统更新，而面向准确性的设计可能产生高昂的令牌成本。我们引入了EMAS（演化多智能体系统），它利用这些经验来修订MAS拓扑和提示，而无需更新LLM参数，既可以提高准确性，也可以降低成本。EMAS将轨迹转换为结构化诊断，指定修订操作和目标。仅当相同诊断在多个样本中重复出现时，它才生成候选修订，并且仅当与当前MAS的配对验证满足相应接受标准时才应用该修订。在四个基准和两个LLM上，EMAS在两种骨干网络下均取得了最高的任务加权整体准确率，并在八个模型-基准设置中的六个中达到最佳或并列最佳。在两个演化周期内，EMAS在Kimi-K2-6和Qwen3.6-27B上的任务加权准确率分别相对提高了6.30%和20.10%。在MBPP上使用Qwen3.6-27B时，EMAS将准确率从55.09%提升至89.12%，同时每个任务的令牌使用量减少了62.2%。这些结果表明，EMAS可以将新样本中的经验转化为对MAS拓扑和提示的可重用更新。

## Abstract
Many methods for automated multi-agent system design optimize prompts and topologies during an initial design stage and then deploy the resulting system unchanged on subsequent samples. Experience from these samples is rarely consolidated into reusable system updates, while accuracy-oriented designs may incur high token costs. We introduce EMAS (Evolving Multi-Agent System), which uses this experience to revise MAS topology and prompts without updating LLM parameters, either to improve accuracy or to reduce cost. EMAS converts traces into structured diagnoses that specify a revision operation and target. It generates a candidate revision only when the same diagnosis recurs across samples and applies it only if paired validation against the current MAS meets the corresponding acceptance criterion. Across four benchmarks and two LLMs, EMAS attains the highest task-weighted overall accuracy for both backbones and is best or tied in six of eight model--benchmark settings. Within two evolution epochs, EMAS achieves relative gains of 6.30% and 20.10% in task-weighted accuracy on Kimi-K2-6 and Qwen3.6-27B, respectively. On MBPP with Qwen3.6-27B, EMAS raises accuracy from 55.09% to 89.12% while reducing token use per task by 62.2%. These results show that EMAS can turn experience from new samples into reusable updates to MAS topology and prompts.

# 论文总结：EMAS——通过证据引导修订稳定多智能体系统演化

## 一、核心问题与整体含义（研究动机与背景）

- **研究动机**：现有自动化多智能体系统（MAS）设计方法通常在初始设计阶段一次性优化提示词（prompts）与拓扑结构，之后部署时不再改变。这些系统无法从后续新样本的执行经验中持续学习与改进，错失了利用运行反馈升级系统的机会。
- **核心问题**：如何将 MAS 处理新任务时产生的经验证据，转化为可复用的系统级更新（修订提示词与拓扑），同时保持底层 LLM 参数冻结？
- **关键挑战**：
  - *何处修订*：需要能暴露中间计算的表示，以定位错误来源（缺失计算、有害信息流、指令不足）。
  - *何时修订*：需区分偶发失败与反复出现的模式，避免对孤立异常做出反应。
  - *如何控制回归*：修订可能损害已有能力，需要验证机制来保证改进的稳定性。
- **整体含义**：EMAS 将任务局部经验转化为可审计的系统状态，将 MAS 自我改进从"生成看似合理的编辑"转向"决定哪些修订可以塑造未来行为"，为递归自我改进（RSI）提供了一种系统层实现路径。

## 二、方法论

### 2.1 核心思想
- **系统层演化**：保持 LLM 权重固定，将 MAS 视为一个可编辑的执行系统，通过修订其拓扑与提示词实现演化。
- **证据驱动的有界修订**：将执行轨迹转译为结构化诊断，只在相同诊断跨样本重复出现时生成候选修订；只有候选在配对验证中胜出才被接受为新的系统版本。

### 2.2 可执行、可编辑的 MAS 状态
- 每个 Agent 被细分为多个原子 Step（单个 LLM 调用），MAS 建模为有向无环图 G = (V, E)。
- 节点 V 表示 Step，边 E 表示 Step 间的工件流。
- 提示词状态 P 包括系统级、类别级、阶段级和步骤级指令。
- 每个任务类别维护一个独立的 MAS：M(v) = (G(v), P(v))；v 表示已接受修订的版本号。

### 2.3 初始化（Initial Evolve）
- 为每个类别挑选少量代表性输入，由 LLM 设计器生成完整的初始 MAS（Step、边、提示词）。
- 经过结构验证与修复，保证图引用合法、拓扑有效、提示词覆盖完整。

### 2.4 在线演化（Online Evolve）：从轨迹到修订
- 每条轨迹可产生多个诊断记录，规范形为 **h = (o, d, a, ℓ)**：
  - o ∈ {ACCURACY, COST}：优化目标（准确率或成本）；
  - d：缺陷类别；
  - a：对应操作；
  - ℓ：规范位置。
- 支持的操作算子：
  - **Step 层面**：ADD-NODE（缺失操作）、REMOVE-NODE（冗余/有害操作）、SPLIT-NODE（非原子操作拆分）；
  - **Edge 层面**：ADD-EDGE（缺失信息供给）、REMOVE-EDGE（冗余/有害信息流）；
  - **Prompt 层面**：PROMPT-ONLY（修订指令）。
- 每个候选修订限于一个主变更加直接关联的边/提示词闭包，保证修订的局部性和可审计性。

### 2.5 复发门控的候选构建
- 每个假设维护一个证据缓冲区；当支持样本数达到操作特定的阈值 κa 时才触发候选构建。
- 阈值设置体现风险差异：ADD 类操作阈值较低（κ=4），PROMPT-ONLY 阈值中等（κ=6），REMOVE 类操作阈值较高（κ=10），因为删除操作风险更大。

### 2.6 配对验证与版本过渡
- 候选 MAS 与当前 MAS 在相同固定验证集 D_val 上比较（公平配对）。
- 接受规则：
  - **准确率导向**：Accept_acc(候选) ⇔ C(候选) > C(当前)（严格提升正确数）；
  - **成本导向**：Accept_cost(候选) ⇔ C(候选) ≥ C(当前) ∧ T(候选) < T(当前)（保持准确率同时严格降低总 token）。
- 接受后提升版本 v → v+1；拒绝则保留当前版本。无论接受与否，被处理的触发相关诊断记录都会被消耗，且接受后会重放剩余活动样本以获得最新诊断，防止陈旧证据引发连锁修订。

## 六、主要结论与发现

1. **准确率提升**：EMAS 在两个骨干上均取得最高任务加权整体准确率；Kimi 从 90.11% → 95.79%（相对 +6.30%），Qwen 从 73.42% → 88.18%（相对 +20.10%），8 个设置中 7 个提升、1 个持平。
2. **准确率与成本可同时改善**：Qwen–MBPP 上准确率从 55.09% → 89.12%，同时 token 从 5.16k 降至 1.95k（节省 62.2%）。
3. **长期演化持续有效**：Game24 扩展到 E15 后，Kimi 最佳准确率达 96.45%（较 E2 +1.11pp），Qwen 达 94.73%（较 E2 +14.83pp），token 也同步下降。
4. **演化特征随系统成熟度变化**：初始头room大的系统（如 Qwen 的 MBPP/PlanBench/Game24）主要经历准确率大幅修复；接近饱和的系统（如 Kimi Math）则更多进行成本优化。
5. **演化非单调但整体进步**：93 个 E2 修订中 39 个（41.9%）在测试集上出现回归，平均损失 3.03pp；但成功修订的平均增益（4.46pp）大于平均损失，整体仍呈上升趋势。
6. **复发与验证门控是稳定性的关键**：κ=1 时回归概率为 Full EMAS 的 1.14 倍，去验证门控时为 1.57 倍；去验证门控后平均单次回归幅度为 7.93pp，远高于 Full EMAS 的 0.28pp。
7. **接受率因骨干而异**：Kimi 的触发接受率为 28.1%，高于 Qwen 的 17.5%，说明更强骨干生成的修订更容易通过验证。

## 七、优点

- **新颖的问题定位**：将 MAS 演化从"设计时优化"扩展到"运行时持续修订"，并形式化为证据积累 + 配对验证的修订授权问题；
- **细粒度可审计性**：使用原子 Step 级别的图表示，使系统内部计算和通信可观测、可定位、可针对性修复；
- **双目标演化**：同时支持准确率提升与 token 成本降低，并分别设有清晰的接受准则；
- **稳定性机制设计合理**：复发阈值过滤噪声，配对验证过滤坏候选，两阶段机制互补（一个改善证据质量，一个测试候选质量）；
- **判断逻辑符合风险直觉**：高风险操作（删除）需要更多证据支撑，低风险操作（添加）可更早触发；
- **实验分析深入**：不仅报告最终结果，还分析版本轨迹、Pareto 前沿、修订成功率、回归分布、成本来源等，透明度高。

## 八、不足与局限

- **非单调性与部署风险**：演化轨迹存在局部回归，且主结果依赖测试集上的"回顾性最佳检查点"，无法提供部署时的最佳版本选择规则；
- **验证集过拟合风险**：固定验证集反复使用会导致自适应选择，使验证接受不完全等价于真实泛化；
- **证据粒度有限**：复发模式的结构化键可能合并了因果上不同的失败，一个有界修订也可能无法处理需要协调多步骤变更的问题；
- **假设正确性反馈**：方法依赖"输出是否正确"的外部信号，不适用于无标签或软反馈场景；
- **计算成本高**：配对验证需要在验证集上完整运行当前与候选两个系统，总演化成本达 2.9B tokens，实用中的开销不可忽视；
- **评测范围有限**：仅两个骨干（Kimi-K2-6、Qwen3.6-27B）和四个 benchmark，未涉及更大模型、更多领域（如问答、对话）或多语言场景；
- **消融不足**：稳定性机制的消融仅在一个数据集和单个骨干上执行，结论的普适性有待更广验证；
- **外部基线公平性存疑**：基线方法未按各 benchmark 进行专门调优，且 AFlow/ADAS 为平均 1–3 次重复，可能在超参数和计算预算上不如 EMAS 精细调节。
