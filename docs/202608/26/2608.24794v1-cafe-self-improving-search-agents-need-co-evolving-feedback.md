## 摘要
结果监督的搜索智能体学习何时检索证据以及如何检索，但最终奖励既不能定位中间错误，也不能在错误累积之前重定向正在进行的轨迹。将纠正性反馈视为一种学习到的轨迹内干预，将两个角色耦合在一起：智能体必须决定何时请求和使用反馈，而评论者必须从结果混淆的 rollout 中推断出有用的纠正，这些 rollout 的失败模式会随着智能体的改进而改变。我们提出了 CAFE（耦合智能体-反馈进化）框架，其中共享参数模型在搜索智能体和评论者角色之间交替。CAFE 从围绕基础智能体自身失败构建的轨迹初始化反馈条件下的恢复，然后耦合在线和离线优化。在线强化学习期间，比较性反馈估计使用提示级别的调用-跳过成功差距来塑造请求回报，而反馈感知的优势塑造在反馈前后重新加权 token 优势。离线时，从 rollout 派生的偏好优化从匹配的成功和不成功轨迹中学习反馈。在七个智能体搜索基准上，CAFE 平均优于被评估的基于强化学习的搜索智能体，在所有六个域外基准上保持其收益，并减少了答案层面的幻觉。单侧消融表明，仅改进智能体或仅改进评论者最终会趋于平稳，而交替进行两种更新会持续提高性能。这些发现表明，自我改进的搜索智能体需要与其所指导的策略共同进化的反馈。

## Abstract
Outcome-supervised search agents learn when and how to retrieve evidence, but terminal rewards neither localize intermediate errors nor redirect an ongoing trajectory before those errors compound. Treating corrective feedback as a learned in-trajectory intervention couples the two roles: the agent must decide when to request and use feedback, while the critic must infer useful corrections from outcome-confounded rollouts whose failure patterns shift as the agent improves. We introduce CAFE (Coupled Agent--Feedback Evolution), a framework in which a shared-parameter model alternates between search-agent and critic roles. CAFE initializes feedback-conditioned recovery from trajectories built around the base agent's own failures, then couples online and offline optimization. During online RL, a comparative feedback estimate uses a prompt-level call--skip success gap to shape request returns, while feedback-aware advantage shaping reweights token advantages before and after feedback. Offline, rollout-derived preference optimization learns feedback from matched successful and unsuccessful trajectories. On seven agentic search benchmarks, CAFE outperforms the evaluated RL-based search agents on average, retains its gains across all six out-of-domain benchmarks, and reduces answer-level hallucinations. One-sided ablations show that improving only the agent or only the critic eventually plateaus, whereas alternating the two updates continues to improve performance. These findings suggest that a self-improving search agent needs feedback that co-evolves with the policy it guides.

### 一、论文的核心问题与整体含义

**研究动机与背景**

- 搜索智能体需要通过与外部环境的迭代交互来解决知识密集型问题，但**仅依赖最终答案的稀疏结果监督**存在根本性缺陷：终结奖励既无法定位中间步骤的错误，也无法在错误累积前重定向正在进行的轨迹。
- 在长程搜索中，早期方向性错误往往会传播并影响后续所有检索步骤，且错误来源事后难以追溯，例如：检索中遗漏必要子目标、约束条件在后续步骤被静默丢弃、反复改写查询却不获取新证据等。
- 已有工作（信息增益、置信度变化、局部状态比较）提供的信号仍然属于**评价式而非指导式**，即事后分配信用而将修正推迟到未来策略更新。轨迹内的即时纠正需要**可学习的、上下文内的纠正性反馈**。
- 引入可学习反馈后出现三个相互交织的挑战：
  1. **智能体侧**：需学会何时请求干预，且被"挽救"的轨迹与完美轨迹（无人请求反馈）获得相同奖励，导致信用归属混淆；
  2. **评论者侧**：反馈的学习没有真值，且其效用被前序搜索和后继动作双重混淆；
  3. **耦合侧**：在线更新不断改变智能体访问的状态与失败分布，静态评论者会与正在演化的策略失配。

**核心主张**

- 自我改进的搜索智能体需要与其策略**共同进化（co-evolve）**的反馈机制，而非固定评论者。批评与行动构成一个耦合的学习系统：每一方的更新都会改变另一方进行学习所依据的经验分布。

### 二、方法论

**核心思想**

- 提出 **CAFE（Coupled Agent–Feedback Evolution）**：一个共享参数模型交替扮演"搜索智能体"与"反馈评论者"两种角色，将轨迹内纠正性反馈整合进主动搜索过程，并通过在线强化学习与离线偏好优化的交替迭代实现两角色的共同进化。

**关键技术细节**

1. **自反馈搜索智能体（RQ1）**
   - 在智能体动作空间中增加可选的 `<request_feedback>` 动作；评论者对当前轨迹进行诊断并生成纠正性反馈，反馈追加到上下文后继续搜索。
   - 智能体与评论者实例化为同一共享模型的条件角色：`a_i,t ~ πθ^A(·|h_i,t)` 与 `f_i,t ~ qθ^C(·|h_i,t)`；共享同一主干，推理时角色分离。
   - **SFT 初始化**：收集基座智能体的失败轨迹，用教师模型（Kimi-K2.5）定位最早出错回合，保留错误前缀，插入 `<request_feedback>`，由教师生成反馈与成功续写。仅保留最终答案正确的修复轨迹。该数据保留了基座智能体自身遭遇的失败模式与恢复路径。

2. **在线智能体优化（RQ2）**

   **（a）对比反馈估计（CFE）奖励**：在 GRPO 的 rollout 分组框架下，定义"调用组"（至少一次反馈请求）与"跳过组"（无反馈请求）之间的提示级成功差：

   \[
   \hat{u}(x) = \frac{1}{|G_{x,call}|}\sum_{j \in G_{x,call}} r_j - \frac{1}{|G_{x,skip}|}\sum_{k \in G_{x,skip}} r_k
   \]

   最终 CFE 形状奖励为：`R_CFE = r_task + β·C_i·û(x) − γ·[n_fb,i − 1]+`，其中 `r_task` 为原始答案正确性奖励，`C_i` 为是否调用反馈的指示变量，`n_fb,i` 为请求次数，第二项惩罚首次以外的重复请求。

   **（b）反馈感知优势塑形（Advantage Shaping）**：将请求反馈轨迹的 token 划分为请求前 `T_pre`（驱动错误搜索的前缀）、请求轮 `T_call` 与反馈后 `T_post`（恢复续篇。将提示级差距 `g_i = clip(û, 0, b)` 应用于优势值：

   \[
   \tilde{A}_{i,t} = \max(A_i − λg_i, 0)，\text{若 } t ∈ T_{pre};\quad A_i，\text{若 } t ∈ T_{call};\quad A_i + λg_i，\text{若 } t ∈ T_{post}
   \]

   其动机是：SFT 初始化保留了基座策略的失败前缀，请求前行为恰是导致失败的行为。若将请求前后统一赋权，则等于奖励被放弃的错误行为。优势塑形解决了这一信用边界问题。

3. **离线反馈优化与迭代共同进化（RQ3）**

   **（c）Rollout-Derived Preference Optimization（RDPO）**：从最新一轮在线 rollout 中提取偏好对——匹配同一提示下成功且请求反馈的轨迹与失败轨迹，要求两轨迹在首次请求前的历史高度相似（使用 token 集合 Jaccard 相似度 ≥ 0.7），经 LLM 判别过滤后构成 `D_fb^k`。成功历史作为共享上下文，成功反馈作为 chosen，失败反馈作为 rejected，进行 DPO 更新。
   - 与正样本 SFT 的对比：结果标签反映整条轨迹而非反馈本身，正样本可能有噪声；RDPO 的相对偏好信号更干净，且锚定在当前在线检查点，避免两个角色在最大似然拟合下漂移。
   - **交替优化调度**：每次迭代 = 100 步在线 RL + 1 次 2 epoch 的 RDPO 更新，共 5 次迭代（500 步在线 RL）。RDPO 使用保守学习率（2×10⁻⁷），防止离线偏好优化覆盖在线学习到的问题求解能力。

4. **理论保证**：论文在附录中提供了一个定理，证明当 CAFE 引入的扰动小于结果优化任务自身的更新范数时，CAFE 在线更新与原始结果监督 GRPO 更新方向保持正对齐，即不会反向优化任务目标。
