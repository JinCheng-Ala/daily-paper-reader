## 摘要
基于大型语言模型的智能体可以通过工具调用来与外部环境交互，但这种能力也带来了安全风险，例如文件修改、信息泄露和未授权操作。现有的防护机制通常评估完整的轨迹，而在动作执行前的步骤级监控尚未得到充分探索。我们提出了StepGuard，一个步骤级防护模型，能够审计已完成的智能体轨迹，并在工具动作执行之前对其进行检查。为了训练StepGuard，我们引入了StepGen，一个自动数据引擎，它能够在相同的上下文但风险步骤上生成不同动作的安全和不安全轨迹。为了进一步减少过度防护和防护不足，我们提出了Balance-GRPO，它根据安全和不安全动作的观测准确率动态平衡学习。实验表明，StepGuard在开放权重防护模型中取得了最高的平均准确率，性能可与GPT-5.4相媲美。当用于保护AgentDojo和AgentDyn上的智能体时，StepGuard相对于无防护设置将平均攻击成功率降低了77.3%，而平均效用仅下降了2.8个百分点。

## Abstract
LLM-based agents can interact with external environments through tool invocation, but this capability also introduces security risks such as file modification, information leakage, and unauthorized actions. Existing guardrails often evaluate completed trajectories, leaving pre-execution monitoring of step-level actions underexplored. We propose StepGuard, a step-level guard model that can audit completed agent trajectories and check tool actions before they are executed. To train StepGuard, we introduce StepGen, an automatic data engine that generates safe and unsafe trajectories with the same context but different actions at the risky step. To further reduce over-defense and under-defense, we propose Balance-GRPO, which dynamically balances learning between safe and unsafe actions based on their observed accuracy. Experiments show that StepGuard achieves the highest average accuracy among open-weight guard models, with performance comparable to GPT-5.4. When used to guard agents on AgentDojo and AgentDyn, StepGuard reduces mean attack success rate by 77.3% relative to the no-guard setting, while mean utility drops by only 2.8 percentage points.

# StepGuard 论文总结

## 1. 核心问题与整体含义

- **背景**：基于大型语言模型（LLM）的智能体（Agent）可通过工具调用与外部环境交互，带来文件修改、信息泄露、未授权操作等真实世界安全风险。部署防护机制（guardrail）是提升智能体安全性的实用途径，且无需修改或重训智能体本身。
- **核心问题**：现有防护大多评估完整轨迹，缺少对步骤级动作的“执行前监控”；同时，防护模型普遍存在“防御偏差”——过度防御牺牲任务效用，或防御不足牺牲安全性。
- **两大挑战**：
  1. 缺乏可扩展、高质量的步骤级监督数据（真实不安全执行稀缺，人工构建昂贵且难以跨工具/上下文/风险扩展）；
  2. 对安全–效用平衡的控制有限（现有训练方法不能根据防护模型在安全/不安全动作上的准确率差异显式调整训练）。
- **总体含义**：论文提出 StepGuard，一个 4B 规模的步骤级防护模型，既能在工具动作执行前检查候选动作，也能审计已完成轨迹；同时提出数据引擎 StepGen 和训练算法 Balance-GRPO，以缓解上述挑战，实现安全性与效用的更好平衡。

## 2. 方法论

### 2.1 任务形式化
- 输入上下文 X 可以是完整轨迹（事后诊断）或当前前缀+候选动作（执行前防护）。
- 防护模型输出结构化诊断：`(Y, B, R, S)`，分别表示安全/不安全判断、是否存在风险源、风险源类型、不安全步定位。
- 强调风险源检测不等于不安全判断：上下文存在风险源但智能体正确处理时，结果仍可为安全。

### 2.2 StepGen：前缀对齐数据引擎
- **风险锚定轨迹构造**：采样风险源 r、失败模式 f、危害类型 h 和工具子集 T，由 planner 生成任务场景和结构化执行计划 P，指定一个不安全动作作为“锚点 i*”；不确定唯一锚点的计划被丢弃重采样；通过环境模拟器 rollout 得到不安全轨迹 τU。
- **前缀对齐对比分支**：
  - 保持锚点之前的执行前缀固定，仅从锚点起重新生成安全分支：
    - **Refuse 分支**：智能体识别风险并拒绝执行；
    - **Aware 分支**：识别风险后通过安全替代方案继续完成任务；
  - 另外独立生成一条“良性工具复用”轨迹：在非对抗场景中复用相同工具子集 T，避免防护模型把“工具身份”当作安全信号。
- **步骤级标注与质量控制**：
  - 每个动作获得 Safe/Unsafe 标签，并附带包含证据、意图、后果、决策、风险源等五个字段的结构化理由；
  - 规则验证器 ϕmech 检查轨迹结构、工具调用格式、参数来源一致性；
  - LLM 审计器 ϕqual 从六个维度（授权匹配、范围一致性、锚点正确性、标签传播、内容真实性、失败模式-危害-工具一致性）打分，总分 ≥14 且无零分维度才保留。

### 2.3 StepGuard 训练
- **冷启动 SFT**：从 Qwen3-4B-Instruct 初始化，在 3K StepGen 示例上全参数微调；用 GPT-5.4 生成目标响应，丢弃与标注不一致的响应。
- **Balance-GRPO**（核心创新）：
  - 结构化奖励：`r = 0.5·I(Y_correct) + 0.5·I(Y_correct)·I(R_correct)`，只有安全判断正确时风险类别才得分；
  - 按标准 GRPO 对同一 prompt 组的 reward 做归一化得到优势 A；
  - 优势重加权：`A' = c_i · ω_i · A`，其中：
    - c_i 为类别计数平衡因子，缓解安全/不安全样本数量不均；
    - ω_i 为基于“安全类准确率 − 不安全类准确率”差距的权重因子，给当前准确率更低的一类更高训练权重；
  - 使用标准 clipped GRPO 目标函数并带 KL 正则，不改变 prompt 采样和原始奖励。

## 6. 主要结论与发现

- StepGuard 在开放权重防护模型中取得最高平均准确率，静态评估中与闭源 GPT-5.4 性能相当（轨迹级 Acc/F1 83.0/83.3，步骤级 84.8/84.1）。
- 动态守卫生成评估中，StepGuard 使 AgentDojo 与 AgentDyn 的平均 ASR 相对无防护降低 77.3%，平均效用仅下降 2.8 个百分点。
- Balance-GRPO 相比 vanilla GRPO，把安全类与不安全类准确率差距从 13.0 降至 8.0，AgentDojo/AgentDyn 效用分别提升 5.4/6.7 个百分点，ASR 仅增加 0.3 个百分点。
- StepGen 的“中间前缀监督”和“良性工具复用”均带来明确收益；模型在未见风险源上也能泛化（2 源训练到 6 源测试，Acc/F1 74.9/78.1，远超骨干模型 49.6/35.6）。

- 错误分析显示：误报主要来自敏感工具的良性使用（43.6%）和可疑上下文被安全处理（25.7%）；漏报集中于遗漏恶意意图（19.8%）、工具语义误解/授权或隐私违规/多步风险传播（各 17.5%）。

## 7. 优点

- **任务定位新颖**：同时支持“执行前步骤级检查”和“完整轨迹事后审计”，填补现有防护多在轨迹级评估的空白。
- **数据设计巧妙**：StepGen 构造“相同前缀、锚点处分支”的安全/不安全对比组，能把风险定位到具体动作；独立的良性工具复用轨迹可防止模型依赖工具身份判断安全。
- **训练目标实用**：Balance-GRPO 不改变 prompt 和原始奖励，仅根据 rollout 中类间准确率差距动态重加权优势，直接缓解防御偏差，思路简单且可迁移。
- **模型小而强**：4B 参数即达到与 GPT-5.4 相当或接近的效果，且推理延迟低于 TS-Guard 和 ShieldAgent-THU（每调用约 600ms），防护开销仅占任务总时长的约 7.24%。
- **评估严谨**：包含数据泄漏分析、人类验证留出集、错误分析、重复稳定性、运行时成本等多维度证据，透明度和可信度较高。

## 8. 不足与局限

- **数据局限**：StepGen 依赖合成轨迹和 LLM 标注，可能继承教师模型的风险分类局限、偏差或标注错误；风险分类体系较固定，未覆盖所有可能的智能体风险。
- **评估局限**：静态与动态评估虽覆盖代表性设置，但未包含完全开放式的工具生态、更长时程工作流、多智能体交互或自适应对抗攻击者。
- **安全性边界**：StepGuard 是执行前防护而非正式安全保证，仍存在误报/漏报；部署中需要处理被阻止动作的修订策略，且新增推理成本。
- **规范类风险检测弱**：错误分析显示其对学术诚信、身份冒用等非技术性规范违规容易漏报，对被动复述可疑内容容易误报，说明安全边界仍偏重工具介导的技术性危害。
- **基准挑战未完全解决**：在 AgentHarm 等强对抗有害智能体场景中，安全–效用权衡尚不令人满意。
- **未报告多随机种子变异性**：论文的重复实验衡量的是相同 checkpoint 的评估管道波动，而非独立训练种子的模型稳定性。
