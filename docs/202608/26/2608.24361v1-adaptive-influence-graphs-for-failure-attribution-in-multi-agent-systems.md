## 摘要
多智能体LLM系统越来越多地部署在现实应用中，其中的故障可能代价高昂且难以定位。尽管自动化故障归因的努力不断增加，但诊断失败的运行仍然主要依赖人类工程师。然而，工程师很少通过从头到尾阅读原始日志来调试复杂系统。相反，可观测性工具围绕组件、动作和依赖关系组织追踪数据，以支持有针对性的导航。我们假设现代LLM也可以受益于同样的范式。为了验证这一假设，我们引入了自适应影响图（AIGs），这是一个两阶段的智能体框架，首先将失败的追踪数据转换为结构化图，然后导航该图以识别关键错误。在多个模型上，我们展示了更丰富的追踪表示能够持续改进故障归因，其中自适应图构建和智能体引导的遍历取得了最强结果。AIGs在Who&When这一多智能体故障归因的标准基准上确立了新的最先进水平。这证实了我们的假设：归因不仅取决于诊断模型，还取决于追踪数据的表示和探索方式。

## Abstract
Multi-agent LLM systems are increasingly deployed in real-world applications, where failures can be costly and difficult to localize. Despite growing efforts to automate failure attribution, diagnosing failed runs still largely relies on human engineers. Yet engineers rarely debug complex systems by reading raw logs end to end. Instead, observability tools organize traces around components, actions, and dependencies to support targeted navigation. We hypothesize that modern LLMs can benefit from the same paradigm. To test this hypothesis, we introduce Adaptive Influence Graphs (AIGs), a two-stage agentic framework that first transforms a failed trace into a structured graph and then navigates it to identify the critical error. Across multiple models, we show that richer trace representations consistently improve failure attribution, with adaptive graph construction and agent-directed traversal yielding the strongest results. AIGs establish a new state of the art on Who&When, the standard benchmark for multi-agent failure attribution. This affirms our hypothesis that attribution depends not only on the diagnosing model, but also on how the trace is represented and explored.

## 2. 方法论

### 2.1 总体框架
将故障归因解耦为两个阶段：
- **构建阶段（Build）**：将原始失败轨迹转换为结构化图（Structured Representation）
- **读取阶段（Read）**：诊断模型在图上进行定向探索，最终输出故障责任智能体和关键步骤

### 2.2 表示阶梯（四种级别的轨迹表示）

论文通过一个四层表示阶梯来隔离不同层次结构带来的收益，固定读取端为单次调用：

1. **原始日志（Raw Log）**：全部步骤以原文拼接的平铺序列。
2. **结构化日志（Structured Log）**：使用确定性、无 LLM 的规则，将同一智能体的连续步骤合并为一个节点，形成链式节点序列。每个节点保留原始步骤的逐字内容——只改变表面形式，不改变证据内容，从而隔离"显式结构"本身的收益。
3. **影响图（Influence Graph，IG）**：在结构化日志的基础上，用 LLM 在单次前向过程中为每个节点添加四字段抽象 α(v_k) = ⟨summary, input, output, authorship⟩（该节点做的事、收到的输入、产生的输出、在其中扮演的创作角色），并在存在继承关系（下游节点复用了上游节点的成果且与失败相关）时添加带注释的有向边。每条边带两个字段：inherited（被继承的元素）和 effect（该继承如何在下游出错）。边只在有继承时添加，可稀疏甚至为空。
4. **自适应影响图（Adaptive Influence Graph，AIG）**：将 IG 的固定单次构建过程替换为智能体式构建器。构建器从空图开始，通过两类工具与轨迹交互：
   - **检查工具 T_log**：get_overview、read_step、read_step_range、search 等（查询轨迹但不改动图）
   - **构建工具 T_build**：add_block、add_inheritance_note、modify_block、delete_block 等（增删改节点与边）
   
   构建器可自适应地选择节点边界（按动作而非固定分段合并步骤）、节点类型（task、orchestrator、agent、conclusion 四种类型，各自带不同字段）、继承边拓扑（可跨多个步骤连边）。图必须满足有效性谓词 Φ(G)：连通性、无环、单根、单汇。

### 2.3 批评—修正循环（Critic–Refiner Loop）
构建器提交图后，由批评者（critic）进行最多 R=3 轮审计：结构性违规通过程序化检查 Φ(G) 发现；语义性违规通过对照原始日志检查节点是否忠实于其引用的步骤。修正者（refiner）应用最小修改消除违规，直至违规集合为空或轮数耗尽。

### 2.4 读取端

- **单次调用读取（Single-call reader）**：将序列化的表示连同原始日志一并输入模型，输出一次归因结果。
- **智能体式图读取（Agentic graph reader）**：先获取图 G 的高层概览，再按需通过检查工具 T_log 选择性验证底层日志。读取器从图指示的候选节点出发，沿入向继承边回溯；仅当原始日志确认当前节点输出确实呈现出边的 effect 注释中所描述的错误时，才将责任回溯到边的源节点。当没有入向继承边能解释观察到的失败时，回溯停止。最终根据节点的 step_refs 和原始日志解析出精确的（智能体, 步骤索引）作为最终归因。

### 2.5 实现细节
- 每个阶段是独立的智能体，基于 Strands Agents SDK v1.37，工具是 Python 函数，图作为共享可变状态。
- 主模型为 Opus-5（默认报告），另测 Sonnet-4、DeepSeek-V3.2、GPT-5.6-sol。
- 通过 Amazon Bedrock Converse API 访问，无任务特定微调。

## 6. 主要结论与发现

1. **SOTA 突破**：AIGs（Opus-5）在 Algorithm-Generated 分区上达到 55.20% 精确步骤准确率和 71.20% 精确智能体准确率，比此前最佳（RAFFLES，Sonnet-4，51.60%）高出 3.6 个百分点。在 ±3 步宽容差下达到 84.00% 定位准确率。
2. **跨模型稳健**：GPT-5.6-sol（54.76%）、Sonnet-4（53.97%）、DS-V3.2（53.17%）均超越此前最高结果；与匹配模型的 CHIEF 对比，领先 7.57–9.96 个百分点。
3. **表示阶梯的单调收益**：从原始日志到结构化日志到影响图，精确步骤准确率持续提升（46.40% → 48.80% → 52.00%）。结构化日志即使不增加任何语义抽象、仅合并同智能体连续步骤，也带来显著提升——说明显式结构本身就有价值。
4. **自适应构建与智能体遍历缺一不可**：将自适应图展平为单次提示时仅 50.40%，而智能体式遍历同图达到 55.20%，说明图不仅是更丰富的提示，更扮演了"高层地图"加"选择性验证"的双重角色。
5. **收益集中在后期失败**：配对分析表明，步骤 ≥5 的后期失败中，AIGs 将 Sonnet-4 的精确步骤准确率从 10.8% 提升到 40.5%。错误预测中 76% 的智能体选择已正确，主要难点在精确定位步骤。
6. **构建器的行为特征**：AIG 相比固定 IG 图产生更多节点（9.5 vs 7.5）、更多边（13.5 vs 9.0）、更高的 hub 出度（3.6 vs 1.8）、更长的跨范围边（最长平均 5.6 vs 4.2 步），说明自适应构建确实产生了更丰富、更远距离连接且粒度可变的结构，而非简单细分或粗化。
7. **读取器行为**：61.3% 的首次读取步骤即最终提交步骤；86.5% 的执行进行了多步调查；仅 1.6% 直接由图提交而不验证。图聚焦搜索方向，但不替代证据验证。

## 7. 优点

- **视角创新**：将故障归因重新定义为"接口设计"问题，借鉴人类可观测性工具的实践范式迁移到自动化归因，视角新颖且有一定实践依据。
- **消融设计精巧**：四级表示阶梯在固定模型下逐级隔离"显式结构""影响语义""自适应构建""智能体遍历"各自的贡献，因果归因清晰。
- **跨模型验证充分**：在四个不同家族模型上分别验证，且在匹配模型上与 CHIEF、RAFFLES 等进行了直接对比，增强了结论的普适性。
- **训练免费**：整个 AIGs 管线是纯提示驱动的（prompt-only），无任务特定微调，应用门槛低。
- **分析深入**：不仅报告最终准确率，还对构建出的图结构（节点、边、跨距、hub）和读取器的交互行为做了细粒度追踪与统计，使方法内部机理透明化。
- **评估的宽容差视角**：补充±1/±2/±3 步的容差评估，提供了更全面的定位性能画像。

## 8. 不足与局限

- **基准覆盖有限**：仅在 Who&When 两个分区上评估，且 Hand-Crafted 分区上智能体准确率未超过 CHIEF（63.79% vs 72.41%），泛化性有待更多 benchmark 验证。
- **不完全可观测假设**：Who&When 只暴露智能体的输出，不暴露每个智能体实际看到的输入和工具日志。在更可观测的数据集（如 Chen et al., 2026b）上结论可能变化，作者预期会更好但未验证。
- **图质量无法直接评估**：缺乏节点粒度或继承边的金标准标注，图的正确性只能通过下游准确率和批评者间接验证。
- **计算成本未量化**：构建阶段 + 批评—修正循环增加了额外 token 开销，论文未给出端到端成本与原始日志读取的定量对比，限制了实际部署时的性价比判断。
- **公平性瑕疵**：跨方法对比中，不同方法使用了不同模型（如 RAFFLES 在 Llama-3.3-70B 上是 43.65%、在 Sonnet-4 上是 51.60%），模型差异与方法差异混杂，虽在匹配模型对比中做了部分弥补，但并非所有对比都对等。Hand-Crafted 分区某些数字来自不同来源（如 CHIEF 在 DS-V3.2 上的 29.31% 与其在 Opus-5 上的 18.97% 差异显著），直接横向比较需谨慎。
- **ground-truth 接入效果不稳定**：提供正确最终答案反而使 AIGs 性能略降（如表 8 所示），作者将之归因于噪声或与既有基线一致的现象，但这一行为缺乏深入解释。
- **步骤粒度定义依赖基准**：步骤索引粒度由基准定义，实际系统中"关键步骤"的概念可能更模糊或分层，方法的直接迁移性有待考察。
