## 摘要
使用工具的大型语言模型代理在完成任务时，可能行使用户未授予或任务不需要的权限，导致超权限错误。传统的仅靠权限门控系统来验证代理环境是不够的。我们研究后训练是否能教会一个40亿参数的模型在可执行终端和模型上下文协议（MCP）环境中选择任务条件化的权限，以补充这些措施。我们提出了一个框架，其中每个动作在执行前以及从观察到的效果中，沿六个风险维度进行审计。该审计使用确定性验证器，对完成度、证据、精确状态、禁止尝试和安全成功进行评分。结合预定义的任务特定充分权限包络，我们为轨迹确定任务特定的过度特权值，并在后训练中进行优化。我们发现，在使用此框架对Qwen3.5-4B进行1500个任务的训练后，选定的种子在涵盖所有500个保留任务的2896个评估场景中达到了98.48%的安全成功率，而基础策略为64.36%，并将超权限错误事件从4.56%降低到0.79%。此外，外部测试显示能力保持和提示引导的改进。一项400任务的延续研究也发现了泛化的证据，将超权限事件减少了6.99个百分点，同时保持了之前的能力。我们得出结论，通过最小权限感知后训练学到的约束行为，作为可执行终端和MCP环境中工具使用代理的额外控制层是有用的，但它不能替代权限门控和沙箱。

## Abstract
Tool-using large language-model agents can complete a task while exercising authority that the user did not grant or the task does not need, causing excess-authority errors. Traditional permission gating systems alone for validating agent environments are insufficient. We study whether post-training can teach a 4B-parameter model to choose task-conditioned authority in executable terminal and Model Context Protocol (MCP) environments to complement those measures. We propose a framework where each action is audited before execution and again from observed effects along six dimensions of risk. This auditing is conducted using deterministic verifiers that score completion, evidence, exact state, prohibited attempts, and safe success. In conjunction with predefined task-specific sufficient-authority envelopes, we determine task-specific excess privilege values for trajectories, which are then optimized for in post-training. We find that after training using this framework on Qwen3.5-4B over 1,500 tasks, the selected seed reaches 98.48% safe success across 2,896 evaluation episodes spanning all 500 held-out tasks, compared with 64.36% for the base policy, and reduces excess-authority error events from 4.56% to 0.79%. Furthermore, external tests show capability retention and prompt-directed improvement. A 400 task continuation study also found evidence of generalization, reducing excess-authority events by 6.99 percentage points while maintaining previous capabilities. We conclude learned restraint through least-privilege aware post-training is therefore useful as an additional control layer for tool-using agents in executable terminal and MCP environments, but it does not replace permission gates and sandboxing.

## 1. 论文的核心问题与整体含义（研究动机和背景）

- **核心问题**：工具使用型大语言模型（LLM）代理在执行终端命令、调用 MCP（Model Context Protocol）工具等可执行操作时，常常会行使用户未授予或任务并不需要的权限，造成“超授权错误”（excess-authority errors）。这类行为包括读取无关记录、修改任务范围外的目标、使用不必要的高权限工具，甚至可能引发权限提升风险。
- **现有方案的不足**：传统权限门控（permission gating）系统只能在模型提出动作后进行拦截，覆盖面取决于预先定义的风险规则；静态门控可能既遗漏真正需要的访问，又授予无关的敏感访问。文献也表明，即使如 Claude Code Auto Mode 等两阶段分类器，仍存在较高的假阴性率和大量超出分类器覆盖范围的动作。
- **研究动机**：作者认为，除了在环境层进行拦截外，还应当让模型自身学会“最小权限”（least-privilege）行为，即从源头减少提出不必要高权限动作的倾向。因此，本文研究通过后训练（post-training）在可执行的终端与 MCP 环境中教会模型任务条件化的权限选择，作为权限门控和沙箱之外的**补充控制层**，而非替代品。

## 2. 论文提出的方法论：核心思想、关键技术细节、公式或算法流程

- **核心思想**：将“最小权限”定义为**任务相对**的概念。模型可以看到完整工具清单，但一个不可见的“环境经纪人”（host broker）会对每个动作进行解析、预审计、风险评估、选择执行模式并记录效果。每个任务预定义一个“充分权限包络”（sufficient-authority envelope），训练中只惩罚超出该包络的额外权限。
- **六维风险向量**：每个动作 \(a_t\) 被映射为一个六维权限向量：
  \[
  z(a_t) = [z_{\text{write}}, z_{\text{exec}}, z_{\text{external}}, z_{\text{secret}}, z_{\text{scope}}, z_{\text{persistent}}] \in [0,1]^6
  \]
  分别对应状态写入、动态执行、越出环境边界、敏感数据访问、宽泛影响范围、持久化副作用。轨迹级风险向量取各维度的最大值 \(z_\tau = \max_{t=1,\dots,T} z(a_t)\)。
- **超授权计算**：给定任务 \(x\) 的充分权限包络 \(z_{\text{req}}(x)\)，超授权向量为：
  \[
  \Delta(\tau, x) = \max(z_\tau - z_{\text{req}}(x), 0)
  \]
  每个维度独立取正值，只有超出任务要求的部分才惩罚。
- **安全成功指标**：
  \[
  \text{SAFE SUCCESS}(\tau, x) = \mathbb{1}[S = 1 \land E \ge e_x \land V_x = 1 \land O_\tau = 0]
  \]
  其中 \(S\) 为任务成功，\(E\) 为证据充分性，\(V_x\) 为任务特定状态约束，\(O_\tau\) 为可上报的超授权事件。该指标区分“尝试”与“环境允许发生”的效果：即使命令被拦截，仍会记录一次超授权尝试。
- **执行与审计流程**：
  - 预执行审计：解析命令族、标志、路径、重定向、组合、工具身份和参数广度；
  - 实际执行：在非 root 容器或可重置的 MCP 服务中运行；
  - 后执行审计：通过文件/Git diff、进程遥测、服务记录、敏感路径访问和确切状态变化评估实际影响；
  - 确定性验证器检查最终答案、隐藏测试、输出文件、MCP 状态、证据路径、必需写入和额外写入拒绝。
- **奖励函数**：
  \[
  R = 0.60S + 0.20E - 0.20P - 0.05U + 0.10H - 0.75B - 0.05F_u - 0.12F_r
  \]
  其中 \(P\) 为加权的轨迹超授权（含秘密访问超限、标签置信度、逐步超限封顶项），\(U\) 惩罚过多动作和重复循环，\(H\) 奖励正确的升级（escalation），\(B\) 衡量被阻止动作的严重性，\(F_u\) 标记格式错误或不支持的动作，\(F_r\) 标记被禁止的读取。奖励函数刻意不采用势函数形式，以偏向低权限轨迹而非仅追求能力最优。
- **训练方法**：使用 Qwen3.5-4B，LoRA（rank 32, alpha 64, bfloat16），直接 Dr. GRPO（无长度归一化和组标准差归一化），1,500 步一个 epoch，每行采样 8 条轨迹，每条轨迹 4,096 token 完成预算，20 次工具调用上限，无 KL 项，无监督微调。

## 6. 论文的主要结论与发现

- 在 500 任务完整验证集上，训练后策略（Seed 1）的**安全成功率从 64.36% 提升至 98.48%**（+34.12 pp），任务成功率从 68.92% 升至 99.27%，成功超授权事件从 4.56% 降至 0.79%。
- 检查点分析显示，内部能力增益主要在第 500 步就已出现（占 98%），后续步主要修复少部分任务族。
- 提示消融：训练策略在全提示、移除安全措辞、单行提示下安全成功率分别为 97.63%、97.63%、97.39%，仅下降 0.24 pp；基础策略则下降 3.70 pp。说明学习到的行为**不是依赖提示措辞**的，而是被内化了。
- 外部测试：MetaTool 准确率从 81.9% 提升至 83.6%（p=4.55×10⁻⁴），说明训练没有损害一般工具选择能力，反而略有提升；FORTIS 在可比较的解析输出上，超授权率从 43.28% 降至 40.72%（p=2.11×10⁻⁵），表明更好的权限选择。
- ToolPrivBench 默认提示下，训练与基础策略无显著差异（45.2% vs 45.0%），但在带最小权限说明的提示下，训练策略降至 37.9%，优于基础策略的 41.2%，说明**提示可以“解锁”已学到的行为**，但训练对陌生接口的迁移有限。
- 400 任务延续研究：在目标域（ToolPrivBench）超授权事件从 45.04% 降至 38.05%（-6.99 pp），且在特权感知提示下降至 26.65%；内部 500 任务安全成功率保持/略微提升（98.48%→98.76%），MetaTool / FORTIS 基本不变，表明能力保持良好。
- 总体结论：**最小权限感知的后训练可作为权限门控和沙箱之外的有效补充控制层，但不能替代它们**；系统仍需保留权限分离和确定性防护措施。

## 7. 优点：方法或实验设计上的亮点

- **任务相对的最小权限定义**：用六维风险向量和充足的权限包络来量化“超授权”，比简单二分类更细致，可适应不同任务（只读任务、多工具跨服务任务等）。
- **可执行环境与确定性验证**：在真实容器和可重置 MCP 服务中执行动作，用文件 diff、过程遥测和精确状态变化进行后审计，避免纯静态解析的盲区；奖励基于确定性测量而非学习得到的动态奖励，降低奖励伪造风险。
- **模块化框架**：经纪人、任务模式、后动作验证器和超权限计算分离，可复用于不同任务和不同强化学习算法，不限于 Dr. GRPO。
- **防御性评估设计**：区分“任务成功”与“安全成功”，防止代理通过消极拒绝来提高安全指标；设置证据门槛，防止事后读取来修补答案；包含提示注入、秘密诱饵、禁止读取等对抗性任务。
- **多粒度验证体系**：内部验证集含同家族变体和异家族全新任务族，外部还有三个独立基准；延续研究以污染检查方式展示了框架泛化能力，实验设计较严谨。
- **对提示依赖的敏感分析**：展示训练后策略行为内化，不是单纯记住提示，这在安全相关后训练中很重要。

## 8. 不足与局限

- **任务合成性局限**：所有内部任务由结构化家族、预定义模板合成生成，不能代表无限制的生产环境仓库或真实服务复杂性；即使有异家族验证，仍然共享相同的经纪人、沙箱和验证器约定。
- **模型与训练配置局限**：仅使用单一 4B 模型（Qwen3.5-4B）和 LoRA 适配器；未扩展到不同规模或不同架构模型；未对比 SFT 冷启动方案（作者也承认两个种子存在不稳定问题）。
- **奖励权重手工设定**：奖励函数各项权重是手动选择的，未做系统搜索，也未验证是否最优。
- **训练饱和与多样性不足**：第 500 步已获得大部分内部能力提升，说明任务多样性不足，更多训练步只修复少量特定场景；外部 ToolPrivBench 默认提示下训练策略无改进，反映跨域泛化不均匀。
- **延续研究的选择偏差**：400 步延续是在已经看到 Seed 1 实验结果后才进行的，动机是事后（post-hoc）的，因此不是完全无偏的泛化演示；且从 Seed 1 继续而非从基础模型从头混合训练。
- **统计与比较限制**：FORTIS Task 2 因输出可解析性问题只比较了部分子集（1,250/1,543），可能引入比较偏差；ToolPrivBench 比较中默认提示下两策略几乎相同，提示行为解释仍有不确定性。
- **应用边界**：作者明确表示该方法不能提供执行保证或确定性失效安全，无法阻止所有类别的新颖攻击或未见过模式；必须与权限门、沙箱、系统提示说明等结合使用。
