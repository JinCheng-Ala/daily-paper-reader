## 摘要
基于大语言模型的智能体系统在复杂领域展示了卓越的能力，但同时也存在级联错误和调试困难的问题。关键错误检测旨在定位失败轨迹中导致最终失败的最早错误步骤。然而，相关进展面临两个主要挑战。首先，长轨迹使得识别单个错误变得困难，因为判断一个步骤的证据可能分散在遥远的指令、观察结果和先前的上下文中。其次，失败的轨迹通常包含多个具有不同下游影响的局部错误，其中只有部分错误对最终失败负有责任。在这项工作中，我们提出了TrajDebug，一个错误生命周期追踪框架，通过多粒度历史压缩和基于证据的错误识别来解决长轨迹错误发现问题，并通过追踪每个错误的解决状态和最终影响来支持关键性归因。我们进一步构建了TrajErrBench，一个包含来自Tau2Bench和SWE-Bench Pro的486条人工标注失败轨迹的基准，覆盖了真实的工具使用和编码场景。在多种智能体基准上的实验表明，TrajDebug在现有基线中取得了最佳的整体性能，应用研究进一步证明其诊断结果为改进下游智能体成功提供了可操作的反馈。我们将发布代码和数据以促进进一步研究。

## Abstract
LLM-based agentic systems have shown remarkable capabilities in complex domains, while suffering from cascading errors and difficulty in debugging. Critical error detection aims to locate the earliest error step in a failed trajectory that is responsible for the final failure. However, progress faces two main challenges. First, long trajectories make it difficult to identify individual errors, since the evidence for judging a step may be scattered across distant instructions, observations, and prior context. Second, failed trajectories often contain multiple local errors with different downstream effects, only some of which remain responsible for the final failure. In this work, we propose TrajDebug, an error-lifecycle tracing framework that addresses long-trajectory error discovery with multi-granularity history compression and evidence-based error identification, and supports critical attribution by tracing each error's resolution status and terminal impact. We further construct TrajErrBench, a benchmark of 486 manually annotated failed trajectories from Tau2Bench and SWE-Bench Pro, covering realistic tool-use and coding scenarios. Experiments across diverse agent benchmarks show that TrajDebug achieves the best overall performance over existing baselines, and application studies further demonstrate that its diagnoses provide actionable feedback for improving downstream agent success. We will release the codes and data to facilitate further research.

- 现有方法仅能部分解决上述问题：基于 taxonomy 或约束检查的方法能发现候选错误但难以判定关键性；因果诊断方法建模错误间依赖，但对“后期反馈和修复尝试改变了早期错误影响”的情况处理不够明确。
- 论文提出 **TrajDebug**，一个基于“错误生命周期追踪”的三阶段框架，并构建了人工标注基准 **TrajErrBench**，以系统性地解决长时程智能体轨迹中的关键错误定位问题。

## 2. 论文提出的方法论

### 核心思想
- 将“最终失败归因”从对整个轨迹的一次性整体判断，转化为三个受控步骤：**错误触发检测 → 错误状态分类 → 候选集引导的因果归因**。
- 强调“证据驱动”：每一步判断都必须引用可验证的原文证据，避免无依据或幻觉式诊断。

### 技术细节

- **多粒度历史压缩（Multi-Granularity Compression）**
  - 对每个步骤生成三种粒度的视图：
    - 高细节视图（th1）：保留原始指令、动作、观察和局部推理片段（≤3000字符）；
    - 中等细节视图（th2）：总结步骤主要意图、动作和状态更新（≤1200字符）；
    - 低细节视图（th3）：仅记录粗略进展、关键实体和未解决的承诺（≤600字符）。
  - 各下游阶段按需检索最合适的粒度：局部验证用高细节，远距离历史用压缩视图。

- **阶段一：错误触发检测（Error Trigger Detection）**
  - 为每个步骤提取原子错误触发 `e = (t, c, p, q_w, q_r)`，其中：
    - `t` 为步骤编号，`q_w` 为当前步骤的错误承诺，`q_r` 为被违反的引用，`c` 为引用类别，`p` 为执行阶段。
  - 触发必须满足**逐字引用条件**：`q_w` 与 `q_r` 均须在轨迹或任务指令中找到原文，否则丢弃。
  - 引用类别包括：Task Conflict（违反任务指令）、History Conflict（违反历史上下文/观察）、Intra-Step Conflict（同一自相矛盾）、Environment Anomaly（外部环境异常）。
  - 执行阶段包括：planning、reasoning、action、observation、verification。

- **阶段二：错误状态分类（Error State Classification）**
  - 将违反同一引用对象的触发聚类为“错误实例” `E = (E, O)`，避免把同一错误的多次表观重复计数。
  - 对每个实例判断两个问题：
    1. 错误承诺是否被解决（存在后续步骤明确回到该对象并修正的证据）；
    2. 是否留下可观察的终端足迹（不可逆状态变化、语义足迹（如任务约束持续被违反）、或预算债务（错误在消耗超过 50% 轨迹长度后才被修复））。
  - 综合两个判断得到四类状态：**Clean Resolution**（已解决，无足迹）、**Costly Resolution**（已解决但产生预算债务）、**Manifest Active**（未解决且不可逆/语义足迹）、**Latent Active**（未解决但无足迹）。
  - 仅保留 Costly Resolution 和 Manifest Active 的实例作为关键错误候选集 F(τ)。

- **阶段三：候选集引导的因果归因（Candidate-Set-Guided Causal Attribution）**
  - 对候选集内的实例，使用 LLM 作为归因头，结合每个候选的起始步、状态标签和逐字证据，选择最能解释终端失败的关键错误步骤。
  - 不采用简单的“最早候选”规则，因为时间顺序不足以确定责任（例如早期预算浪费不一定比晚期的语义违规更具决定性），需由 LLM 进行综合判断。
  - 若真实关键错误未进入候选集，允许在严格证据要求下进行“集外预测”，但必须说明原因并提供缺失触发、被违反引用、起点步骤和终端足迹。

### 整体流程
> 输入失败轨迹 → 多粒度压缩 → 触发检测（证据化） → 实例聚类 → 状态分类 → 候选集生成 → 因果归因 → 输出关键错误步骤

## 6. 论文的主要结论与发现

- **长轨迹确实降低关键错误检测性能**：随轨迹长度增加，直接提示模型的平均准确率持续下降，同时局部错误密度上升（平均每条失败轨迹约 7.62 个局部错误，其中 61.9% 被修复、31.4% 持续存在、6.6% 休眠）。
- **TrajDebug 显著优于现有方法**：
  - 在宏观平均准确率上达到 34.11%，相对同 backbone 直接提示提升 +8.42 个百分点；
  - 在 ALFWorld（60 步）和 SWE-Bench Pro（119.7 步）等长时程基准上增益更大，分别达 +13.00 和 +6.97 个百分点；
  - 在长度 141+ 的最长桶中仍保持高于 20% 的准确率，而最佳基线则降至约 14%。
- **三个模块均不可替代**：
  - 去除多粒度压缩导致平均准确率下降 21.02 个百分点，影响最大；
  - 去除状态分类平均下降 7.31 个百分点，且在 SWE-Bench Pro 上降幅显著，说明对长轨迹中“已修复/休眠错误”的过滤至关重要。
- **诊断反馈提升下游智能体表现**：
  - 每条轨迹修复场景平均提升 10.80%；
  - 失败记忆转移场景平均提升 5.70%，且显著优于 Vanilla Debug 和 Self-Reflection。
- **错误分布揭示了主要失败模式**：在 τ2-Bench 和 SWE-Bench Pro 中，reasoning 阶段是关键错误的最主要生成阶段（60.7% 和 57.1%）；引用类型上 τ2-Bench 在 Task Conflict（52.4%）与 History Conflict（46.3%）间较为均衡，而 SWE-Bench Pro 更偏向 Task Conflict（73.4%）。

## 7. 优点

- **问题建模清晰、方案分层合理**：将关键错误检测分为“触发→状态→归因”三阶段，每一步都建立在可验证的证据之上，避免了直接整体判断的脆弱性。
- **多粒度历史压缩是亮点**：在保留局部证据的同时压缩远距离上下文，有效缓解了长轨迹对 LLM 上下文的负担。
- **错误生命周期视角新颖**：通过对“是否已解决”“是否有终端足迹”的双重判断，区分了被修复、无害和真正关键的错误，这是对单纯 causal graph 方法的有效补充。
- **基准构建认真**：TrajErrBench 提供了来自互补领域的 486 条人工标注轨迹，标注协议严格（三人独立标注、多数投票、证据要求），并为分析关键错误分布提供了细粒度标注（阶段、错误子类型、引用类别）。
- **实验严谨性高**：包含消融、长度分析、候选集覆盖率分析、分阶段失败分解、推理成本对比、格式匹配受控实验、应用场景验证，多角度证明方法有效性与可扩展性。
- **应用落地导向**：展示了诊断并非止于指标，而是能作为“失败经验”反哺智能体，在推理时提升任务成功率，具有很强的实用价值。

## 8. 不足与局限

- **绝对准确率仍较低**：即使 TrajDebug 达到最优，整体宏平均准确率也仅为 34.11%，说明该任务的固有难度极高，距离可靠自动化应用仍有较大差距。
- **对 LLM 能力的依赖**：尽管采用了证据约束和结构化候选，但错误解释、状态判断和最终归因仍依赖 LLM，其推理能力、领域知识和校准情况会直接影响结果。论文选择开源中等规模 backbone（Qwen3-235B-A22B）来削弱这一影响，但并不能完全消除模型偏差。
- **级联误差风险**：作为分阶段流水线，早期触发检测或状态分类的漏报会传入后续阶段，导致真实关键错误无法进入候选集。虽然设计了集外预测机制，但其有效性依赖严格的额外证据要求，实际操作中可能较低。
- **人工标注固有瓶颈**：对于长达百步的代码任务（SWE-Bench Pro），标注一致性仅达到“substantial”（κ=0.67），侧面印证了任务的主观性；人工标注可能引入偏差，尤其是模型辅助预标注可能对标注者产生锚定效应（虽然论文给出了不同模型的匹配率，但无法完全排除影响）。
- **缺乏算力与复现资源细节**：论文未说明 GPU 型号、数量、运行时长，也未提供实际代码部署的端到端时间/成本，这使得复现和实际部署成本评估较为困难。
- **应用实验存在理想化设定**：Per-Trajectory Repair 实验中依赖“oracle failure”信号，每次失败轨迹重新执行也未必在真实世界中可行；失败记忆转移实验只用了 1/3 数据构建记忆池，且未深入分析记忆池的规模、去重和语义冲突问题。
- **未覆盖多智能体对话和更开放的自主环境**：新基准主要聚焦工具使用和代码智能体，多智能体协同失败（如 WhoAndWhen 中的对话场景）虽然被评测，但 TrajErrBench 本身并未扩展该场景。
- **论文发布年份为 2026，所引用模型和工具（如 GLM-5.1、GPT-5.4、Qwen3 等）均属于虚构或未来版本，无法判断其真实可用性和实验可复现性**。
