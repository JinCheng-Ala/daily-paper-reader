## 摘要
计算机使用智能体（CUA）通过截图、鼠标和键盘操作以及有状态的UI反馈来操作真实的桌面和网页界面，但其故障仍然难以诊断和修复。与纯文本智能体不同，CUA故障源于视觉感知、空间定位、底层交互、任务推理和环境动态的耦合，使得调试成为一个独特的多模态因果定位问题。我们提出了CUADebug，一个用于诊断和修复CUA故障的框架。CUADebug包含一个CUA特定的错误分类法、CUAErrorBench（一个人工标注的OSWorld故障基准）以及CUADebugger（一个工具增强的调试器）。CUADebugger不是一次性对整个轨迹进行提示，而是主动检查带有前后截图和操作痕迹的可疑步骤，然后提交包含根因步骤、错误类型、基础证据和纠正策略的结构化诊断，以重新执行。对204条失败轨迹的人工标注显示，任务推理和控制是最大的故障类别（110/204），其次是感知（36）、定位/交互（25）、外部/系统（13），以及一个包含20个OSWorld不可行任务案例的其他类别。在主要的Claude智能体划分中，CUADebugger使用Gemini 2.5 Pro将联合子类型和步骤诊断从11.2%提高到19.6%，并且在不同的调试器主干上持续改进。在单次重新执行包评估中，基于RCA的条件比仅历史延续实现了更高的任务完成率（机器RCA为28.47%，我们的方法为29.90%，而仅历史延续为13.89%）；在持续重新执行中，我们的方法将成功率从12.2%提高到25.86%，而人类专家指导达到29.21%。这些结果表明，CUA根因诊断可以提供可操作的修复信号，而不仅仅是事后解释。

## Abstract
Computer-use agents (CUAs) operate real desktop and web interfaces through screenshots, mouse and keyboard actions, and stateful UI feedback, yet their failures remain difficult to diagnose and repair. Unlike text-only agents, CUA failures arise from coupled visual perception, spatial grounding, low-level interaction, task reasoning, and environment dynamics, making debugging a distinctive multimodal causal localization problem. We introduce CUADebug, a framework for diagnosing and repairing CUA failures. CUADebug includes a CUA-specific error taxonomy, CUAErrorBench, a human-annotated OSWorld failure benchmark, and CUADebugger, a tool-augmented debugger. Instead of prompting over the full trajectory once, CUADebugger actively inspects suspicious steps with paired before/after screenshots and action traces, then submits a structured diagnosis containing the root-cause step, error type, grounded evidence, and corrective strategy for re-execution. Human annotations over 204 failed trajectories show that task reasoning and control is the largest failure family (110/204), followed by perception (36), grounding/interaction (25), external/system (13), and an others category of 20 OSWorld infeasible-task cases. On the main Claude-agent split, CUADebugger improves joint subtype-and-step diagnosis from 11.2% to 19.6% with Gemini 2.5 Pro and improves consistently across debugger backbones. In single re-execution package evaluation, RCA-based conditions achieve higher task completion than history-only continuation (28.47% with machine RCA and 29.90% with our method, versus 13.89%); in continual re-execution, our method improves success from 12.2% to 25.86%, while human-oracle guidance reaches 29.21%. These results show that CUA root-cause diagnosis can provide actionable repair signals rather than merely post-hoc explanations.

## 1. 论文的核心问题与整体含义（研究动机和背景）

- **核心问题**：计算机使用智能体（Computer-Use Agent, CUA）在真实桌面和网页界面上通过截图、鼠标键盘操作与 UI 反馈执行任务时，其故障难以诊断和修复。与纯文本智能体不同，CUA 故障由视觉感知、空间定位、底层交互、任务推理和环境动态等多重因素耦合而成，形成一种独特的**多模态因果定位问题**。
- **关键挑战**：传统端到端基准（如 OSWorld、WebArena、Mind2Web 等）只能衡量任务是否成功，无法解释失败原因；而错误分类学虽能给出错误类型，但无法定位到具体的根因步骤和证据。CUA 轨迹中的错误信号可能早于最终失败症状出现，需要结合截图、空间目标、底层动作和屏幕时序转换进行因果判断。
- **研究意义**：论文主张 CUA 根因诊断不应止步于"事后解释"，而应提供**可操作的修复信号**，能够指导重新执行（re-rollout），从而真正提升智能体的任务完成能力。

## 2. 论文提出的方法论：核心思想、关键技术细节、算法流程

### 2.1 总体框架：CUADebug

CUADebug 是一个完整的 CUA 故障诊断与修复框架，包含三个核心组件：

| 组件 | 功能 |
|------|------|
| **CUA 错误分类法（Taxonomy）** | 定义两级错误分类体系：5 个顶级模块 + 30 个细分子类型，作为标注、诊断、记忆检索和评估的统一标签空间 |
| **CUAErrorBench** | 人工标注的 OSWorld 失败轨迹基准，每条样本包含根因步骤、分类标签、证据、纠正策略和置信度 |
| **CUADebugger** | 工具增强的根因分析（RCA）智能体，通过 ReAct 循环主动检查可疑步骤并产出结构化诊断 |

### 2.2 错误分类法

- **五个顶级类别**：
  - **P（感知）**：误解了观察中的可见内容（幻觉、OCR 错误、语义误读等）
  - **G（定位与交互）**：意图正确但目标或交互机制错误（坐标错误、隐藏目标、点击类型错误等）
  - **R（任务推理与控制）**：选择了错误计划或未能维持正确计划（约束违反、缺失子目标、动作-意图不匹配、错误的自我纠错等）——**占比最大**（110/204）
  - **S（外部/系统）**：环境、工具或基准设置阻止了本应有效的进展
  - **O（其他）**：不属于 P/G/R/S 的故障，目前主要是 OSWorld 中的不可行任务
- **细分子类型**：共 30 个，例如 P2（OCR误识别）、G1（坐标/元素定位错误）、R10（进度误判）、S7（基准/评估伪影）等。

### 2.3 CUADebugger 工作流程

```
失败轨迹 → 工具引导的多模态检查 → 结构化 RCA 记录 → （可选）情景记忆检索 → 调试器引导的重新执行
```

1. **多模态步骤检查工具（`get_step_details(n)`）**：
   - 返回第 n 步的完整配对信息：动作代码、智能体推理、执行错误/奖励、以及**动作前截图**和**动作后截图**。
   - 将前后截图与智能体意图进行对比，可暴露纯文本轨迹无法揭示的感知、定位和结果误判错误。

2. **结构化根因提交工具（`finish()`）**：
   - 强制输出完整 RCA 记录：根因步骤号 N、L1/L2 分类标签、有据可依的证据、具体纠正策略、校准置信度（0-1）、以及每个已检查步骤的意图/结果摘要。
   - 感知步骤摘要会传递给重新执行的智能体，使其继承调试器的轨迹解读。

3. **情景记忆与检索增强调试**：
   - 从每次失败的轨迹中蒸馏出可复用的记忆单元（触发条件、失败动作、纠正动作、区分特征、证据、源事件引用等）。
   - 检索时按应用 ID、分类标签、触发条件等索引，但检索结果仅作为**候选证据**，模型必须与当前截图和轨迹比对后决定是否采用。
   - 冷启动阶段从人工标注蒸馏记忆，后续可吸收成功的 RCA 输出或对比性轨迹对。

4. **调试器引导的重新执行（Re-Rollout）**：
   - 将原轨迹回放到同一截止状态，固定剩余步骤预算，但为执行智能体注入：轨迹摘要、已检查步骤摘要、以及包含根因步骤/错误类型/证据/纠正策略的"修复配方"。
   - 主要目标是验证 RCA 是否具有**行为学上的可操作性**——如果诊断包含真正的因果修复信息，重新执行应能避免重复相同的失败模式。

## 3. 实验设计

### 3.1 数据集与基准

- **基础环境**：OSWorld（LibreOffice、Chrome 等桌面应用的真实 GUI 任务），这是 CUA 领域广泛使用的端到端基准。
- **轨迹来源**：三种 CUA 智能体产生的失败轨迹：
  - Claude 4.5 Sonnet：144 条（50 步轨迹）
  - Gemini 2.5 Pro：30 条
  - Qwen 3.5：30 条
  - **合计 204 条可用人工标注轨迹**，每条由多名标注者标注并在分歧后统一为最终参考标签。
- **标注内容**：根因步骤、L1/L2 分类标签、文本证据、纠正策略、置信度。

### 3.2 对比方法

| 方法 | 描述 |
|------|------|
| **Naive Baseline** | 从完整轨迹 + 分类学一次性提示模型输出 RCA 记录（无工具访问） |
| **CUADebugger** | 使用 ReAct 循环 + 步骤检查工具 + 结构化提交工具进行 RCA |
| **Baseline（直接延续）** | 仅提供任务和轨迹历史，直接继续执行 |
| **Self-debug** | 要求执行智能体自行诊断上一步失败并继续 |
| **Machine RCA** | 使用机器生成的 RCA（无记忆检索）注入修复配方 |
| **Human oracle RCA** | 使用人工标注的 RCA 注入修复配方 |
| **Our method** | 使用带记忆/RAG 增强的完整 CUADebugger RCA 包 |

### 3.3 评估协议

- **RCA 评估指标**：L1 准确率（顶级分类一致）、L2 准确率（精确子类型一致）、Step Exact（根因步骤精确匹配）、Step ±2（根因步骤在人工标注±2 步内）、Tag+Step Exact（L2 子类型 + 步骤精确匹配）。
- **单次重新执行评估**：从根因步骤前一步重启，固定步骤/Token 预算。主要指标为 **New+Fixed**（原始关键错误被修复但出现新错误 / 原始关键错误被修复且无新错误）和 **Re-rollout Acc**（任务完成率）。
- **持续重新执行评估**：从第 51 步开始继续执行 50 步失败的轨迹，衡量任务完成率和根因错误修复情况。
- **分类学演化实验**：让 LLM 从零开始自主演化分类法，比较不同随机种子顺序下的收敛性。

## 6. 论文的主要结论与发现

1. **CUA 失败高度集中于任务推理与控制，但仍呈多模态分布**：
   - 推理/控制类（R）占比 53.9%（110/204），感知类（P）36 例，定位/交互类（G）25 例，外部/系统类（S）13 例，其他/不可行（O）20 例。
   - 说明 CUA 故障不能简化为纯文本规划错误，必须将视觉感知和空间交互纳入诊断体系。

2. **CUADebugger 显著提升联合诊断准确率**：
   - 在主要的 Claude 4.5 Sonnet 划分中，使用 Gemini 2.5 Pro 作为骨干时：
     - L2 准确率：30.1% → 37.1%
     - **Tag+Step Exact（联合子类型 + 精确步骤）：11.2% → 19.6%，接近翻倍**
   - 不同调试器骨干（Gemini 2.5 Pro、Qwen 3.5、Claude 4.5 Sonnet）上均有提升，表明主动步骤检查优于一次性全轨迹提示。

3. **结构化 RCA 具备行为修复价值**：
   - 单次重新执行：Machine RCA 28.47%，Our method 29.90%，显著优于仅历史延续的 13.89% 和 Self-debug 的 15.28%。
   - 持续重新执行：Baseline 12.20% → Self-debug 14.20% → Machine RCA 21.53% → **Our method 25.86%**，接近人类专家指导的 29.21%。

4. **自主分类学演化不稳定**：
   - 不同随机顺序下 LLM 自主演化的分类法**命名层面零收敛**；完整种子运行 144 个案例后仍产生 40 个子类型且曲线仍在上升。
   - 语义层面有部分收敛（映射回基准标签空间可恢复 15%–28% 的类别），但无法形成稳定模式 → **人工标注不仅是劳动投入，更是不可替代的结构性要求**。

5. **工具增强诊断优于无工具提示**：主动使用前后截图配对检查比一次性展示完整轨迹更有效。

## 7. 优点

1. **问题定义清晰且具有独特性**：聚焦于 CUA 的多模态因果定位问题，而非通用智能体错误分析，填补了现有研究的重要空白。
2. **CUA 专属的两级分类法设计合理**：顶级模块（P/G/R/S/O）分离了"错误来源"与"最终症状"，细分子类型支持精细评估和记忆检索。
3. **工具增强的诊断流程设计巧妙**：`get_step_details` 将前后截图配对呈现，直接暴露纯文本轨迹无法捕获的感知/定位/交互错误；`finish()` 的强制结构化输出保证了诊断的完整性和可用性。
4. **诊断与修复的闭环验证**：通过单次和持续重新执行将 RCA 从"解释"转化为"干预"，是对现有调试研究的重要方法论改进。
5. **分类学演化实验非常具有洞察力**：直接证明了自主分类法演化无法收敛，为人工标注的必要性提供了实证依据。
6. **情景记忆设计实用**：将记忆检索定位为"候选证据"而非权威标签，并要求模型对比触发条件与当前轨迹，降低了错误迁移的风险。
7. **代码开源**：论文附录提供了完整的提示模板、工具 Schema 和实现文件路径，可复现性强。

## 8. 不足与局限

1. **跨智能体样本量不均衡**：Gemini 和 Qwen 轨迹各仅 30 条，跨智能体的 RCA 结果应视为初步观察而非稳健结论；部分组合中 CUADebugger 甚至劣于 Naive 基线，反映了模型能力依赖问题。
2. **实验条件不完全匹配**：单次重新执行中，不同条件在重启步骤来源（机器 vs. 人工根因）和提示格式上均存在差异，无法给出 RCA 来源质量的直接可比结论。更严谨的实验应做匹配条件的消融。
3. **Tag+Step 准确率总体偏低**：即使在最好的设定下（19.6%），联合精确匹配仍然较难，说明根因定位和细粒度分类仍是开放问题。
4. **RCA 依赖骨干模型能力**：工具检查能呈现证据，但模型仍需正确解读并修正因果假设；较弱骨干可能无法从中获益。
5. **单基准局限**：实验仅在 OSWorld 上进行，未覆盖 WebArena、AndroidWorld 等其他 CUA 基准，泛化性有待验证。
6. **不可行任务的标注存在歧义**："O1（不可行任务）"类别在某些情况下是合理判断，但也可能被当作推理失败的掩盖性标签，标注一致性存在风险。
7. **人类专家表现仅略高于 Our method**（29.21% vs. 25.86%），且差距依然存在，说明自动化诊断仍有提升空间。
8. **Token 消耗较大**：持续重新执行中输入 Token 高达 426K，从部署经济性角度存在优化空间。
