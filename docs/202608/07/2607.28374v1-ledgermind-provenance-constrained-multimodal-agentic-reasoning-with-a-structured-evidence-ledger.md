## 摘要
用于视觉问答的多模态代理日益以多步骤轨迹的形式运作，这些轨迹交错进行感知、检索和推理，然而评估在很大程度上仍简化为最终答案的准确性。这种总体信号无法判断正确答案是通过有据可依的证据、语言先验还是偶然的错误抵消而达成的。我们提出将多模态代理轨迹视为受来源约束的状态机：工具输出被规范化为结构化证据账本，作为轨迹状态；下游推理和决策声明只能引用活动账本条目；接地性在实体和数值层面进行检查；修复被实现为类型化状态转换，且不能在没有工具生成的来源的情况下引入内容。我们将这一设计实例化为LedgerMind（基于结构化证据账本、受来源约束的多模态代理推理），并辅以三层接地协议、自适应双路调度器（将推理深度与问题复杂性匹配）以及带有形式化来源非放大保证的事件触发验证与修复引擎。我们使用LedgerMind针对四个最终答案准确性往往掩盖的反复出现的失败模式：无支撑的中间推理、引用支撑的实体幻觉（幻影接地）、对简单查询的过度推理以及修复时的放大。跨多个多模态推理基准和骨干MLLM的实验表明，LedgerMind提高了答案准确性和轨迹层面的忠实度。

## Abstract
Multimodal agents for visual question answering increasingly operate as multi-step trajectories that interleave perception, retrieval, and reasoning, yet evaluation still largely reduces to final-answer accuracy. This aggregate signal cannot tell whether a correct answer was reached through grounded evidence, language priors, or accidental error cancellation. We propose to treat a multimodal agent trajectory as a provenance-constrained state machine: tool outputs are normalized into a Structured Evidence Ledger that serves as the trajectory state, downstream reasoning and decision claims may cite only active ledger entries, grounding is checked at the entity and numeric level, and repair is realized as typed state transitions that cannot introduce content without tool-produced provenance. We instantiate this design as LedgerMind (Provenance-Constrained Multimodal Agentic Reasoning with a Structured Evidence Ledger), augmented by a Three-Layer Grounding Protocol, an Adaptive Dual-Path Dispatcher that matches reasoning depth to question complexity, and an Event-Triggered Verification-and-Repair engine with a formal provenance non-amplification guarantee. We use LedgerMind to target four recurring failure patterns that final-answer accuracy tends to obscure: unsupported intermediate reasoning, citation-backed entity hallucination (Phantom Grounding), over-reasoning on simple queries, and repair-time amplification. Experiments across multiple multimodal reasoning benchmarks and backbone MLLMs show that LedgerMind improves both answer accuracy and trajectory-level faithfulness.

## 1. 核心问题与研究动机

- **背景**：多模态大语言模型（MLLM）驱动的视觉问答系统日益"代理化"，输出不再是一条单一预测，而是包含感知、检索、工具调用与推理的多步轨迹。然而主流评估仍以**最终答案准确率**为核心信号。
- **核心问题**：最终答案准确率无法区分正确答案是来自**有据可依的推理**、**语言先验**，还是**偶然的错误抵消**（如感知错误与推理错误互相抵消）。轨迹中大量中间推理声明缺乏可审计性。
- **四类被掩盖的典型失败模式**：
  - **F1（轨迹忠实性缺口）**：答案正确但中间推理声明缺乏证据支撑；
  - **F2（幻影接地，Phantom Grounding）**：声明引用了有效的证据 ID，却引入了引用来源中不存在的实体或数值，即"引用结构通过、结论级实体伪造"；
  - **F3（过度推理悖论）**：不必要的深层多步推理会覆盖简单查询的初始正确答案；
  - **F4（修复期放大）**：自由文本形式的自我反思在修复旧问题的同时引入了新的无支撑声明。
- **核心主张**：应将轨迹视为"受来源约束的状态机"，使来源可追溯性成为**结构性约束**而非提示词层面的偏好。

## 2. 方法论

### 2.1 结构化证据账本（Structured Evidence Ledger）
- 每个工具输出被规范化（通过确定性映射 M）为账本条目，包含11个字段：id、来源工具、认识论类型（感知/检索/衍生）、时间戳、规范化事实、置信度、生命周期状态、空间边界框、TTL、取代条目 ID、依赖集。
- **四条不变量**：I1 证据来源约束（条目必须来自工具输出）；I2 引用有效性（推理/决策声明只能引用 ACTIVE 条目）；I3 声明-证据包含（引用必要但不充分，需实体/数值被证据池许可）；I4 修复局部性（修复不能追加无来源的自由文本）。

### 2.2 三层接地协议（Three-Layer Grounding Protocol）
- **支持覆盖率**（式3）：声明与引用证据的词法重叠率 ρ(c)；
- **实体一致性检查（ECC）**（式4）：结论级非数值实体须出现在引用证据池中（允许多义词别名）；
- **数值一致性检查（NCC）**（式5）：数值型声明须与证据池中数值在类型感知容差内匹配——年份、日期、计数等精确匹配，连续视觉读数允许约15%的相对容差。
- ECC/NCC 失败分别将置信度降至 0.50/0.52（低于验证阈值 0.6），触发假设验证。

### 2.3 自适应双路调度器（Adaptive Dual-Path Dispatcher）
- 通过规则型复杂度分类器 φ(q) 将问题分为简单与复杂两类（式6）：
  - **DIRECT 路径**：小证据预算、单步视觉/浅层事实回答；
  - **FULLPIPE 路径**：任务规划 → 观察声明提取 → 裁剪缩放 → 双读验证 → 检索 → [E]→[I]→[J] 接地推理 → 三层防线。
- 两条路径共用同一账本接口，输出可比可审计。

### 2.4 事件触发验证与类型化修复
- 在 6 类高危事件（工具异常、陈旧引用、证据冲突、置信度下降、无支撑决策、幻影接地）触发时执行修复。
- 修复限定为 **7 个类型化操作符**，分三层：证据层（DROP、REFRESH）、动作层（RETRY、SWITCH、ACQUIRE）、轨迹层（STOP AND ANSWER、ABSTAIN）。
- **命题1（来源非放大保证）**：形式化证明任何修复操作符新增的账本条目都必须具有工具来源，修复不可能凭空伪造无来源内容（但不保证工具输出本身事实正确）。

### 2.5 轨迹级忠实性指标
- **UCR_reason**（无支撑推理率，式7）：仅统计状态声明与决策声明，避免感知声明稀释分母；
- **GDR**（接地决策率，式8）、**R4R**（证据支撑的成功率，式9）、**WDG**（外表接地但实际错误的比率，式10），另附 OCErr、EUR、RR、RC、SE 等辅助指标。

## 7. 优点

- **思想创新**：将代理轨迹从"自由文本缓冲区"重构为"结构化证据账本"，把来源约束从提示词偏好升级为结构性不变量，概念清晰且具有一般性。
- **形式化保证**：命题 1 提供了类型化修复下的来源非放大保证，是同类框架中少有的形式化承诺。
- **设计完备**：三层接地协议（覆盖率 + 实体 + 数值）精确对应"幻影接地"问题；双路调度器在统一账本接口下实现"按需深度"；事件触发机制避免无谓的自我批判。
- **指标创新**：提出 UCR_reason、GDR、R4R、WDG 等轨迹级指标，并区分感知错误（OCErr）与推理错误（UCR_reason），诊断粒度合理。
- **实验充分**：多基准、多骨干、多厂商覆盖，且与基线保持相同工具预算，因此增益归因于框架而非额外算力；Hard-200 的委员会式难度挖掘与多样性约束构造方法严谨。

## 8. 不足与局限

- **应用范围受限**：仅在静态图文 VQA 上评估，未覆盖长时程代理、视频流、具身交互

- **成本开销未量化**：LedgerMind 虽免训练，但引入了双读验证、事件触发的多轮修复（预算 M=2）以及账本规范化等额外步骤，实际 API 调用次数、token 消耗与端到端延迟均未报告。同为"公平工具预算"，但**框架自身开销**与基线不持平，公平性论证只覆盖了工具调用次数，未覆盖内部验证开销。
- **依赖外部工具链与封闭评估环境**：账本条目的有效性高度依赖工具输出质量与可用性；MC-Search 中需要外部搜索 API 和固定裁判模型，若工具失效或 API 变更，框架的增益幅度可能显著缩水。论文未测试工具缺失或工具输出被污染场景下的鲁棒性。
- **指标定义中的人工启发成分**：三层接地协议的词法覆盖率、ECC/NCC 的"类型感知容差"（如 15% 连续读数容差）、别名映射等均依赖人工设定的阈值与规则，跨领域（如医学影像、音频）迁移时这些参数需要重新标定，通用性存疑。
- **自建数据集规模与主观性**：Hard-200 仅 200 题，其中 25 个 RealCAR 为自建样例，构造过程虽有委员会式难度挖掘，但样本量小、域窄（BrowseComp-VL + TIR-Bench + RealCAR），难以支撑统计显著性；且题目遴选本身可能引入对框架有利的偏差。
- **与更强推理框架的对比缺失**：对比基线以"同骨干原生日志推理"和一批通用/视觉基线为主，未与显式设计了状态追踪、验证器或搜索式推理（如带奖励模型的树搜索、程序化验证、自训练反思框架）的方法对比，因此无法定位其相对"结构性约束"与"传统验证器"路线各自的贡献。
- **理论保证较弱**：命题 1 仅保证修复不引入无来源声明，不保证来源内容正确、不保证账本一致性最终成立；I3 与 I4 不变量在实现层面依赖 ECC/NCC 的启发式实现，并非形式化验证后的性质。
- **安全与伦理问题未讨论**：账本化的"可审计性"可能给人"系统更可信"的错觉，但若被引用的证据本身来自被攻击的工具输出，用户仍可能被误导；ABSTAIN 行为在真实决策场景下的代价、以及如何处理恶意构造的证据源，论文均未涉及。

## 9. 总体评价

LedgerMind 是一篇**概念与工程并重**的代理推理框架论文：它抓住了当前多模态代理评估中"答案正确掩盖轨迹腐烂"这一痛点，提出了证据账本 + 四条不变量 + 三层接地协议 + 类型化修复的系统性解决方案，并在与官方基线的相同工具预算下取得了跨骨干、跨基准的一致增益。其最突出的贡献在于**将"可追溯性"从评估指标层面下沉为系统结构约束**，并以轨迹级指标（UCR、GDR、R4R、WDG）证明准确率提升来自更好的接地轨迹，而非偶然的答案修正。

但论文的局限也很明显：评估域仍停留在静态图文 VQA，形式化保证的效力有限，成本与鲁棒性缺乏量化，消融与审计的覆盖范围不够全面。总体而言，这份工作为"可信视觉代理"提供了有说服力的设计与度量范式，是迈向**可审计、可追踪、受来源约束**的多模态代理推理的重要一步；未来若能在长时程交互、跨域工具链与动态环境（视频、具身）中推广，并补齐成本与安全性分析，其实践价值将进一步放大。
