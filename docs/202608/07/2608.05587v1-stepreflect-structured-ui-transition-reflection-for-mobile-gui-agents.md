## 摘要
自主移动GUI智能体需要准确的动作反思，以实现可靠的长期执行。现有方法在每个动作后依赖开放式多模态推理，成本高昂且与GUI状态转换的结构化特性不匹配。我们提出StepReflect，将逐步GUI反思形式化为基于显式转换规范和配对视觉证据的监督式结构化预测。StepReflect通过分阶段流程训练，结合了监督微调、师生蒸馏以及基于偏好和奖励的优化。离线状态下，生成的8B模型在AndroidWorld上达到82.16%的转换级准确率，在相同结构化输入下超过零样本GPT-5.2达11.83个百分点。在线状态下，在M3A、Agent-SAMA、MAI-UI-8B和Seed-2.0-Pro中，StepReflect在四个代理配置中的三个实现了更高的任务成功率，并在第四个配置中与GPT-5.2反思代理仅相差一个成功任务。它还在所有四个配置中相对于基于GPT的反思减少了付费API费用。这些结果表明，StepReflect是面向长期移动GUI智能体的重复前沿模型反思的一种实用、可本地部署的替代方案。

## Abstract
Autonomous mobile GUI agents require accurate action reflection for reliable long-horizon execution. Existing approaches rely on open-ended multimodal reasoning after each action, which is costly and poorly matched to the structured nature of GUI state transitions. We propose StepReflect, which formulates per-step GUI reflection as supervised structured prediction conditioned on explicit transition specifications and paired visual evidence. StepReflect is trained through a staged pipeline combining supervised fine-tuning, teacher-student distillation, and preference- and reward-based refinement. Offline, the resulting 8B model achieves 82.16% transition-level accuracy on AndroidWorld, exceeding zero-shot GPT-5.2 by 11.83 percentage points under the same structured input. Online, across M3A, Agent-SAMA, MAI-UI-8B, and Seed-2.0-Pro, StepReflect achieves higher task success in three of four agent configurations and remains within one successful task of the GPT-5.2 Reflection Agent in the fourth. It also reduces paid API charges relative to GPT-based reflection in all four configurations. These results establish StepReflect as a practical, locally deployable alternative to repeated frontier-model reflection for long-horizon mobile GUI agents.

## 1. 核心问题与整体含义

**研究动机与背景：**
- 移动GUI智能体需执行复杂长序列任务（如订餐、叫车），要求每一步动作后进行**动作反思（action reflection）**——判断已执行动作是否产生了预期的界面转换。
- 现有方法依赖**开放式多模态推理**（如调用GPT-4o/GPT-5.2等大模型进行自由文本判断），存在两大问题：
  - **成本高**：每步都调用云端前沿模型，长轨迹下延迟与API费用持续累积；
  - **结构性错配**：GUI交互本质上是**可预期的、结构化的状态转换**（从状态s_t经动作a_t到状态s_{t+1}），而开放式推理将其当作一般性“思考”问题处理，忽略了这种内在结构。
- 更根本地，当前系统属于**反应式（reactive）**架构，缺乏显式结构、持久状态和执行反馈，长程任务中微小的反思误差会逐步累积导致任务失败。

**核心含义：**
论文主张将GUI动作反思**重新定义为UI转换上的监督式结构化预测问题**——只需判断观察到的UI转换是否与动作的预期效果一致，而非进行开放式的多模态推理。StepReflect作为这一思路的落地实现，是一个紧凑的8B参数学习型反射器，可作为独立模块嵌入异构智能体框架，替代重复调用前沿大模型的反思方式。

## 2. 方法论

**核心思想：**
将反射任务形式化为：

> fθ : S × A × S × H × I → {0, 1} × R

即输出二元判定（转换是否一致）+ 结构化自然语言推理。

**关键输入设计（反思实例）：**
- **转换规格（Transition Specification）**：由宿主智能体提供的语义期望，包括动作意图、前置/后置条件（pre-/post-conditions）及屏幕描述；
- **配对视觉证据**：动作前/后双截图（BEFORE/AFTER screenshots）；
- **有界同子目标历史**：仅保留当前子目标范围内的最近转换，上限 hmax = 5，跨子目标的旧状态不进入输入，避免误导；
- 分层隔离：语义期望由宿主提供，观察证据来自截图与状态描述，StepReflect只判断两者是否一致，不生成期望本身。

**三阶段训练管线（图2）：**
1. **阶段一：监督微调（SFT）**
   - 学习GUI转换动态的基础识别能力；
   - 输出结构化JSON（二元判定+解释）；
   - 数据来自Mobile-Eval-E与SPA-Bench的执行轨迹，经GPT-5.2初始标注+人工审计，最终得到882个转换实例（517正/365负）。
2. **阶段二：教师-学生蒸馏（TS-Dis.）**
   - 以GPT-5.2为教师，要求学生先描述前后状态、观察到变化的UI、与当前子目标的对齐度，再给出判定；
   - 蒸馏产生更长、模板化的推理输出，**但单独使用不一定保持分类准确率**。
3. **阶段三：偏好与奖励优化（GRPO + DPO）**
   - **GRPO（不对称奖励设计）**：正确“Yes”得+2.5、正确“No”得+2.0；误接受（假阳性）罚-2.0，**误拒绝（假阴性）罚-2.5**——反映长程执行中错误拒绝的更高代价（可能触发不必要的恢复或终止）；
   - **DPO（拒绝采样构建偏好对）**：每输入采样5个候选，228个合格输入产生488个偏好对；
   - 优化顺序很重要：**GRPO→DPO** 优于 DPO→GRPO（见消融）。

**基座模型与适配：**
- 评估Qwen2.5-VL（3B/7B）、Qwen3-VL（4B/8B）四个基座，最终采用Qwen3-VL-8B；
- LoRA适配（秩r=16，α=16，4-bit加载，零dropout），8位AdamW，bf16，余弦调度，max_length SFT/蒸馏为8192、GRPO为16384；
- StepReflect作为**独立模块**，通过轻量提示接口嵌入宿主智能体，不修改宿主智能体的规划/动作生成策略。

1. **离线反射准确性**：最终StepReflect（Qwen3-VL-8B，TS-Dis.→GRPO→DPO）在AndroidWorld达到**82.16%转换级准确率**，超出同输入下零样本GPT-5.2达**11.83个百分点**，超GPT-4o达15.99个百分点。

3. **在线任务成功率**：在M3A（44.44% vs GPT-5.2 38.89%）、MAI-UI-8B（29.91% vs 25.64%）、Seed-2.0-Pro（41.88% vs 34.19%及以上基准41.03%）三个框架中取得更高成功率；在Agent-SAMA上（55.56% vs 58.33%）仅相差一个成功任务。

## 7. 优点

- **问题重构有新意**：将反思从“开放推理”重新定义为“结构化转换验证”，概念清晰、直击成本与结构性错配的双重痛点，并在理论上呼应了GUI交互的可预期状态转换特性；
- **异步错误不对称的设计意识**：明确意识到假阴性（误拒绝有效转换）在长程执行中的更高代价，并在GRPO奖励函数中直接建模（-2.5 vs -2.0），这种针对下游代价的奖励设计是务实且少见的；
- **非侵入式集成**：StepReflect作为独立模块可嵌入异构框架，不修改宿主规划/动作策略，通过轻量适配器映射字段——可迁移性较好，降低部署门槛；
- **三阶段渐进式训练**：从基本动力学学习→推理结构蒸馏→决策校准层层递进，每一阶段有明确目标，消融验证了各组件（优化顺序、结构化输入）的贡献；
- **实验设计较严谨**：训练-测试完全分离；对比模型输入严格一致；在线为组内控制变量比较；同时报告类条件准确率（Positive/Negative Accuracy）暴露接受/拒绝偏差，避免被总体准确率掩盖。

## 8. 不足与局限

- **数据标注成本高、可扩展性受限**：依赖GPT-5.2辅助标注+人工审计修正，扩展至更大规模需要半自动验证和不确定性主动采样策略；
- **上游误差传播风险**：StepReflect不生成符号字段，若宿主提供的状态描述/前后置条件本身有误，错误会传播进入反射判定；
- **在线评估范围有限**：AndroidWorld在线仅36个中等难度任务，不代表完整基准表现；存在任务选择带来的偏置风险；不反映运行间变化（agent/emulator/API变异性）；
- **MobileWorld集成仅为描述-only**：无显式前后置条件暴露，虽验证了鲁棒性，但无法评估完整结构化输入在该场景下的增益；
- **成本统计口径不对称**：只计算付费API调用，**排除本地推理的硬件/服务器成本**——在需要自购GPU部署的场景下，总体成本对比可能有不同结论；
- **跨平台泛化未知**：仅验证移动 GUI 环境，扩展到Web或桌面环境需要适配不同的动作空间、布局与状态表示；
- **训练资源明细缺失**：未披露GPU型号/数量/训练时长，降低了可复现性与算力需求评估的透明度。
