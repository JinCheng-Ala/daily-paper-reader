## 摘要
深度搜索智能体通过长时间的网络交互来应对具有挑战性的问题，这一过程既复杂又脆弱：小的推理错误可能会沿着漫长而嘈杂的轨迹传播，最终形成流畅但错误的答案。诊断此类失败十分困难，需要人工检查极其冗长的执行轨迹，这可能超出人类的能力范围。为此，我们引入了SearchAuditBench，一个评估LLM审计者能否定位、归因并修复这些失败的基准，从而减轻人类负担。SearchAuditBench包含1,243条失败轨迹，平均每条73.1条消息和65.1K个令牌，收集自八个开放权重模型在五个深度搜索基准上的运行结果，每条轨迹均附有专家标注的关键错误步骤、搜索特定的根因以及带有评分标准的参考修复方案。我们进一步提出了SearchAuditor，一个多视角审计框架，通过基于证据的裁决有效地定位、归因并修复搜索智能体的失败。实验结果表明，即使是最强的基线，当使用GPT-5.5等前沿模型驱动时，端到端通过率也仅为26.6%。相比之下，我们的SearchAuditor在不同前沿模型上均持续优于所有基线，端到端通过率达到32.3%，并且利用其修复方案恢复失败运行能使智能体更好地从错误中恢复。

## Abstract
Deep search agents tackle challenging questions through long-horizon web interactions, a process that is both complex and fragile: small reasoning errors may propagate through long, noisy trajectories into fluent but incorrect answers. Diagnosing such failures is difficult, requiring the manual inspection of extremely long execution traces, which could be beyond human capacity. We therefore introduce SearchAuditBench, a benchmark that evaluates whether LLM auditors can localize, attribute, and repair these failures, thereby reducing the human burden. SearchAuditBench comprises 1,243 failed trajectories, averaging 73.1 messages and 65.1K tokens, collected from eight open-weight models on five deep-search benchmarks, each expert-annotated with the critical error step, a search-specific root cause, and a reference repair with grading rubrics. We further propose SearchAuditor, a multi-perspective auditing framework that effectively localizes, attributes, and repairs search-agent failures through evidence-grounded adjudication. Experimental results show that even the strongest baseline, when powered by a frontier model like GPT-5.5, attains only a 26.6% end-to-end pass rate. In contrast, our SearchAuditor consistently outperforms all baselines across different frontier models, achieving an end-to-end pass rate of 32.3%, and resuming failed runs with its repairs enables agents to better recover from errors.

- **核心难点**：
  - 轨迹规模庞大且噪声密集（平均73.1条消息、65.1K tokens），关键错误被淹没在大量工具返回中。
  - 与代码智能体（可用可执行测试作为oracle）不同，搜索智能体没有明确的可验证结构，证据链建立在易变的网页内容上。
  - 失败是“静默传播”的：智能体很少崩溃，而是错误地信任来源、遗漏关键证据或错误维护候选答案，且最终答案看起来依然自然。
- **研究意义**：人工审计这些超长轨迹超过人类能力，自动化审计对于提升搜索智能体的可信度、可调试性和安全部署至关重要。论文首次系统性地提出**失败定位、归因与修复**三位一体的审计任务，旨在显著降低人工负担。

## 2. 方法论

### 2.1 SearchAuditBench 基准构建
- **轨迹收集**：
  - 8个开放权重模型（GLM-5.2、Kimi-K2.6、DeepSeek-V4-Pro、Qwen3.5-397B-A17B、OpenSeeker、OpenResearcher、Quest-35B、Tongyi-DeepResearch-30B-A3B）在5个深度搜索基准（BrowseComp、BrowseComp-ZH、DeepSearchQA、Seal-0、xBench-DeepSearch）上运行。
  - 所有模型使用统一脚手架（基于Tongyi DeepResearch），配备 `search` 和 `visit` 两个工具。
  - 共收集3,500条原始轨迹，经过自动筛选（LLM判断最终答案错误）和专家审核后，保留**1,243条“可审计的失败轨迹”**（排除误判、基准问题、轨迹不完整、无法离线审计、无单一关键步骤等情况）。
- **标注内容**：
  1. **关键错误步骤（critical step）**：定义为“最早使失败机制确立的决策步骤”，并附带一个**容差区间（tolerance span）**以解决标注模糊性。
  2. **根因分类（root cause）**：六类搜索特定分类法——候选答案管理不当、搜索覆盖缺口、约束忽视、未验证来源依赖、实体-关系错误绑定、无证据支持答案。
  3. **修复指令（repair directive）**：可执行的、过程级的、从关键步骤起生效的修复方案，并拆分为3~5条原子化评分标准（rubrics）。
- **审计设置**：严格离线——审计者只能看到查询、错误最终答案和轨迹，无金标准、无网络访问，保证可复现性。

### 2.2 SearchAuditor 框架
- **三阶段流程**：
  1. **多视角审计（Multi-perspective Auditing）**：三个审计分支并行运行，共享同一骨干模型但使用不同程序化提示：
     - 整体审计（Holistic）：直接对整个轨迹进行诊断。
     - 后向约束审计（Backward）：解析查询为显式约束，从错误答案反向追踪每个约束的验证状态，定位最早违反或未验证的决策步骤。
     - 前向时间线审计（Forward）：先构建查询最小化规划，再按时间顺序扫描决策步骤，寻找“最早确立失败路径”的步骤，防止向后期漂移。
  2. **证据基础裁决（Evidence-grounded Adjudication）**：
     - 确定性规则组织三份报告（生成差异摘要、对相近步骤提案聚类）。
     - 在每个提案步骤和最终答案附近提取原始消息的有界窗口，并加入全局步骤大纲。
     - 裁决器重新决定关键步骤和根因，遵循“少数派报告可凭证据胜出”“步骤与根因必须一致”“优先最早证据支持的步骤”等规则。
  3. **诊断条件修复合成（Diagnosis-conditioned Repair Synthesis）**：
     - 仅接收诊断结果、证据窗口和查询信息，生成由2~4条原子化、可执行、过程级指令组成的修复方案，明确禁止泄露金标准答案。

## 3. 实验设计

### 3.1 基准与数据集
- **SearchAuditBench**：1,243条标注失败的轨迹，跨8个模型×5个基准，统计特性包括：平均73.1条消息、65.1K tokens（其中工具返回49.1K vs 推理15.3K）、36.7次工具调用、约32K次搜索调用和13.6K次页面访问。
- **LiveBrowseComp**（335题）用于验证修复的实际功效，与SearchAuditBench来源基准不重叠。

### 3.2 对比方法与骨干模型
- **基线**：
  - 直接提示策略（改编自Zhang et al., 2025）：All-at-Once（单次全轨迹评估）、Step-by-Step（前缀逐步扫描）、Binary Search（二分定位）。
  - 框架基线：AgentRx（通过约束违反诊断失败）。
- **骨干模型**：GPT-5.5、Gemini-3.1-Pro、Claude-Opus-4.8（推理强度设为high）。
- **修复评分器**：DeepSeek-V4-Flash，并已在200个输出、872条rubrics上进行盲检人工验证（85%级别的一致性）。

### 3.3 评估指标
- **关键步骤定位**：CS-Strict（精确等于金标准）、CS-Loose（落在容差区间内）。
- **根因分类**：RC-Acc（六分类准确率）、RC-F1（宏平均F1）。
- **诊断质量**：Diag（根因正确且步骤在容差内的比例）。
- **修复质量**：Rep@Diag（仅在诊断正确的子集上评估，全部rubrics通过的比例）。
- **端到端**：FPS = Diag × Rep@Diag（全部通过的比例）。

### 3.4 实验内容
1. **主实验**：三个骨干模型下对5种方法（4个基线+SearchAuditor）的对比。
2. **消融实验**：在300条随机子集上，6个变体验证多视角分支、证据裁决、大纲/窗口的作用。
3. **修复恢复实验**：在LiveBrowseComp上，用Kimi-K2.6和Quest-35B的重跑测试（干预方式包括无引导重试、通用提示、各方法修复指令注入等）。
4. **标注者验证**：200输出、872条rubrics上验证自动评分器。
5. **成本效率分析**：100条实例上测量延迟和token用量。

## 6. 主要结论与发现

- **审计任务极端困难**：最强基线（GPT-5.5）在FPS上仅达26.6%，说明长程搜索轨迹审计具有内在本征难度。
- **SearchAuditor全面优于所有基线**：
  - GPT-5.5上：CS-Strict 44.89%（+5.87）、CS-Loose 58.73%（+6.84）、FPS 32.26%（+5.71）。
  - Gemini-3.1-Pro和Claude-Opus-4.8上提升幅度保持在4~5个点，显示方法对骨干模型稳健。
  - 消融证明：多视角分支（尤其是前向时间线审计）、证据基础裁决和结构化证据视图（大纲+窗口）均贡献显著。
- **修复具有实际价值**：在LiveBrowseComp上，SearchAuditor的修复使Kimi-K2.6的失败恢复率达到17.37%，准确率从34.03%提升至45.07%；Quest-35B的准确率从8.96%提高到18.21%。修复本身而非仅定位是恢复收益的主要来源。
- **失败模式新洞察**：
  - **大多数失败不是检索失败**：77.2%的失败源于证据利用而非检索覆盖不足（重要证据其实已在轨迹中）。
  - 在25%的失败中，正确答案字面出现在检索内容中，且其中83%在关键步骤或之前就已出现。
  - **失败静默传播**：关键错误之后平均还有16.7次额外工具调用，近一半的计算资源（47.1% tokens、45.4%工具调用）被浪费。
  - **探索预算增加并非万能**：搜索覆盖缺口失败的比例与工具调用中位数呈强负相关（Pearson r = -0.88），但探索多的模型只是把失败迁移到候选管理和约束忽视上。

## 7. 优点

- **基准贡献突出**：首个面向长程搜索智能体的、专家标注的失败轨迹审计基准，规模大（1,243条）、标注丰富（关键步骤、容差、根因、修复+rubrics），填补社区空白。
- **方法论设计有亮点**：
  - “分而治之+对抗化”的多视角审计，通过不同程序化分析暴露单一视角的盲点。
  - 证据基础裁决（而非简单投票）有效整合冲突报告，并通过局部窗口+全局大纲平衡细节与全局结构。
  - 诊断条件修复合成确保修复与根因一致，且严格禁止泄漏金标准，保证了评价的可信度。
- **实验设计严谨**：
  - 消融设计区分“不同视角”与“重复采样”的功效。
  - 修复恢复实验提供了无需人工标注的实用验证，证明了审计的实际价值。
  - 自动评分器经人工盲检验证，增强了指标的可信度。
- **分析洞察有价值**：基于大样本标注的失败分析揭示了“答案在手”悖论，为后续搜索智能体优化指明了方向。

## 8. 不足与局限

- **离线审计的天然边界**：SearchAuditBench 严格限制审计者仅能访问查询、错误答案与历史轨迹，无法联网核实实时页面内容。这种设计保证了可复现性，但也使得审计无法捕捉“搜索时机敏感”型失败（例如页面内容在收集后发生变化、或智能体因时效性问题而错过关键信息）。因此，基准更适用于诊断“证据利用”类错误，对“检索环境动态性”类错误覆盖有限。
- **数据标注的主观性残余**：关键步骤虽采用容差区间缓解模糊性，但“最早确立失败机制的步骤”本身仍是专家判断，不同专家对同一轨迹的标注可能存在系统性偏差。论文报告了筛选流程和专家审核，但未提供标注者间一致性（如 Cohen's Kappa）的定量报告，使得标注可靠性的证据链略显单薄。
- **根因分类法的完整性存疑**：六类根因虽针对搜索场景定制，但可能无法覆盖所有失败模式（例如长期规划中的目标漂移、多子问题间优先级冲突等）。部分失败可能同时涉及多个根因，强制单标签分类会损失粒度，影响后续归因和修复的精准度。
- **修复质量评估的自动化依赖**：Rep@Diag 依赖 DeepSeek-V4-Flash 作为评分器，尽管已在 200 个输出上做了人工盲检验证（85% 级别一致性），但剩余 15% 的误判仍可能扭曲结果。且 rubric 是否真正“无泄漏”仅靠提示约束，难以从机制上保证评分器不会利用训练集中的相关模式。
- **方法适用范围的局限性**：SearchAuditor 的报告生成与裁决均使用大型前沿模型 API，成本虽低于逐步扫描基线，但单实例仍需约 5 次调用、275K 输入 tokens。对于需要大规模工业级审计的场景，该成本可能仍难以承受。论文未探索蒸馏到小模型或使用开源模型的可行性。
- **修复恢复实验的覆盖不足**：LiveBrowseComp 仅用两个智能体验证修复功效，且评估指标仅为准答率。未检验修复对答案质量（如推理链一致性、引用准确性）的影响，也未评估修复指令在无故障轨迹上是否有副作用（即“误修复”风险）。
- **比较公平性的潜在折扣**：基线方法（如 AgentRx）并非为长程搜索轨迹专门设计，其提示可能未经针对该任务调整；而 SearchAuditor 经过多轮迭代优化。这种不对称的提示工程投入可能使基线表现低于其潜在水平，需谨慎解读“全面优于”的结论。
- **未报告硬件与运行资源细节**：除 API 消费量外，论文未披露本地推理环境（模型部署框架、并发策略等），为复现实验增加了额外障碍。此外，也未讨论 API 温度、随机种子等采样参数对审计结果稳定性的影响。

## 9. 研究启示与未来方向

- **对搜索智能体设计的启示**：77.2% 的失败源于证据利用而非检索覆盖，且 25% 的失败中正确答案早已出现在检索内容中。这表明盲目增加搜索预算或扩展检索范围并非提升准确率的根本途径，核心改进应放在“证据综合”“候选答案管理”“约束跟踪”等推理环节。
- **对审计方法论参考**：多视角审计 + 证据裁决的流程具有较强通用性，可迁移到代码智能体、具身智能体等长程决策场景。特别是“前向时间线”分支的显著贡献说明，将规划预期与实际轨迹对齐是定位早期失败的有效策略。
- **未来研究方向**：
  - 自适应审计：根据轨迹长度和错误信号动态调节多视角分支的深度，降低正常轨迹的审计成本。
  - 在线审计与干预：将审计从离线诊断推向在线监控，在关键错误发生后即时触发修复。
  - 修复指令自动生成与闭环验证：形成“失败 → 归因 → 修复 → 重跑 → 再审计”的闭环，并在此基础上学习可泛化的修复策略。
  - 根因体系的细粒度扩展：引入多标签、层次化根因结构，或结合网页内容动态变化建立时间-证据联合模型。
  - 轻量化审计模型：利用蒸馏或开放权重模型实现低成本审计，使中小团队也能应用。

## 10. 总体评价

SearchAuditBench 与 SearchAuditor 为该领域提供了从“系统性能评估”到“失败过程审计”的重要范式转换。论文工作扎实、分析深入，不仅在方法上提出了新颖的三阶段框架，更通过大规模标注和详实的实验验证了其有效性。尽管存在离线审计边界、标注主观性和资源开销等局限，但作为首个专注长程搜索智能体失败审计的基准与方法，它为该方向奠定了坚实起点，也清晰指出了未来优化的路径。对于需要在复杂开放环境中部署搜索智能体的研究者和工程师，本文具有很高的参考价值与实用意义。
