## 摘要
工具使用的大型语言模型代理通常在工具调用可靠成功的环境中进行训练和评估，但部署后的工具可能会发生瞬时、持续或静默的失败。因此，稳健的恢复不仅仅需要重复重试：代理可能需要重试相同的路径、切换到替代方案，或认识到没有可行的路径剩余。我们提出了BENCH2ROBUST框架，该框架将无失败的工具使用基准转换为受控随机环境，具有受场景控制的可解性，其中情节明确要求在执行可用路径用尽后重试、切换或停止。我们使用BENCH2ROBUST研究两种互补的干预措施：通过贝叶斯工具记忆（BTM）提供的结构化运行时恢复上下文，以及课程控制的强化学习。在来自4个家族的7个模型和两个多轮基准家族中，工具失败产生了近乎普遍的鲁棒性差距。在保留的零售任务上，BTM在不重新训练的情况下将鲁棒性提高了最多16.8个百分点，而强化学习学习了互补的恢复行为，在没有推理时BTM的情况下仍然有益。将两者结合在注入条件下达到40.8-45.5%的性能，同时保持无失败的性能。这些结果表明，稳健的工具使用受益于将环境特定的恢复知识与学习到的恢复行为相结合。

## Abstract
Tool-using LLM agents are commonly trained and evaluated in environments where tool calls succeed reliably, yet deployed tools can fail transiently, persistently, or silently. Robust recovery therefore requires more than repeated retries: an agent may need to retry the same path, switch to an alternative, or recognize that no viable path remains. We present BENCH2ROBUST, a framework that converts failure-free tool-use benchmarks into controlled stochastic environments with scenario-controlled solvability, where episodes explicitly require retrying, switching, or stopping after available paths are exhausted. We use BENCH2ROBUST to study two complementary interventions: structured runtime recovery context through Bayesian Tool Memory (BTM), and curriculum-controlled reinforcement learning. Across 7 models from 4 families and two multi-turn benchmark families, tool failures produce a near-universal robustness gap. On held-out Retail tasks, BTM improves robustness by up to 16.8 percentage points without retraining, while RL learns complementary recovery behavior that remains beneficial without inference-time BTM. Combining the two reaches 40.8-45.5% under injection while preserving failure-free performance. These results suggest that robust tool use benefits from combining environment-specific recovery knowledge with learned recovery behavior.

### 1. 核心问题与整体含义（研究动机与背景）

- **研究动机**：工具使用型 LLM 智能体通常在工具调用可靠成功的“理想”环境中训练和评估，但实际部署中工具调用会面临三类失败：**瞬时失败**（如超时、限流）、**持续失败**（如鉴权失效、schema 漂移）和**静默失败**（如返回部分数据、过期值、事实错误）。这些失败对用户是不可见的，而现有评估基准几乎完全忽略了这一鲁棒性问题。
- **整体含义**：工具失效后的恢复策略具有战略意义——智能体不应盲目重试，而需要学会三种差异化行为：**重试（Retry）**、**切换（Switch）** 或 **放弃（Abstain）**。传统随机故障注入无法揭示某一场景究竟需要哪种恢复行为，导致策略退化、评估信号被环境随机性污染。
- **核心目标**：通过受控方式显式区分这三种恢复场景，并设计干预措施来提升智能体的恢复策略，从而弥合工具使用过程中因失效导致的鲁棒性差距。

### 2. 方法论（核心思想、关键技术细节）

**（1）BENCH2ROBUST 框架：基于场景控制的可解性设计**

- 将无失败基准转换为受控的随机环境，采用 POMDP 建模（Minj），其中底层状态转移和奖励与干净环境一致，但观测被噪声核（Zinj）污染。
- 每个工具调用以 60% 概率返回干净结果，40% 概率触发 9 种失效模式之一——6 种**显式信号错误**（timeout、rate_limit、server_error、auth_error、malformed、schema_drift）和 3 种**静默损坏**（部分数据、过期值、事实错误）。
- 核心创新在于引入**场景受控可解性（scenario-controlled solvability）**，每个训练情节被显式标注为三类之一：
  - **S1（retry_works）**：无路径被永久阻断，重试即可恢复；
  - **S2（switch_needed）**：主路径被情节级永久阻断，必须切换到等价备用工具；哪一侧被阻断是随机化 50/50；
  - **S3（impossible）**：所有可行工具路径均被阻断，正确行为是放弃/上报。
- 注入预算 B ≤ 5、单工具连续随机失败上限 Kmax = 2，并与情节持久性阻断分离，从而将“持久不可用”与“随机失败运气”区分开。

**（2）贝叶斯工具记忆（BTM）**

- 从训练切分回滚中计算 **Beta 后验可恢复性统计**（每对工具×错误的恢复概率、切换成功率），并融合**领域特定的 fallback 映射**和**启发式约束**（如"任何错误至少重试一次""切换后验证字段""不可逆操作前必须确认""只有穷尽恢复路径后才能上报"）。
- 作者明确承认"Bayesian"主要体现在经验恢复统计的估计上，**后验校准值本身并非主要增益来源**——消融显示 fallback 结构和约束贡献了绝大部分提升。

**（3）奖励函数设计**

- 完成任务：`1.0 × eff(τ) × rep(τ)`；
- 未完成任务：`0.3 × (匹配动作数/总需求数) × rep(τ)`；
- `eff` 惩罚过长情节（超过 12 步后逐步衰减至 0.3 下限），`rep` 惩罚重复调用（≥4 次相同调用归零）。
- 奖励中**没有正确的放弃正项**——S3 情节无法通过基准评估器，作者据此限制了"完全学会放弃"的声明范围。

**（4）DAPO 课程强化学习**

- 五阶段课程递进：阶段 1 学 R ETRY（100% S1），阶段 2–3 引入 S WITCH（20%→40% S2），阶段 4 添加 A BSTAIN（10% S3），阶段 5 全谱系训练（30/45/25）。
- DAPO 算法 + KL 约束（系数 0.02）防策略崩溃；非对称裁剪（εlow=0.20, εhigh=0.28）；动态组过滤（方差<0.01 时屏蔽）；G=16 条组内相对优势（8 干净 + 8 注入）。

### 3. 实验设计（数据集 / 场景 / 基准 / 对比方法）

- **训练与域内评估**：Combined Retail 1,339 任务（tau2-bench retail 114 + Retail-3I 1,225，覆盖 general/ambiguous/changing 三类用户意图），划分 937 训练 + 402 留出任务。
- **跨基准评估**：Airline-3I（584 任务）、tau2-bench Telecom（114 任务）、BFCL multi-turn（200 任务）。
- **参照模型**：Qwen3-4B-Thinking-2507（主训练目标）、Qwen3-8B、Qwen3-32B、Qwen3-235B、DeepSeek-V3、GLM-4.7、MiniMax-M2.5，覆盖 4 个模型家族、4B 到 235B 尺寸。
- **对比配置**：Base（无 BTM 无 RL）、Base+BTM（仅推理上下文）、RL（训练后不加推理 BTM）、RL+BTM（两者结合），在 clean / inject w/o alt（标准工具集）/ inject w/ alt（含 fallback 工具集）三种模式下评估。

### 4. 资源与算力

### 5. 实验数量与充分性

- **鲁棒性差距评估**：7 模型 × 10 任务/域切片 = 70 组（model, subset）对，其中 69 组在注入下性能下降（-1.8 至 -46.7pp），覆盖面广。

### 6. 主要结论与发现

1. **鲁棒性差距具有普遍性**：70 个（模型, 子集）对中 69 个在注入下性能下降，模型规模增大并不能消除脆弱性（Qwen3-235B 仍损失 15.8pp）。
2. **BTM 提供最大的零训练增益**：在不重新训练的情况下，4B 基础模型提升 +16.8pp（无备用工具）/ +11.7pp（有备用工具），增益主要来自 fallback 映射和恢复约束，而非后验校准值。
3. **RL 学到了超越重试坚持的行为**：去掉推理时 BTM 后，训练策略仍比基础模型高 +6.3/+6.9pp；在真实需要切换的 S2 情节上表现更好，过早上报率降低。
4. **运行时知识与学习行为互补**：RL+BTM 在注入下达 40.8%（无备用）/ 45.5%（有备用），同时保持干净性能不下降（63.9% vs 基线 64.3%）；BTM 擅长显式瞬时错误，RL 在持久错误和静默错误上增量更大。

### 7. 优点

- **场景受控设计是核心亮点**：S1/S2/S3 显式区分"重试可恢复 / 切换必须 / 无路可走"，避免把盲目重试的运气与真实恢复策略混为一谈。
- **框架通用性**：BENCH2ROBUST 通过薄适配器可迁移到任何符合 tool_call → response 模式的基准，已覆盖 4 个基准家族，且错误类型覆盖面超过现有鲁棒性基准（9/9 vs ToolBench-X 等的 4–6/9）。
- **BTM 的设计诚实且可解释**：通过分解实验诚实指出"Bayesian"命名主要来自经验统计而非校准值优势，避免了过度声称。
- **跨域迁移评估完整**：从零售训练迁移到航空、电信、BFCL，展示了恢复行为的可复用性和边界。
- **效率与鲁棒性兼顾**：采用效率折扣、重复惩罚、KL 稳定机制，并报告 token 消耗，相比纯鲁棒性研究更具工程实用性。

### 8. 不足与局限

- **放弃（Abstain）信号不完整**：奖励函数中无正确的 S3 正奖赏，任务评估器无法为不可解任务分配成功分，因此论文只将 S3 作为训练条件，未声称"学会放弃"，这是当前贡献的重要边界。
- **干预比较是完整配方而非分离组件**：RL+BTM 与 vanilla-GRPO 基线的对比同时变化了课程、稳定化与奖励塑形，无法归因单一因素。
- **失效与数据均为模拟**：9 种噪声类型虽覆盖广泛，但其概率配置是严重压力测试设定而非真实 API 故障统计；无真实事故轨迹验证。
- **跨域迁移能力有限**：电信域接近 4B 模型能力下限（21% 干净通过率），RL 增益在噪声范围内；零售→BFCL 迁移仅 +5pp，说明恢复行为仍部分绑定于域内工具结构。
- **效率代价**：恢复行为增加 token 使用（70K→117K），在延迟敏感部署中可能受限；表 15 显示 BTM 和 RL 的注入通过率提升伴随步骤数增加。
- **策略级分析的混杂问题**：各策略通过自身轨迹决定 S1/S2 划分，比较"有提示意义但无法分离因果效应"。
- **评估者限制**：Qwen3-235B 作为用户模拟器，文中引证先前工作称其方差低，但未评估模拟器选择敏感性。
