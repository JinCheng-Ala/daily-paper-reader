## 摘要
评估语言引导的移动代理近期已从基于规则的方法转向基于模型的方法，以实现可扩展和自动化的评估。然而，现有的整体评估范式一次性处理整个轨迹，导致显著的上下文过载。此外，它们主要关注任务完成情况，而忽视了操作安全性。为解决这些局限性，我们提出了CRATE，一种新颖的两阶段VLM作为裁判的框架，用于自动化移动代理评估，兼容开源和闭源模型。利用步骤级后果推理机制，CRATE在每一步独立提取任务相关的视觉线索，并推断基于动作的状态变化。随后，通过轨迹级聚合综合生成的步骤级文本证据，以提供基于证据的任务完成评估。在此评估方案基础上，我们进一步将CRATE扩展为CRATE-S，用于操作安全评估。大量实验验证了CRATE和CRATE-S的有效性和鲁棒性。基于Qwen2.5-VL-72B-Instruct，CRATE在AndroidWorld上达到了0.833的F1分数（比SPA-Bench高出20%），而CRATE-S在MobileRisk上达到了0.697的F1分数，展示了与基准真实标签的强一致性。代码可在 https://anonymous.4open.science/r/CRATE-D580 获取。

## Abstract
Evaluating language-guided mobile agents has recently shifted from rule-based to model-based approaches to achieve scalable and automated assessments. However, existing holistic evaluation paradigms process entire trajectories at once, leading to substantial context overload. Moreover, they primarily focus on task completion while overlooking operational safety. To address these limitations, we introduce CRATE, a novel two-stage VLM-as-judge framework for automated mobile agent evaluation that is compatible with both open- and closed-source models. Leveraging a step-level consequence reasoning mechanism, CRATE independently extracts task-relevant visual clues and infers action-conditioned state changes at each step. The resulting step-level textual evidence is then synthesized through trajectory-level aggregation to deliver an evidence-grounded evaluation of task completion. Building upon this evaluation scheme, we further extend CRATE to CRATE-S for operational safety assessment. Extensive experiments validate the effectiveness and robustness of both CRATE and CRATE-S. Powered by Qwen2.5-VL-72B-Instruct, CRATE achieves an F1-score of 0.833 on AndroidWorld (outperforming SPA-Bench by 20%), while CRATE-S reaches an F1-score of 0.697 on MobileRisk, demonstrating strong alignment with benchmark ground truths. Code is available at https://anonymous.4open.science/r/CRATE-D580.

### 2. 方法论：核心思想、关键技术细节与算法流程

#### 2.1 核心思想

CRATE 采用 **"步骤级后果推理 → 轨迹级聚合"** 的两阶段评估范式：
- 将长轨迹拆解为独立的步骤对，逐步骤进行分析；
- 将视觉轨迹压缩为高密度文本证据；
- 最后在轨迹层面综合证据、作出判定。

#### 2.2 阶段一：步骤级后果推理（Step-level Consequence Reasoning）

- **输入**：任务描述 I、前动作截图 sᵢ₋₁、执行动作 aᵢ。
- **过程**：独立地将每个步骤对 (sᵢ₋₁, aᵢ) 送入 VLM 评估器，生成结构化步骤级证据（公式 (1)）：

  `(cᵢ, eᵢ) = VLM(sᵢ₋₁, aᵢ, I | p_s)`

  - cᵢ：与任务完成相关的视觉线索文本描述；
  - eᵢ：推断出的动作效果文本描述；
  - p_s：步骤级后果推理的提示词（prompt）。

- **关键技术细节**：模型仅依赖 **"前动作截图 + 动作"**（而非 "动作前截图 + 动作 + 动作后截图" 三元组）来推断动作后果，利用 VLM 固有的世界模型能力消除冗余跨状态计算；各步骤独立处理，支持批量推理加速；同时该模块起到**语义压缩**作用，过滤视觉噪声。

#### 2.3 阶段二：轨迹级聚合（Trajectory-level Aggregation）

- **输入**：任务描述 I、所有步骤级证据 {(cᵢ, eᵢ)}、最终截图 sₙ。
- **过程**（公式 (2)）：

  `o = VLM({(cᵢ, eᵢ)}ⁿᵢ₌₁, I, sₙ | p_t)`

  - 评估器先显式列出任务中的全部必要条件；
  - 逐条检查是否存在"直接、清晰、无歧义"的证据；
  - 最终输出二值化任务完成判定 o ∈ {0, 1}；
  - 任何一条条件不清楚或未满足，则判定为失败。

#### 2.4 CRATE-S：操作安全评估扩展

- 与 CRATE 共享同一两阶段框架，但**移除任务描述 I**（安全评估不依赖任务指令，是任务无关的）。
- 步骤级推理中额外预测二值安全风险标签 rᵢ ∈ {0, 1}，实现**细粒度风险定位**；
- 轨迹级聚合时仅基于步骤级证据，采取**保守判定原则**：只要任一步骤存在明确风险，整条轨迹即判为不安全。
- 完整流程见 Algorithm 1（见论文原文）。

### 6. 主要结论与发现

- **CRATE 优于现有方法**：在 AndroidWorld 上，以 Qwen2.5-VL-72B-Instruct 为骨干，CRATE 取得 0.930 的 Accuracy 和 0.833 的 F1-score，较 SPA-Bench（F1=0.623）提升约 20 个百分点；在 CRATEBench 上同样一致领先；
- **CRATE-S 在安全评估上表现优异**：在 MobileRisk 上取得最高 F1-score（0.697，Qwen2.5VL 骨干），同时步骤级风险定位得分最高（28.8），优于 OS-Sentinel 等基线；
- **开源模型在新框架下可与闭源模型竞争**：除 SPA-Bench 之外，Qwen2.5VL 作为评估器整体优于 GPT-4o，说明良好的评估框架可以降低对超大闭源模型的依赖；
- **消融结果验证了核心设计**：去除步骤级推理后，Qwen2.5VL 出现严重的过度乐观偏差（Recall=1.000 但 Precision=0.480），证明两阶段设计有效缓解了上下文过载；仅使用最终截图则因信息不足而性能下降；

- **代理能力分层分析**：在更长步骤的复杂任务中代理容易遗漏关键里程碑；内容类（Toutiao）、社交类（WeChat）和工具类（Google Maps）应用的 UI 复杂度较高，代理表现相对更差。

### 7. 优点与亮点

- **方法新颖性强**：首次提出"步骤级后果推理 + 轨迹级聚合"的两阶段评估范式，将长轨迹压缩为高密度文本证据，与现有"整条轨迹一次性处理"的范式形成明确区分；
- **可解释性强**：评估过程产生结构化的步骤级证据（视觉线索 + 动作效果），最终判定附有详尽的理由说明，而非黑盒式打分；
- **不依赖人工标注里程碑**：与 SPA-Bench 和 A3 需要预定义关键组件或关键状态不同，CRATE 完全无需人工介入即可自适应到新任务；
- **通用性与兼容性好**：同时支持开源（Qwen2.5-VL-72B）和闭源（GPT-4o）模型；同一框架可无缝扩展到安全评估（CRATE-S），做到"一框架两用"；
- **操作安全评估的粒度优势**：CRATE-S 不仅给出轨迹级风险判定，还能定位具体的不安全步骤，延迟惩罚得分显著优于基线；
- **工程实用性**：步骤独立推理天然支持批量并行，具有较高的推理加速潜力。

### 8. 不足与局限

- **场景覆盖有限**：CRATE 仅在移动端（Android）场景验证，未扩展到桌面 GUI 或 Web 场景，其视觉层级结构差异可能影响方法的可迁移性；
- **仅支持事后评估**：当前验证全部基于离线轨迹，未探索作为在线奖励模型、实时反射模块或闭环执行监控的潜力；
- **受限于底层 VLM 能力**：虽然框架降低了认知负担，但步骤级推理和轨迹级聚合的质量仍受制于 VLM 自身的视觉理解、推理和忠实度，错误会向上传播；
- **自建基准的样本规模偏小**：CRATEBench 真实设备轨迹仅 62 条（24 成功 / 38 失败），正负样本不均衡，可能影响评估置信度；
- **安全评估的保守偏差**：CRATE-S 的判定仅依赖"显式可验证"的证据，可能漏掉隐性风险；在 GPT-4o 骨干下 Precision 偏低（0.576），表明存在一定的误报倾向；
- **数据与隐私细节未完全公开**：论文提及涉及真实应用和个人账户的登录实验，但未详细说明脱敏流程和发布计划；
