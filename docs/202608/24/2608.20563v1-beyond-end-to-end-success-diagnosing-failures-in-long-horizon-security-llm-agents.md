## 摘要
长时域安全LLM智能体必须在许多相互依赖的交互中携带信息和决策，后续操作往往依赖于早先发现的服务、状态或访问权限。这使得最终任务成功难以解释：智能体可能在其感兴趣的能力得以发挥之前就已失败。我们提出了一种诊断方法，通过检查点为安全任务设置埋点，区分能力暴露前后的失败，并使用受控干预来测试疑似上游瓶颈。我们在四个任务族上评估了该方法，涉及延迟重用已发现信息、重用观察到的状态、从失败策略中恢复以及在不确定结果后做出决策。在观察到的状态重用方面，检查点分析显示，Gemini 2.5 Flash的许多失败发生在模型观察到其后续预期重用的状态之前。在一项预先指定的92种子研究中，针对性的协议消歧指导将状态观察率从匹配的非指导对照消息下的65.5\%提高到95.4\%。使用Gemini 3.7 Flash重复相同设计则产生相反效果，而状态观察不再可靠地预测任务完成。这些结果表明，失败的主要来源可能在不同模型代际之间发生转移，这促使评估应诊断长时域安全智能体在何处以及为何失败，而非仅依赖总体任务成功率。

## Abstract
Long-horizon security LLM agents must carry information and decisions across many dependent interactions, where later actions often depend on services, state, or access discovered much earlier. This makes final task success difficult to interpret: an agent may fail before it ever reaches the point where the capability of interest can be exercised. We present a diagnostic methodology that instruments security tasks with checkpoints, separates failures before and after capability exposure, and uses controlled interventions to test suspected upstream bottlenecks. We evaluate the methodology across four task families involving delayed reuse of discovered information, reuse of observed state, recovery from failed strategies, and decision making after uncertain outcomes. On observed state reuse, checkpoint analysis shows that many Gemini 2.5 Flash failures occur before the model observes the state it is later expected to reuse. In a pre-specified 92-seed study, targeted protocol-disambiguation guidance increases state observation from 65.5\% under a matched non-guidance control message to 95.4\%. Repeating the same design with Gemini 3.7 Flash produces the opposite effect, while state observation no longer reliably predicts task completion. These results show that the dominant source of failure can shift across model generations, motivating evaluation that diagnoses where and why long-horizon security agents fail rather than relying only on aggregate task success.

## 一、论文的核心问题与整体含义（研究动机和背景）

- **核心问题**：长时域（long-horizon）安全 LLM 智能体的最终任务成功率难以解释。智能体在完成目标前往往需要经历大量相互依赖的交互步骤，后续操作常依赖早先发现的服务、状态或访问权限。如果智能体在目标能力（如状态复用、策略恢复、歧义决策）尚未被真正检验之前就已失败，那么端到端成功率无法揭示失败的真实位置和原因。
- **整体含义**：端到端成功率的不足在于它混淆了两类截然不同的失败——**能力暴露前的失败**（上游发现/可达性问题）与**能力暴露后的失败**（目标能力本身的缺陷）。仅凭最终成功率，一个从未观察到所需状态、因而根本无法复用该状态的智能体，会被误判为"状态复用能力差"。
- **研究愿景**：评估不应只问"任务是否完成"，还应诊断"智能体是否到达了能力可被检验的关键点"以及"到达之后发生了什么"。这促使作者提出一种检查点（checkpoint）加受控干预（controlled intervention）的系统性诊断方法。

## 二、论文提出的方法论

### 1. 核心思想

- 在安全任务中埋设**检查点**，将长轨迹分解为可观测的进度节点。
- 用**暴露（exposure）**概念区分失败位置：暴露指智能体首次获得执行目标能力所需信息或状态的关键检查点。报告三类指标：
  - 端到端成功率；
  - 关键检查点（gating checkpoint）到达率；
  - 到达暴露点后的成功率。
- 当检查点分析锁定上游瓶颈后，使用**匹配的受控干预**（Rescue–Placebo）进行因果验证，而非仅依赖轨迹推断。

### 2. 关键技术细节

- **检查点语义**：每个检查点必须基于轨迹中实际可见的证据（命令输出、服务响应等）进行判定；尝试动作本身不算达到检查点。对随机化任务值，将可见证据与生成的真实值比对，但证据本身必须已暴露给智能体。
- **暴露条件化（exposure conditioning）**：未到达暴露点的失败仍保留在端到端结果中，不修正任务或强制智能体到达关键点；报告总体成功率和暴露条件化成功率以对比解释。
- **受控干预设计**：
  - 对每个确定性环境种子，运行三组匹配实验：**Baseline**（无附加消息）、**Rescue**（提供针对疑似障碍的目标信息）、**Placebo**（结构匹配但无任务相关指导的无关消息）。
  - Rescue 与 Placebo 是主要对比，因为它隔离了目标信息本身与"额外插入消息"这一一般效应。
  - 干预可在固定模型轮次或指定执行事件后触发；触发条件不依赖任务是否成功，也不检查生成的任务值。
- **统计检验**：配对二元结果使用**双侧 McNemar 精确检验**，α = 0.05；主要比较 Rescue 与 Placebo 的不一致配对方向。
- **实验治理与可复现性**：
  - 冻结实验配置：预先生成并存储执行顺序、条件分配、干预触发条件；
  - 使用加密摘要保护脚手架配置和干预消息内容；
  - 追加式账本记录每次运行的完整生命周期；基础设施失败与任务失败分开记录，不静默重跑或替换；
  - 正式研究须经候选、审查、批准流程，批准后配置和源码冻结。

### 3. 四种诊断任务族

| 任务 | 变体 | 研究焦点 |
|---|---|---|
| Delayed Secret Reuse (DSR) | Short, Long | 延迟秘密复用 |
| Controlled State Reuse (CSR) | Short (2步), Medium (8步), Long (20步) | 受控状态复用 |
| Strategy Recovery (SR) | Control, Explicit, Ambiguous | 策略失败后的恢复 |
| Ambiguous-Outcome Adaptation (AOA) | Transient, Persistent, Explicit | 歧义结果后的决策 |

CSR 是核心受控任务：唯一有意的变体差异是状态观察与状态复用之间的强制中间动作数（2/8/20），用于隔离"未能观察到状态"与"观察到但未能复用"两类失败。CSR 的关键检查点为 **C3**（精确观察到生成状态），C3 是状态复用能力的暴露点。

## 六、论文的主要结论与发现

1. **Gemini 2.5 Flash 在 CSR 上的失败主因在上游发现阶段**：
   - Flash 端到端成功率仅 5/15 (33%)，Pro 为 15/15 (100%)；
   - 但 Flash 仅 6/15 到达 C3（状态观察点），其中 5 次最终成功——说明"失败主要是没观察到状态"，而非观察后无法复用；9 次失败中的 9 次都发生在暴露之前。
2. **协议发现瓶颈是 Gemini 2.5 Flash 的因果性上游障碍**：
   - 在 92 种子确认性研究中，Rescue 使 C3 到达率从 Placebo 的 65.5% 提升至 95.4%（87 对中 29 对利于 Rescue、3 对利于 Placebo，McNemar p = 2.56×10⁻⁶）；
   - 到达 C3 后，Flash 的后续完成率高达 205/210 (97.6%)，进一步印证上游瓶颈为主。
3. **跨代复制出现干预反转**：
   - Gemini 3.7 Flash 在相同设计下，Rescue 的 C3 到达率为 79.1%，Placebo 反而达 98.9%（19 对利于 Placebo、1 对利于 Rescue，p = 4.01×10⁻⁵）；
   - 到达 C3 后 Gemini 3.7 的最终成功率仅 36.1%（90/249），远低于 Gemini 2.5 的 97.6%——说明对更模型，状态观察不再可靠预测完成，失败主因转移到了下游。
4. **检查点证据揭示了最终成功率掩盖的任务设计缺陷**：
   - DSR-Long 的更低成功率源于新增路由发现而非更差的秘密记忆；
   - SR 性能天花板意味着任务已无法区分当前模型能力；
   - AOA 的预期分支（重复访问首选策略）从未被触发，任务无法检验其设计意图。
5. **结论**：长时域安全智能体的失败主因可随模型代际发生根本性转移；仅报告聚合成功率不足以理解模型能力，需要结合检查点暴露分析和受控干预的"位置+原因"诊断框架。

## 七、优点

- **方法论创新**：提出"暴露前失败 vs. 暴露后失败"的明确区分，为长时域智能体评估提供了比中间过程指标更精确的诊断视角——中间进度只能说明"做了什么"，暴露分析说明"目标能力是否真的被检验"。
- **因果验证设计**：Rescue–Placebo 匹配干预将轨迹分析从"假设生成"推进到"假设检验"，避免了单纯从轨迹推测原因的不可靠性；消息在字节数和行数上匹配，减少了长度效应混淆。
- **严格的实验治理**：冻结清单、预定执行顺序、加密摘要、追加式账本、基础设施失败分离——这使研究可复现，并防止"看到结果后再改设计"的偏倚。
- **跨代复制的胆识**：在发现干预效果反转后没有修改设计或掩盖结果，反而如实报告。这种对"意外结果"的保留是检测模型行为真实变化的关键。
- **统计严谨性**：使用配对精确 McNemar 检验而非简单地比较比例，对缺失观察做极端敏感性界分析，并预先区分主要结局与次要结局。
- **诊断价值突出**：在 SR 和 AOA 未能按预期工作时，作者利用检查点证据明确说明"任务没有检验其设计意图"，展示了诊断方法本身对 benchmark 质量评价的适用性。

- **干预内容的外部效度**：Rescue 消息仅针对 CSR 中的 HTTP/SSH 协议歧义，是一种特定于任务的诊断探针；它不能推广为通用改进方法，作者也明确此点。
- **长期可靠性未测**：单次运行快照，未评估同一模型在同一种子上的运行间一致性（run-to-run consistency），而可靠性本身是长时域智能体的关键维度。
