## 摘要
大型语言模型（LLM）智能体日益通过涉及用户指令、工具使用、外部观察和记忆的长视界轨迹进行操作。现有基准主要评估行为结果，但对细粒度归因分析的支持有限。我们引入轨迹归因这一任务，并为此开发了一个基准和标注框架。该基准在统一组件模式之下组织异构轨迹，并提供主要归因组件的标注，以及适用情况下的攻击链和执行链。利用来自AgentDojo以及Agent3Sigma的Stage和Canary设置中的轨迹实例化该基准，产生了超过1,300条标注轨迹，涵盖任务对齐行为、不安全行为和安全性拒绝。该基准定义了两个评估任务——主要归因定位和归因链恢复，并提供了基于增量轨迹贡献和组件级留一扰动法的参考基线。它捕捉了多种归因设置，包括局部与长程归因以及结构化归因链。参考基线结果在这些设置之间表现出显著的性能差异，初步刻画了基准的归因挑战。除这一初始实例化外，我们发布了一个可复用的标注技能，使得新智能体模型生成的轨迹能够在同一框架下被标准化、标注和评估。项目资源和未来版本可在https://github.com/chenjing-2024/agent-trajectory-attribution获取。

## Abstract
Large language model (LLM) agents increasingly operate through long-horizon trajectories involving user instructions, tool use, external observations, and memory. Existing benchmarks primarily evaluate behavioral outcomes but provide limited support for fine-grained attribution analysis. We introduce trajectory attribution and develop a benchmark and annotation framework for this task. The benchmark organizes heterogeneous trajectories under a unified component schema and provides annotations of the primary attribution component, together with attack and execution chains where applicable. Instantiating the benchmark with trajectories from AgentDojo and the Stage and Canary settings of Agent3Sigma yields more than 1,300 annotated trajectories covering task-aligned actions, unsafe actions, and safety refusals. The benchmark defines two evaluation tasks, primary attribution localization and attribution-chain recovery, and provides reference baselines based on incremental trajectory contribution and component-level leave-one-out perturbation. It captures diverse attribution settings, including local and long-range attribution as well as structured attribution chains. Reference baseline results exhibit substantial performance differences across these settings, providing an initial characterization of the benchmark's attribution challenges. Beyond this initial instantiation, we release a reusable annotation skill that enables trajectories generated by new agent models to be standardized, annotated, and evaluated under the same framework. Project resources and future releases are available at https://github.com/chenjing-2024/agent-trajectory-attribution.

- **整体含义**：该工作将智能体评估从“结果导向”扩展到“过程导向”，为失败诊断、安全审计和可解释智能体研究提供了基础设施，同时发布可复用的标注技能，使新模型生成的轨迹也能在同一框架下被标准化和评估。

## 2. 论文提出的方法论

### 核心思想
- 将轨迹表示为有序组件序列，把归因定义为组件级排序问题：给定目标组件 `ct`，对候选集（目标之前的所有组件）按贡献程度排序。
- 参考归因结构包含两部分：**主归因组件（primary attribution）** 和可选的 **有序归因链（attribution chain）**。主归因是标注的根因，归因链包含传递信息、建立语境或执行中间步骤的其他相关组件。
- 针对不安全行为，进一步区分 **攻击链（attack chain）** 和 **执行链（execution chain）**：攻击链追踪对抗性影响的传播路径，执行链描述不安全行为最终实现的下游组件序列。

### 关键技术细节
1. **统一组件模式（Schema）**：每个组件由 `Role`（system/user/assistant/tool）和 `Content`（文本化交互内容）两个字段表示，将不同框架的异构轨迹标准化为统一的有序组件序列。
2. **行为感知标注方案**：将目标行为分为三类——任务对齐动作、不安全动作、安全拒绝。每类轨迹都标注一个主归因组件；不安全轨迹若存在分布式因果结构则额外标注攻击/执行链。
3. **标注验证协议**：两阶段验证——结构验证（主归因在目标之前、链内组件按时间顺序、组件有效）和语义验证（LLM 评审器检查是否符合归因定义）。失败则修复并重新验证。
4. **评测任务**：
   - **主归因定位**：使用 Hit@1 和 MRR。
   - **归因链恢复**：使用 Recall@K 和 MAP。

### 参考基线（公式）
- **增量归因（Incremental Attribution）**：  
  `s_inc_i = log p(y | c≤i) − log p(y | c≤i−1)`，通过逐步引入组件后目标行为似然的变化来打分。
- **留一法归因（Leave-One-Out, LOO）**：  
  `s_loo_i = avg log p(y|τ) − avg log p(y|τ(−i))`，移除候选组件前后目标行为平均 token 级对数似然的差值。

## 3. 实验设计

### 数据集 / 场景
- **基准来源**：AgentDojo、Agent3Sigma Stage、Agent3Sigma Canary。
- **轨迹总量**：1,351 条标注轨迹，覆盖三类目标行为：
  - 任务对齐动作：409 条（30.3%）
  - 不安全动作：532 条（39.4%）
  - 安全拒绝：410 条（30.3%）
- **环境覆盖**：通信协作、银行交易、旅行规划、工作区操作、数据分析、代码开发、文档处理、网页交互、文件管理、系统管理等。

### 对比方法
- 本文未与其他归因方法进行横向对比，而是建立了两个简单参考基线（增量归因和留一归因），用于刻画基准的难度和结构特征。

### 评估指标
- 主归因定位：Hit@1、MRR。
- 归因链恢复：Recall@3、MAP。

### 主要实验结果
- 增量归因在所有目标上的整体 Hit@1 为 0.369，MRR 为 0.616；留一归因整体 Hit@1 为 0.537，MRR 为 0.713。
- 任务对齐动作的归因最容易（局部情况下增量归因 Hit@1 达 1.0），不安全动作和安全拒绝难度更高。
- 局部归因（d=1）显著优于长程归因（d≥2），表明长距离因果依赖是主要挑战。
- 链级归因（攻击链/执行链恢复）总体上比主归因定位更难，尤其攻击链在 AgentDojo 上增量归因的 Recall@3 仅 0.0，凸显了分布式因果结构的难度。

## 6. 论文的主要结论与发现

- **轨迹归因是一个独立的、有价值的评估问题**，区别于传统的结果导向评估和单输入归因，需要跨整个轨迹推理。
- **统一组件模式和标注框架能有效标准化异构轨迹**，使来自不同基准的轨迹可以在同一协议下进行归因评测。
- **基准覆盖了多样化的归因难度**：从简单的局部归因（如 d=1 的任务对齐动作，基线几乎完美）到需要长距离依赖和分布式链恢复的复杂场景（如攻击链恢复，部分子集上基线 Recall@3 为 0）。
- **长距离归因是核心挑战**：主归因组件与目标行为之间间隔越远，基线性能下降越明显。
- **多步因果链恢复显著更难**：不安全行为往往不是单一组件触发，而是通过攻击链和执行链传播，两种基线都无法很好恢复完整链结构。
- **留一法在多数场景下优于增量法**（尤其在长距离和链恢复上），但两者仍远未解决该问题，为未来方法留下了巨大空间。

## 7. 优点

- **问题定义清晰**：将轨迹归因形式化为主归因定位 + 归因链恢复，结构简洁且具有可操作性。
- **统一基准设计**：提出跨来源的统一组件模式，实现不同类型轨迹的标准化，克服了现有基准各自为政的碎片化问题。
- **覆盖三类行为**：同时评估任务对齐动作、不安全动作和安全拒绝，使归因分析不局限于失败定位，而适用于更广泛的智能体行为理解。
- **细粒度链标注**：在不安全轨迹中区分攻击链和执行链，能更精确地刻画分布式因果路径，优于简单“多原因无序集合”的标注方式。
- **可扩展性**：发布可复用的标注技能，新模型生成的轨迹可自动标准化和标注，基准具备适应未来智能体演化的能力。
- **验证协议**：结构 + 语义两阶段验证，并带有修复机制，提升了标注质量的一致性。

## 8. 不足与局限

- **基准来源有限**：仅覆盖 AgentDojo、Agent3Sigma Stage 和 Canary 三个基准家族，无法代表所有新兴智能体系统（如多智能体协作、具身智能等）。
- **LLM 标注可能引入偏差**：虽然有人工复核，但部分轨迹可能存在替代性合理解释，标注的“唯一根因”假设可能与实际复杂因果冲突。
- **组件级粒度限制**：目前只标注到组件（如一条工具调用），未扩展到句子或词元级，无法支持更细粒度的归因分析。
- **基线过于简单**：仅两个似然类基线，评估结果只提供难度参考，不能代表最佳性能，且未与现有失败归因方法（如 Who&When、TraceElephant）进行直接对比。
- **计算资源未说明**：缺少对算力、模型版本和成本的描述，不利于他人复现标注和基线实验。
- **链标注只覆盖不安全轨迹**：任务对齐和安全拒绝行为没有链级标注，限制了归因链结构对全行为类型的普遍性验证。
- **潜在评估偏差**：局部 d=1 的任务对齐案例中，候选集极小（几乎只有用户指令和系统组件），导致 Hit@1 接近 1.0，可能高估某些方法的“真实”性能，论文虽已指出这一点，但基准中这类近确定性样本的占比仍需关注。
