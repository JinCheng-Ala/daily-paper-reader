## 摘要
当长时程智能体执行失败时，结果级评估仅揭示失败结果，而无法指出决定性错误在轨迹中的进入位置。开发者随后必须检查完整执行过程以识别责任角色，并定位最早的决定性根本原因步骤。现有故障归因基准主要聚焦于较短轨迹，导致对数百个记录步骤的诊断研究不足。我们提出了LongRCA Bench，包含五个领域中的1140条无注入错误失败轨迹，并提供了独立评分的人工标注，标注责任角色与最早的决定性根本原因步骤。轨迹中位数包含145步，最强基线仅达到13.2%的精确根因步骤准确率。我们进一步提出根因轨迹归因（RCTA），一种免训练方法，从段摘要中检索候选错误步骤，并将其追溯至可用的早期交接指令。使用相同骨干模型、基准实例与评分协议，RCTA达到51.1%的责任角色准确率与24.1%的精确根因步骤准确率。这些结果强调在长轨迹故障诊断中，需将责任角色归因与精确根因步骤定位作为独立目标进行评估。

## Abstract
When a long-horizon agent execution fails, outcome-level evaluation reveals the unsuccessful result but not where the decisive error entered the trajectory. Developers must then inspect the full execution to identify the responsible role and localize the earliest decisive root-cause step. Existing failure-attribution benchmarks largely focus on shorter traces, leaving diagnosis across hundreds of recorded steps underexplored. We introduce LongRCA Bench, comprising 1,140 failed trajectories across five domains without injected errors. It provides independently scored human labels for the responsible role and earliest decisive root-cause step. The median trajectory contains 145 steps, and the strongest baseline reaches only 13.2% exact root-step accuracy. We further present Root-Cause Trajectory Attribution (RCTA), a training-free method that retrieves candidate error steps from segment summaries and traces them to available earlier handoff instructions. Using the same backbone, benchmark instances, and scoring protocol, RCTA reaches 51.1% responsible-role accuracy and 24.1% exact root-step accuracy. These results highlight the need to evaluate responsible-role attribution and exact root-step localization as separate targets in long-trajectory failure diagnosis.

- **整体含义**：本文主张将**责任角色归因**与**根因步骤定位**视为两个独立的任务目标来分别评估，不能混为一谈（例如不能从所选根因步骤的发出者来推断责任角色）。该工作填补了长轨迹失败诊断方向上的基准和方法空白。

## 2. 论文提出的方法论

### 2.1 基准构建方法（LongRCA Bench）
- **数据来源**：从 5 个现有基准（SWE-bench Pro、Terminal Bench 2、TravelPlanner、VitaBench、WebArena Verified）中收集**自然发生的失败轨迹**，未注入任何合成错误。
- **筛选条件**：原始基准评估器标记为失败的已完整执行轨迹；排除基础设施、冒烟测试、调试等非完整尝试。
- **轨迹标准化**：将不同源的异构日志统一转换为具有 0-based 索引的有序历史记录，每条记录包含步骤索引、角色名称和原始内容。
- **人工标注**：22 名计算机科学硕博生参与。第一轮 100 条轨迹用于校准协议，全规模阶段收集 1,444 条标注，平均每条轨迹 1.31 个标注。标注者需返回三个字段：责任角色、最早决定性命根因步骤、基于轨迹证据的书面理由。
- **质量控制和标签消解**：结构验证（索引和角色合法性）+证据审查；同一轨迹的多重标注出现分歧时，由资深标注者依据原始任务、完整历史、评估器结果和书面理由进行消解。

### 2.2 RCTA（Root-Cause Trajectory Attribution）方法
- **核心思想**：将广泛的轨迹搜索与聚焦的原文比较分离，采用"分段摘要召回候选错误步骤 → 回溯交接指令"的策略。
- **处理流程**（共 3 个阶段，属于训练自由方法）：
  1. **轨迹切分**：基于规则（字符上限、步数上限）将长轨迹划分为连续片段，不借助语言模型。
  2. **候选错误步骤召回**：对每个片段调用一次 LLM 生成摘要并提出候选错误步骤；再调用第二次 LLM 将相邻片段摘要合并为按子目标组织的轨迹大纲，从中**合并并去重候选步骤**。
  3. **候选追溯与最终归因**：对执行者或验证者角色的候选步骤，检索发给该角色的最近交接指令；对其它候选则检索最近的交接指令作为计划上下文。最终调用 LLM 将候选的原始文本与交接指令比较，判定根因是**指令步骤本身**还是**后续偏离步骤**。
- **关键设计**：角色和根因步骤作为**独立输出字段**分别预测和验证；程序化验证器检查角色是否出现在轨迹中、根因步骤是否有效、引用文本是否可溯源；无效输出有一次重试机会。
- **责任判断规则**：交接指令已包含错误则选指令步骤为根；后续步骤偏离指令或引入新错误则选该步骤；成功修复的早期错误被排除；错过验证的后期验证者错误不能替代引入错误的步骤。

## 3. 实验设计

### 3.1 数据集与基准
- **LongRCA Bench** 包含 1,140 条失败轨迹、总计 178,137 个记录步骤，平均长度 156.3 步，中位数 145 步，最长 728 步。
- 根因到终点距离：中位数 48 步，90 百分位 183 步，最大 605 步；49.0% 的轨迹在根因之后超过 50 步才结束，28.4% 超过 100 步，7.7% 超过 200 步。
- 来源分布：TravelPlanner 685 条（60.1%）、WebArena Verified 177 条、SWE-bench Pro 128 条、VitaBench 108 条、Terminal Bench 2 42 条。
- 生成模型覆盖：MiniMax-M2.5（681 条）、Kimi-K2.5（276 条）、Qwen3.5-Plus（183 条）。

### 3.2 对比方法与实验设置
- 对比 5 种免训练基线（全部使用 DeepSeek-V4-Flash 骨干模型）：
  1. **All-at-once**：一次调用输入全部轨迹。
  2. **Step-by-step**：逐顺序扫描判断。
  3. **Binary search**：递归二分定位根因区域。
  4. **ECHO**：层次化上下文 + 共识投票。
  5. **FALAT**：依赖引导搜索。
- **评估指标**：责任角色准确率、根因精确准确率（exact）、根因 ±5 准确率、源加权有效输出根因 MAE。
- **辅助分析**：按轨迹长度（≤100、101–200、201–400、>400）和根因到终点距离（≤10、11–50、51–100、>100）进行分层分析。

## 4. 资源与算力

## 6. 论文的主要结论与发现

1. **长轨迹根因定位极具挑战性**：最强基线 ECHO 仅达 13.2% 精确根因步骤准确率，有力证明了长轨迹诊断的难度。
2. **RCTA 全面优于基线**：在角色准确率（51.1% vs 27.5%）、根因精确准确率（24.1% vs 13.2%）、±5 准确率（37.4% vs 24.7%）和 MAE（38.6 vs 50.4）上均显著领先，分别提升 23.6、10.9、12.7 个百分点和减少 11.8 步 MAE 误差。
3. **角色归因比步骤定位更容易**：所有方法中角色准确率普遍高于根因步骤准确率，侧面说明两任务是不同的能力维度。
4. **依赖引导搜索在此场景下不足**：FALAT 在匹配设置下仅达到 2.8% 精确准确率，低于最直接的 All-at-once 提示方法（7.6%），不足以应对长轨迹。
5. **性能随长度下降但非单调**：大部分方法在 100 步以上出现显著下降；RCTA 在 >400 步区间恢复到 31.0%，但该区间仅 42 条轨迹且源组成不同。

## 7. 优点

- **基准设计精心**：
  - 使用**自然失败**而非注入错误，更贴近实际；
  - 全量人工标注 + 多名标注者一致性统计 + 证据消解流程，标签质量有保障；
  - 提供完整决策规则，公开透明。
- **任务定义清晰**：将责任角色与根因步骤作为独立评分目标，避免将二者混为一谈，更符合真实诊断需求；明确排除了成功修复的错误，区分了根因、传播和暴露。
- **方法设计巧妙**：RCTA 的"分段摘要筛选候选 → 回溯交接指令"范式将长轨迹搜索成本与精确文本比较分离，是一种实用且可扩展的免训练方案。
- **评估协议严格**：所有方法在相同骨干、相同数据和相同评分规则下比较；对输出有效性进行程序化验证；缺失或无效输出计入错误。
- **数据集规模与多样性突出**：1,140 条全标注轨迹覆盖 5 个领域、多种智能体组织和 3 种生成模型，优于多数现有基准（如 Who&When 的 184 条、RootSE 的 102 条）。

## 8. 不足与局限

- **标注主观性与低一致性**：根因步骤精确一致性仅 39.5%，虽然论文披露了这一事实并采取了消解流程，但标签的根本主观性仍然存在，可能限制基准的可靠性上限。
- **标签范围有限**：仅评分责任角色和根因步骤两个标签，中间因果链不作为目标，无法评估完整因果链重建能力。
- **评估设置受限**：仅评估**离线事后诊断**，不测试早期预警或在线干预，结果不能与在线检测协议的基准直接比较。
- **骨干依赖**：所有方法使用同一骨干，绝对性能可能随更强骨干显著变化，结论限于匹配骨干场景。
- **分层分析缺乏因果性**：长度与根因距离分箱中源组成混杂，不能得出独立因果结论。
- **标注成本高**：每条 30–40 分钟的标注时间，使得扩展更大规模数据集的成本较高；TravelPlanner 占比 60.1%，数据存在源分布不均衡。
- **RCTA 的局限**：
  - 未做组件消融，难以确定各环节的具体贡献；
  - 有效输出验证仅保证"文本可溯源"，不能验证引用指令确实包含相同因果错误；
  - 308/1,140 个输出的阶段数超出请求范围（提示解析容错，但可能影响一致性）。
