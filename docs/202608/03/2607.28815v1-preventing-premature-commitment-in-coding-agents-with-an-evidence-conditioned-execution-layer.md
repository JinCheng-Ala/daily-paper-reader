## 摘要
基于 LLM 的编码智能体常常在检查足够的仓库证据以证明变更合理性之前就开始编辑源代码或提交补丁，我们将这种失败模式称为“过早承诺”。我们提出了 ECLoop，一个介于智能体与仓库之间的执行层，用于强制执行基于证据条件的执行。对于每个任务，ECLoop 利用问题描述和仓库结构来编译一组条件，规定智能体在进行每种类型的代码修改或提交补丁之前应观察到的内容。在执行过程中，ECLoop 跟踪智能体运行时轨迹已满足哪些条件，并推迟任何所需条件未满足的拟议操作。在 SWE-bench Verified 的全部 500 个实例上，使用两种语言模型和两种智能体框架进行评估，ECLoop 无需模型重新训练或框架更改即可将 Pass@1 提高 4.8–11.8 个百分点。消融实验表明，ECLoop 的三个操作各自具有独特价值，并且结构化证据条件优于等效的自然语言摘要。这些收益不会产生额外推理成本：通过在智能体采取不支持的动作之前进行引导，ECLoop 将平均 token 消耗降低了最多 12.1%。

## Abstract
LLM-based coding agents often edit source code or submit patches before examining enough repository evidence to justify the change, a failure pattern we call premature commitment. We present ECLoop, an execution layer that interposes between the agent and the repository to enforce evidence-conditioned execution. For each task, ECLoop uses the issue description and repository structure to compile a set of conditions specifying what the agent should observe before each type of code modification or patch submission. During execution, ECLoop tracks which conditions the agent's runtime trajectory has satisfied and postpones any proposed action whose required conditions remain unmet. Evaluated on all 500 instances of SWE-bench Verified with two language models and two agent scaffolds, ECLoop raises Pass@1 by 4.8-11.8 percentage points without model retraining or scaffold changes. Ablation experiments show that each of ECLoop's three operations contributes distinct value and that structured evidence conditions outperform an equivalent natural-language summary. These gains come at no additional inference cost: by redirecting the agent before it pursues unsupported actions, ECLoop lowers average token consumption by up to 12.1%.

## 1. 核心问题与研究动机

- **问题定义**：基于 LLM 的编码智能体常常在尚未收集到足够仓库证据时，就执行编辑源代码或提交补丁等“承诺性动作”。论文将这种失败模式称为 **“过早承诺”（premature commitment）**。
- **典型表现**：智能体在查看目标函数后做出看似合理的修改，但忽略了相关调用者、其他实现、测试或行为约束；或者在单条测试通过后即提交补丁，却未检查其他相关行为。
- **现有缺陷**：现有智能体运行时只会执行智能体提出的动作，无法独立判断当前收集的证据是否足以支撑该动作。提示（prompt）层面的建议不能验证证据是否真正被收集，也不能阻止未受支持的动作执行。
- **核心意义**：需要将“提出一个动作”和“确认已具备执行该动作的证据”两件事分离开来，在执行层面进行强制检查，从而减少因过早行动导致的修复失败。

## 2. 方法论：ECLoop

### 基本思想
- ECLoop 是一个**证据条件化执行层**，位于智能体动作与仓库之间。
- 将动作分为两类：
  - **信息收集动作**（文件读取、代码搜索、诊断命令等）：自由执行，不加限制。
  - **承诺动作**（源代码编辑、最终补丁提交）：仅在相关证据条件满足时放行。
- 智能体仍然负责如何探索仓库和构造修复，ECLoop 只控制“何时允许承诺”。

### 关键技术细节
- **证据规格编译**：每次任务开始时，用语言模型分析问题描述和仓库结构，生成一组结构化条件集合 \( C_q = \{c_1, \dots, c_m\} \)。
- **条件形式化表示**：每个条件被转为五元组：
  \[
  \phi_i = \langle b_i, v_i, R_i, sat_i \rangle
  \]
  - \( b_i \)：适用的承诺动作类型；
  - \( v_i \)：具体的程序实体（函数、文件等）；
  - \( R_i \)：运行时轨迹中需要出现的事件模式；
  - \( sat_i(Z_t) \)：在当前证据状态 \( Z_t \) 下是否已被满足。
- **实体解析与接地**：通过 AST 遍历、调用图、类层次结构，将抽象角色（如“待编辑函数的调用者”）解析为具体仓库实体。无法解析的条件会被移除，避免不可检查的约束。
- **全局证据缺口**：
  - 从智能体的运行时轨迹中提取事件，得到证据状态 \( Z_t \)；
  - 计算当前未满足的条件集合 \( U_t = \{\phi_i \in C_t \mid sat_i(Z_t) = 0\} \)；
  - 将 \( U_t \) 渲染为文本指导 \( g_t \) 加入模型上下文，引导智能体继续调查。
- **动作特异性门控**：当智能体提出承诺动作 \( a_t \) 时，计算仅与该动作相关的证据缺口：
  \[
  U_t(a_t) = \{\phi_i \in C_t \mid applies(\phi_i, a_t) \land sat_i(Z_t) = 0\}
  \]
  - 若 \( U_t(a_t) = \emptyset \)，动作放行；
  - 否则暂停动作，将缺失证据返回智能体，最多重复三次；超出保持预算后，通过“审计回退”放行（但会记录未满足条件）。

### 算法流程（文字说明）
1. **任务开始前**：LLM 根据 issue 和仓库结构生成候选条件 → 对接仓库结构进行实体解析和接地 → 得到可用条件集合。
2. **执行过程中**：解析智能体每条命令和输出为结构化事件 → 更新证据状态 → 计算全局证据缺口 → 渲染为上下文指导。
3. **每次承诺动作前**：解析并添加新可接地的条件 → 计算动作特异性缺口 → 若为空放行，否则保持动作并反馈缺失证据。

## 3. 实验设计

### 数据集与基准
- **SWE-bench Verified** 全部 500 个实例，每个实例是一个真实 GitHub issue + 仓库快照 + 保留测试。
- 主要指标：**Pass@1**（单次运行解决比例），并补充 **RRU**（未解决实例的相对下降率），统计显著性用 **exact McNemar test**（p < 0.001）。

### 模型与框架
- 语言模型：**MiniMax-M2.5**（高推理负载）、**GPT-5-mini**。
- 智能体框架：**mini-swe-agent v2**（轻量研究框架）、**OpenAI Codex CLI**（生产级框架）。
- 共构成 4 组“模型 × 框架”配置。

### 对比方法
- **基线**：未加 ECLoop 的同配置智能体，保证相同模型、提示、工具、框架，唯一差异是 ECLoop。
- **Self-Refine**：让模型在 patch 生成后自我审查并反复修改（最多三轮），作为后验式改进对比。
- **消融实验**：在固定 100 个实例子集上，逐一移除 ECLoop 的三大操作：
  - 移除 guidance（不提供全局缺口指导）；
  - 移除 commitment check（不门控承诺动作）；
  - 移除 state update（不随轨迹更新证据状态）；
  - 将结构化条件替换为自然语言摘要。

## 6. 主要结论与发现

- **准确性显著提升**：
  - mini-swe-agent v2 下，GPT-5-mini 的 Pass@1 从 56.2% 提升至 68.0%（+11.8 pp，RRU 26.9%）；MiniMax-M2.5 从 75.8% 提升至 80.6%（+4.8 pp，RRU 19.8%）。
  - Codex CLI 下，GPT-5-mini 从 40.4% 提升至 50.8%（+10.4 pp）；MiniMax-M2.5 从 74.8% 提升至 79.8%（+5.0 pp）。
- **效率不降反升**：所有配置下 token 消耗降低 1.4%–12.1%，成本降低 1.5%–10.2%，因为提前拦截了不当动作，避免了更长但无效的轨迹。
- **后验改进失效**：Self-Refine 在两个模型下分别下降 1.4 pp 和 1.8 pp，说明事后自省无法修复因证据不足而做出的错误决策。
- **组件互补性**：移除任一操作都会显著下降，其中 commitment check 贡献最大（-10 pp），state update 次之（-9 pp），guidance 贡献 +5 pp。
- **结构化条件优于自然语言**：将结构化条件替换为自然语言摘要，Pass@1 下降 10 pp（至 58%），甚至低于移除 guidance 的 63%，说明明确可检查的条件至关重要。

## 7. 优点

- **问题定义清晰**：首次系统性地提出“过早承诺”这一独立失败模式，并将其与动作选择质量区分开。
- **设计可移植**：作为执行层插入现有智能体，不改变模型、提示或动作选择策略，可以适配不同框架（在 Codex CLI 上仅通过 hook 机制集成）。
- **无需重新训练**：条件生成使用同一 LLM，但满意度检查是确定性的，不依赖模型临时判断，提高可靠性。
- **双重证据缺口设计**：
  - 全局缺口用于引导探索；
  - 动作特异性缺口用于控制执行；
  - 兼顾灵活性与安全性。
- **效率与效果兼顾**：不仅提升准确率，还减少 token 消耗，说明干预能减少无效探索。
- **实验设计严谨**：使用随机配对显著性检验，报告 RRU，并在相同配置下进行严格对照。

## 8. 不足与局限

- **对 issue 质量敏感**：证据规格从 issue 描述中提取，如果问题描述模糊，生成的条件可能不完整或包含无关条件，削弱门控效果。SWE-bench Verified 的 issue 质量较好，真实世界可能更差。
- **共享模型盲区**：证据规格、缺口评估和引导均由驱动智能体的同一模型生成，模型的行动选择盲点可能同样影响证据充足性判断。论文虽用仓库结构进行了 grounding 以缓解，但仍未彻底解决。
- **保持预算导致的回归**：少量失败实例是因为智能体反复尝试承诺动作、三次保持预算耗尽后被回退放行，最终产生不正确补丁（例如随动回归 9–16 个实例）。
- **评估范围有限**：仅一个 benchmark（SWE-bench Verified）、两种模型、两种框架；未覆盖其他语言、特性开发任务，也未在更广泛的真实软件工程场景验证。
- **消融实验规模较小**：100 实例的子集可能不足以全面暴露不同组件的交互效应，且未报告该子集上的显著性检验。
- **缺乏与其他运行时约束系统的直接对比**：论文只对比了基线和 Self-Refine，未与 AgentSpec、Agent-C 等同类工作定量比较，难以直接判断相对优势。
