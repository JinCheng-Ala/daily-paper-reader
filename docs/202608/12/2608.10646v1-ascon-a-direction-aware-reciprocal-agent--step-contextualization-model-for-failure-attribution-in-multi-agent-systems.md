## 摘要
基于大语言模型的多智能体系统（MAS）中的失败归因旨在回答是谁导致了失败、失败何时发生以及为何发生，通过识别包括故障智能体、错误步骤和失败模式在内的责任目标。现有方法主要集中于为特定归因目标开发专用模型，而对它们之间证据依赖关系的关注有限。尽管这些归因目标各不相同，但它们依赖于来自MAS轨迹的常见诊断证据，包括任务约束、智能体角色、行为历史和智能体间交互。这种共性促使我们开发一个统一的表示模型，将轨迹证据聚合到单个智能体和步骤表示中，随后可适应不同的归因目标。据此，我们提出了ASCon，一种面向多个失败归因目标的方向感知的交互式智能体-步骤上下文化模型。ASCon引入方向感知图注意力来建模执行上下文，掩蔽的步骤到智能体注意力来构建行为感知的智能体表示，以及智能体条件下的步骤上下文化来将智能体上下文融合回步骤表示中。得到的上下文化表示通过轻量级目标特定头支持不同的归因目标。实验表明，ASCon在微观准确率上可将故障智能体检测提高5.83%以上，故障步骤检测提高10.63%以上，并在宏F1上可将失败模式检测提高14.73%以上。同时，在域外场景中，它还能大幅增强基于LLM的方法的归因能力。

## Abstract
Failure attribution in LLM-based multi-agent systems (MAS) aims to answer who caused failures, when they occurred, and why by identifying responsible targets including faulty agents, erroneous steps, and failure modes. Existing methods have primarily focused on developing dedicated models for specific attribution targets, with limited attention to the evidential dependencies among them. Despite these attribution targets are different, they rely on common diagnostic evidence from MAS trajectories, including task constraints, agent roles, behavioral histories and inter-agent interactions. This commonality motivates us to develop a unified representation model that aggregates the trajectory evidence into individual agent and step representations, which can subsequently be adapted to different attribution targets. Accordingly, we propose ASCon, a direction-aware reciprocal \textbf{A}gent--\textbf{S}tep \textbf{Con}textualization model for multiple failure attribution targets. ASCon introduces direction-aware graph attention to model execution context, masked step-to-agent attention to construct behavior-aware agent representations, and agent-conditioned step contextualization to incorporate agent context back into step representations. The resulting contextualized representations enable different attribution targets through lightweight target-specific heads. Experiments show that ASCon can improve faulty-agent detection by 5.83\%+ in micro-accuracy, faulty-step detection by 10.63\%+ in micro-accuracy, and failure-mode detection by 14.73\%+ in Macro-F1. Meanwhile, it can also substantially enhance the LLM-based methods' attribution capabilities in out-of-domain scenarios.

## 1. 论文的核心问题与整体含义（研究动机和背景）

- 随着基于大语言模型（LLM）的多智能体系统（MAS）在软件开发、信息检索、科学分析等复杂任务中的广泛应用，系统调试和错误修复变得越来越困难。MAS 的失败往往由多种因素引发，如智能体间目标不一致、协作矛盾、行为偏离角色等，开发者需要从冗长的执行轨迹中手动定位故障，耗时巨大。
- 论文将 MAS 失败归因定义为回答三个问题：
  - **who**：哪个智能体导致了失败；
  - **when**：失败发生在哪一步；
  - **why**：对应的失败模式（failure mode）是什么。
- 现有研究通常针对单一归因目标分别开发专用模型（如步骤级、智能体级、失败模式级），但忽略了这些目标之间的证据依赖关系。实际上，不同归因目标都依赖相同的轨迹诊断证据：**任务约束、智能体角色、行为历史、智能体间交互**。
- 核心动机：既然不同归因目标共享相同的底层证据，是否可以构建一个**统一的表示模型**，将轨迹证据聚合为智能体和步骤的表示，再通过轻量头适配不同归因任务？据此提出 **ASCon**（Direction-Aware Reciprocal Agent–Step Contextualization Model）。

## 2. 论文提出的方法论

### 核心思想
ASCon 通过**交互式（reciprocal）的步骤-智能体上下文化**，实现轨迹证据在步骤和智能体表示之间的双向流动，从而支持故障智能体、故障步骤、失败模式三种归因目标。整体框架包括三大部分：

### (1) 方向感知图注意力（Direction-Aware Graph Attention, DGAT）
- 将轨迹建模为**有向步骤图**和**有向智能体图**：
  - 步骤图：用户查询作为额外初始节点 s₀，相邻步骤按执行顺序构成有向边，编码任务约束与动作依赖。
  - 智能体图：引入“用户”节点 a₀，相邻步骤所属的智能体之间按执行顺序连接有向边，建模智能体交互与协作关系。
- DGAT 分别处理每个节点的**入邻域、出邻域和自信息**，因为失败根因与其后续影响在方向上是有区别的：
  - 入邻域提供“该节点是否异常”的上下文；
  - 出邻域反映该节点行为的下游影响。
- 计算过程：
  - 对入边和出边分别计算 LeakyReLU 注意力分数；
  - 分别在两个方向归一化，得到方向特定的消息聚合；
  - 节点更新为自变换 + 入消息 + 出消息，再经 ELU 激活。

### (2) 行为感知智能体表示（Behavior-aware Agent Representation）
- 通过**掩码步骤到智能体注意力（Masked Step-to-Agent Attention）**将步骤证据聚合到智能体：
  - 定义智能体-步骤分配矩阵 M，M_kt=1 表示步骤 t 由智能体 k 执行；
  - 先计算每个智能体自身步骤的局部平均摘要，与角色嵌入拼接生成查询向量；
  - 步骤表示作为键值，使用缩放点积注意力计算相关性，并应用掩码强制每个智能体只关注自己的步骤；
  - 得到的智能体表示兼具角色信息、行为历史和任务约束。
- 融合全局轨迹上下文（所有步骤表示的平均池化），经 MLP + LayerNorm 得到初始智能体表示。
- 在**智能体交互图**上再应用 La 层 DGAT，得到最终上下文化的智能体表示 H(a)。

### (3) 智能体条件下的步骤表示（Agent-Conditioned Step Representation）
- 将智能体表示投影到步骤表示空间，然后对每个步骤的上下文向量与投影后的智能体向量做**逐元素乘法**，再经 MLP + LayerNorm 融合，得到 agent-conditioned 的步骤表示。
- 这样，每个步骤不仅包含自身内容与相邻步骤的上下文，还携带执行该步骤的智能体的行为与角色信息，有助于细粒度故障定位。

### 目标特定的归因头
- **根因归因（Root-fault attribution）**：对智能体和步骤分别使用二元分类头，训练目标为 BCELoss；推断时选择概率最高的智能体和步骤作为根因结果。
- **失败模式归因（Failure-mode attribution）**：将智能体表示与其对应步骤的池化表示拼接，预测故障智能体概率和失败模式分布，损失为智能体二分类 BCE + 故障类型交叉熵 CE。
- 轻量头设计使同一套上下文表示可以适配不同标注和监督方案。

## 3. 实验设计

### 数据集与评测基准
- **TracerTraj（扩展版）**：用于根因归因任务，包含 6 个 MAS 生成的轨迹，覆盖 coding、mathematical reasoning、agentic tasks 三类任务；3,208 条训练轨迹，790 条测试轨迹（127 code + 63 math + 600 agentic）。
- **Aegis-Bench**：用于失败模式归因任务，包含超过 9K 条轨迹、6 个 MAS、14 种失败模式，每条轨迹可能包含多个故障智能体和多个失败模式；默认设置下用 600 条测试，其余按 8:2 划分训练/验证。
- **Who&When benchmark**：用于**域外泛化**评估，不进行任何训练直接测试；失败模式归因部分采用扩展的失败类型标注版本。

### 对比方法
- **根因归因**：
  - Prompt-based：All-at-Once、Step-by-Step、Binary Search、SDBL(EASD)（均用 GPT-4o-mini 实例化），以及 DeepSeek-V4-Pro 和 Gemini-3.1-Flash 基于 All-at-Once prompt。
  - Learning-based：StepFinder、AgentTracer、Qwen-SFT（从 Qwen2.5-14B 微调而来）。
- **失败模式归因**：
  - 商业 LLM：DeepSeek-V4-Pro、Gemini-3.1-Flash、GPT-4o-mini、Qwen3.5-Flash（使用 Aegis prompt）。
  - Learning-based：Aegis-SFT（LoRA 微调）。

### 评估指标
- 根因归因：agent-level 和 step-level 的 micro-accuracy 与 macro-accuracy，判断预测的最高概率项是否与 ground-truth 匹配。
- 失败模式归因：Micro-F1（μF1）和 Macro-F1（MF1），以及三个层级：Agent（只判故障智能体）、Error（只判失败模式）、Pair（同时判智能体-失败模式关联）。

### 关键实验结果（摘要）
- 根因归因：ASCon 在 agent 级 micro-accuracy 上提升 5.83%+，step 级 micro-accuracy 提升 10.63%+。
- 失败模式归因：Error 级 Macro-F1 提升 14.73%+。
- 域外场景：将 ASCon 预测注入 LLM 方法后，agent 级 micro-accuracy 提升 8.69%+，step 级 micro-accuracy 提升 12.50%+，failure-mode 级 Macro-F1 提升 3.15%+。

### 5.1 消融实验（Ablation Study）

论文对 ASCon 的关键组件进行了消融分析，以验证各模块的必要性。消融变体包括：

- **w/o Direction-aware**：将 DGAT 替换为普通图注意力（无方向区分），用于验证方向感知的有效性；
- **w/o Agent graph**：移除智能体图，仅保留步骤图；
- **w/o Behavior-aware agent**：去除行为感知聚合模块，智能体表示仅由角色嵌入和简单平均池化得到；

- 智能体条件下的步骤表示对步骤级细粒度定位有重要影响；

### 5.3 潜在失效情况与限制分析

论文在讨论部分（或案例分析中）指出 ASCon 仍有若干局限：

- **依赖轨迹质量**：如果执行轨迹缺乏足够的语义信息（如纯二进制日志），表示学习的有效性会减退；
- **多故障并发**：在 Aegis-Bench 中一条轨迹可包含多个故障智能体/失败模式，ASCon 通过叠加分类头处理，但对同时发生且相互交织的故障仍可能定位不准；
- **域偏移**：尽管域外实验表现良好，但在与训练数据分布差异极大的新智能体架构上，性能仍可能下降；
- **未利用外部知识**：模型完全依赖轨迹内证据，缺乏对智能体设计规范、代码库等外部知识的引用能力，因此在理解深层意图方面不如 LLM 方法。

## 6. 论文的贡献点总结

1. **提出首个统一框架** ASCon，将智能体级、步骤级和失败模式三类归因目标统一到一个上下文化表示学习框架中，利用不同归因目标共享的证据依赖关系，避免为每个目标单独训练模型。
2. **设计方向感知图注意力（DGAT）**，显式建模步骤间和智能体间的有向信息流，利用“入边-出边”区分来刻画故障的成因与影响。
3. **提出行为感知的智能体表示与智能体条件下的步骤表示**，实现双向、交互式的证据流动，兼顾粗粒度智能体定位与细粒度步骤定位。
4. **在多个基准和多种设置下取得显著性能提升**，包括根因归因、失败模式归因和域外泛化，并展示了与 LLM 方法的互补性。
