## 摘要
AI代理越来越擅长处理复杂、长时间运行的任务。随着自主能力的迅速增长，由于缺乏以人为中心的接口，人类监督系统性地滞后。为了解决这一问题，我们引入了AgentGUI，一个用户友好的本地托管GUI，用于在多个并发、长时间运行的会话中无缝观察和引导AI代理。AgentGUI具有以下特点：1）丰富的代理轨迹可视化；2）有效的手动和自动引导；3）与开源和前沿代理框架的集成与协调。一项受控的用户研究表明，从代理轨迹中识别关键元素所需的时间显著减少（速度提高38%，p=0.023）。在一项初步实验中，AgentGUI的自动漂移预防功能将小型本地代理的任务完成率提高了高达34个百分点，跨越0.8B至9B模型阶梯（每个模型运行50次）。AgentGUI可通过其项目网站（https://agent-gui-project.github.io）和开源仓库（https://github.com/eth-medical-ai-lab/agent-gui）公开获取，同时提供一个演示视频（https://youtube.com/watch?v=GSDyxN1gTF0）。

## Abstract
AI agents are increasingly adept at tackling complex, long-running tasks. With the rapid surge of autonomous capabilities, human oversight is systematically lagging behind due to limited human-centered interfacing. Aiming to address this, we introduce AgentGUI, a user-friendly, locally hosted GUI for seamlessly observing and steering AI agents amid multiple concurrent, long-running sessions. AgentGUI features 1) rich agent trajectory visualizations, 2) effective manual and automated steering, and 3) integration with and coordination between open-source and frontier agent frameworks. A controlled user study demonstrates statistically significant reduction in the time it takes to identify key elements from agent traces (38% faster, p = 0.023). In a preliminary experiment, AgentGUI's automated drift prevention feature raises the task completion rate of small local agents by as high as 34pp across a 0.8B--9B model ladder (N=50 runs per model). AgentGUI is publicly available through its project website (https://agent-gui-project.github.io) and open-source repository (https://github.com/eth-medical-ai-lab/agent-gui), along with a demo video (https://youtube.com/watch?v=GSDyxN1gTF0).

- **问题**：工具型 LLM 代理在执行复杂、长期任务（如软件工程、科学实验、计算机使用）时，其自主能力迅速增强，但人类监督因缺乏以人为中心的接口而严重滞后。代理留下的轨迹（推理、工具调用、文件访问交错）难以理解，导致人类无法有效验证和干预，反而可能抵消代理带来的时间节省。
- **整体含义**：提出 **AgentGUI**——一个开源、本地托管的图形界面，旨在无缝地观察和引导多个并发、长期运行的 AI 代理，将不透明的轨迹转化为人类可验证、可纠正的结果，提升人机协作监督效率。

## 2. 方法论：核心思想、关键技术细节
- **核心思想**：通过统一的 GUI 集成代理轨迹可视化、手动/自动引导以及多代理协调，降低人类理解代理行为的心智负担，并允许即时干预。
- **关键技术细节**：
  - **观察模块**：
    - **活动流**：将代理轨迹分解为推理/生成内容、工具请求/响应，并用不同视觉线索辅助略读。
    - **概览**：按墙上时钟时间展示代理在各任务上的耗时。
    - **调试终端**：显示逐轮 API 调用和 token 遥测。
    - **代理控制台**：轻量级代码执行终端，突出代理的代码执行动作。
    - **文件标签页**：一键预览代理工作目录和制品。
    - 子代理（如 Hermes 的 delegate 工具生成）以可展开的迷你头像显示。
  - **引导模块**：
    - **手动引导**：用户可通过直接输入中断并重定向当前轮次；修改任务定义（代理会在当前轮完成后审查）；切换代理模型（如用更强模型接管卡住的任务）。
    - **自动引导（LLM 驱动的管理器审计）**：管理器将任务分解为可验证标准，收集证据，判断每项标准并生成审计报告。若未标记为已完成，则自动恢复代理并输入纠正性反馈。
  - **工程亮点**：
    - 每个代理工作台拥有独立的 Docker 沙箱，实现隔离。
    - 后端 FastAPI 服务器通过 WebSocket 流式传输事件到 React 前端。
    - 支持本地推理（Ollama）和远程 GPU 服务器/托管 API。
    - 桌面可保存/恢复完整轨迹和工作区快照。

## 6. 主要结论与发现
- **用户研究**：
  - AgentGUI 使用户识别关键元素的速度提高 **38%**（平均每问题 90s → 145s，p=0.023）。
  - 准确率从 80% 提升至 **93%**（p=0.031）。
  - 所有五种问题类型均观察到了时间减少，其中“时间分解”和“输出制品”类问题显著。
  - 用户自我报告的心理需求、挫折感、努力程度均显著低于基线。
- **自动引导实验**：
  - 单次管理器审计后，任务完成率提升幅度从 10 个百分点（0.8B: 10%→26%）到 34 个百分点（4B: 44%→78%），较大模型（9B: 92%→98%）也有提升。
  - 管理器 token 开销极小（不到总 token 的 1%）。
  - 代理 token 消耗随模型能力增强而降低（小模型因纠正需要更多 token）。
