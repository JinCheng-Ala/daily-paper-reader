## 摘要
长期任务网络智能体常常在最终失败之前就偏离轨道：即使当前状态、复用的技能或计划假设不再支持用户指令，轨迹仍然可能在局部看似合理。现有智能体可以规划、反思或复用经验，但其计划很少指定在何种证据下当前步骤仍应被信任。我们提出FCPAgent，一种用于鲁棒长期任务网络智能体的可证伪承诺规划框架。FCPAgent将每个计划步骤表示为可证伪承诺单元（FCU）：一个基于可复用技能的子目标，以及确认性证据、证伪证据和置信度得分。执行被组织为计划-测试-修复循环。混合承诺测试模块在候选动作修改浏览器之前进行检查，并在执行后检查观察结果；为提高效率，它结合了轻量级证据匹配和基于LLM的诊断验证。当证据证伪一个承诺时，范围感知修复将矛盾定位到执行、技能或规划层面，并修正最小的适当部分。在WebArena上，FCPAgent相对于最强基线实现了平均成功率13.8%的相对提升，在长期任务上尤其显著。

## Abstract
Long-horizon web agents often go off track before final failure: a trajectory can remain locally plausible even after the current state, reused skill, or plan assumption no longer supports the user instruction. Existing agents can plan, reflect, or reuse experience, but their plans rarely specify the evidence under which an active step should still be trusted. We propose FCPAgent, a falsifiable commitment planning framework for robust long-horizon web agents. FCPAgent represents each plan step as a Falsifiable Commitment Unit (FCU): a subgoal grounded in a reusable skill, together with confirming evidence, falsifying evidence, and a confidence score. Execution is organized as a plan-test-repair loop. The hybrid commitment testing module checks candidate actions before they modify the browser and checks observations after execution; for efficiency, it combines lightweight evidence matching with LLM-based diagnostic verification. When evidence falsifies a commitment, scope-aware repair localizes the contradiction to the execution, skill, or planning level and revises the smallest adequate part. On WebArena, FCPAgent achieves a 13.8% relative improvement in average success over the strongest baseline, with especially large gains on long-horizon tasks.

## 1. 核心问题与整体含义（研究动机与背景）

- **核心问题**：长期任务（long-horizon）的网络智能体在最终失败前常偏离轨道（off-track execution）：即使当前状态、复用技能或计划假设已不再支持用户指令，智能体仍可能继续执行局部合理的动作，导致最终失败。
- **动机**：现有方法（如规划、反思、经验复用）的步骤通常是“无条件执行”的，缺乏运行时有效性判断接口，无法在偏离初期主动检测并修正。
- **整体含义**：需要将计划步骤设计为可测试的承诺（falsifiable commitment），附带显式确认与证伪证据，使得智能体能在线检测偏离并及时修复，从而提升长期任务的可靠性。

## 2. 方法论：核心思想、关键技术细节、公式或算法流程

- **核心思想**：将每个计划步骤表示为**可证伪承诺单元（Falsifiable Commitment Unit, FCU）**，定义证据接口，执行变为“计划-测试-修复”循环。
- **关键技术细节**：
  - **FCU四元组**：\( c_i = (g_i, s_i, E^+_i, E^-_i, \kappa_i) \)，其中 \( g_i \) 为子目标，\( s_i \) 为可选复用技能，\( E^+_i \) 为确认性证据（按阶段分前置、进展、完成），\( E^-_i \) 为证伪证据（分层：执行层、技能层、规划层），\( \kappa_i \) 为置信度。
  - **混合承诺测试**：
    - 轻量级测试：对动作前（action-level）和状态后（state-level）进行快速证据匹配，使用 NLI 与图像-文本匹配模型计算分数。
    - LLM 诊断验证：仅在轻量级测试触发“完成”、“风险”、“冲突”等路由时调用 LLM 进行深度分析，输出 continue / advance / repair 及诊断 \( u_t \)。
  - **范围感知修复**：根据诊断 \( u_t \) 确定违反范围（执行级、技能级、规划级），保留已完成前缀，仅修正最小必要部分（局部动作修正、技能切换、重规划剩余 FCU、或从安全状态重启）。修复时检索失败-修复经验库作为软指导。
  - **经验构建**：离线从成功轨迹提取技能库（\( \mathcal{S} \)），从失败/修复轨迹提取失败-修复库（\( \mathcal{F} \)），测试时固定不变。
- **算法流程**（Algorithm 1）：
  1. 检索相关技能与失败案例 → 生成 FCU 序列 \( C \)；
  2. 逐个执行 FCU，前一步执行前测试，后一步执行后测试；
  3. 若测试结果非 continue，调用慢验证器；若为 repair，调用修复模块更新 FCU 与后续部分；
  4. 若 advance，则完成当前 FCU 并推进到下一个；
  5. 循环直到所有 FCU 完成或达到步骤预算。

## 6. 主要结论与发现

- FCPAgent 在 WebArena 上平均成功率 65.3%，超过最强基线 ColorBrowserAgent（57.4%），相对提升 13.8%。
- 长周期任务（≥11步）提升最为显著（Shopping 领域提升 161%，GitLab 提升 87%）。
- 零样本迁移到 WebChoreArena 仍能取得 9.6% 相对提升，表明方法的泛化能力。
- 消融实验表明三个组件（可证伪计划、承诺测试、范围修复）均贡献显著，其中可证伪计划最为关键。
- 混合测试有效降低 LLM 调用时间约 19.5% 而不牺牲成功率。
- 经验积累（技能库+失败-修复库）可随训练数据增加带来稳定提升。

## 7. 优点

- **概念创新**：首次提出将计划步骤视为可证伪承诺，显式定义证据接口，为智能体提供运行时自我监督能力。
- **框架完整**：覆盖生成、测试、修复、经验构建全流程，具有实用价值。
- **效率优化**：混合测试设计精巧，轻量级过滤常规状态，LLM 仅用于关键或模糊情况，平衡成本与精度。
- **范围感知修复**：根据诊断层次选择最小修正，避免过度修改或无效重试，修复成功率高。
- **强实验结果**：在多个基准、多种任务、长周期场景下均取得一致提升，消融和运行时分析详实，验证了设计各部分的有效性。

## 8. 不足与局限

- **证据质量依赖**：生成证据的质量直接影响检测效果，过于宽泛的证伪证据可能引发不必要修复，过于狭窄则可能遗漏漂移。论文未探讨自动学习证据的方法。
